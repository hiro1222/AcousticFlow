## 実時間スレッドの規律

### 傾斜を掛けて片耳ずつ黙らせる

`Middleware/src/block_source.h` — `ClipSource::render`

```cpp
if (c < kMaxCh) {
    const float wantCh = (mute & (1u << c)) ? 0.0f : 1.0f;
    float&      cur    = muteGain_[c];
    if (cur < wantCh)      { cur += rampStep_; if (cur > wantCh) cur = wantCh; }
    else if (cur > wantCh) { cur -= rampStep_; if (cur < wantCh) cur = wantCh; }
    v *= cur;
}
```

**何をしているか** ── 目標値（0 か 1）へ向けて 1 サンプルずつ動かし、行き過ぎたら止める。
歩幅は下の「傾斜の速さは周波数から出す」で決まる 5ms 相当。

⚠ **素直に書くと壊れる所** ── こう書きたくなります。

```cpp
if (mute & (1u << c)) v = 0.0f;      // ← 波形の途中で 0 に落ちる＝プチッと鳴る
```

振幅 0.8 の所で突然 0 にすると、そこが**階段**になります。
この道具は聴き比べに使うので、切り替えるたびにクリックが乗ると
**比べたいものが聞こえません**。

**守り方** ── 検査「黙らせるとき一気に 0 にせず傾斜で落とす」
（切った直後の先頭 8 サンプルが 0 でないこと）。傾斜が消えたら落ちます。

### 「鳴らしたい状態」と「音が出ている」を分ける（停止・一時停止のフェード）

`Middleware/src/block_source.h` — `ClipSource::render`

```cpp
const bool want  = (st == State::Playing);
const bool alive = (want || envGain_ > 0.0f) && channels_ == channels && !clip_.empty();

if (want) { envGain_ += rampStep_; if (envGain_ > 1.0f) envGain_ = 1.0f; }
else      { envGain_ -= rampStep_; if (envGain_ < 0.0f) envGain_ = 0.0f; }
```

**何をしているか** ── 状態を 2 つに割っています。`want`＝鳴らしたいか、
`alive`＝いま音が出ているか。止めた直後は `want=false` でも
**傾斜が下り切るまで `alive` なので音は出続けます**。

⚠ **素直に書くと壊れる所** ── 状態だけで切ること。

```cpp
const bool run = (state == Playing) && ...;   // ← 止めた瞬間に 0。波形の途中で崖
```

振幅 0.5 の所で即 0 にすると階段になります。しかも `pause()` も同じ経路なので、
**一時停止でもクリックが出ていました**。

⚠ **罠 1** ── `stop()` で頭出しを先に戻すと、**鳴らしながら位置だけ頭へ飛びます**。
だから `stop()` は注文を置くだけにして、実時間スレッドが下ろし切ってから戻します。

```cpp
if (!want && envGain_ <= 0.0f && rewindReq_.exchange(false, ...)) {
    posF_ = 0.0;
    resetFilters();
}
```

⚠ **罠 2（危うく踏んだ）** ── **鳴り切ったときは戻してはいけません。**
自然終了でも戻すと `finished()` が false に化けて、
「鳴り切るまで回す」という呼び方が**永久に終わりません**（検査が固まります）。
だから `stop()` で押されたときだけ旗を立てます。

**守り方** ── 検査「止めるときは傾斜で落とす」
（一定値 0.5 の素材で、止めた次のブロックの頭が 0.4977 ／ 隣との最大差 0.00227）。

### 音量は 1 極で追いかける

`Middleware/src/block_source.h` — `ClipSource::render`

```cpp
gainCur_ += (gTarget - gainCur_) * gainCoef_;
```

**何をしているか** ── 目標との**差に比例して**動く。遠いほど速く、近づくほど遅い。

**なぜ 1 極か（一定歩幅を退けた理由）** ── ミュートと同じ一定歩幅にすると、
`-60dB` への移動（振幅 1.0 → 0.001）と `-3dB`（1.0 → 0.7）で
**掛かる時間が 300 倍違います**。1 極ならどちらもほぼ同じ時間で収まる。
しかも乗加算 1 回で済みます。

**なぜ dB でなく振幅で傾斜させるのか** ── dB で傾斜させると 1 サンプルごとに
`pow()` が要ります。つまみを動かす程度の変化量なら差は聞こえません。

⚠ **弱点** ── 目標に**厳密には届きません**。時定数 5ms なので 20ms 後に -100dB 以下、
実用上は無視できますが、**聞かれたら答えられるようにしておくこと**。

⚠ **素直に書くと壊れる所** ── ブロックの頭で 1 回読んで掛けること。
10ms 刻みの階段になり、つまみを動かすと **100Hz のジッパーノイズ**が乗ります。

**守り方** ── 検査「音量は傾斜で変わる（階段にならない）」
（-40dB へ落としたブロックの頭が 0.4978 ／ 隣との最大差 0.00223）。

### 傾斜の速さは周波数から出す

```cpp
static constexpr float kRampSeconds = 0.005f;   // 5ms
rampStep_ = 1.0f / (sr * kRampSeconds);
```

⚠ 固定の歩幅（`1/220`）だと **44.1k で 5ms、48k で 4.6ms** になり、
「5ms のはず」が説明できなくなります。ミュートの傾斜も同じ値に寄せたので、
**5ms が 1 箇所で決まります**（決めごと #1）。

**なぜ 5ms か** ── これより短いと可聴の不連続が残り、長いと「切った」感じが遅れます。
奪取時のフェードとして一般に使われるのも 5〜20ms の範囲です。

### 双 2 次フィルタ ── 端では素通りさせる

`Middleware/src/block_source.h` — `ClipSource::design`

```cpp
// 端＝素通り。低い方を通す側は上端、高い方を通す側は下端。
if (( lowPass && hz >= kLpOff) || (!lowPass && hz <= kHpOff)) { f->on = false; return; }

const float w0 = 6.2831853f * hz / (nyq * 2.0f);
const float cw = std::cos(w0);
const float sw = std::sin(w0);
const float q  = 0.70710678f;            // バターワース（山を作らない）
const float al = sw / (2.0f * q);
```

**何をしているか** ── RBJ の双 2 次係数。`w0` は正規化角周波数、`al` は帯域幅を決める値。

**なぜ Q = 0.707 か** ── `1/√2`。**バターワース**＝通過帯域が最も平坦になる値で、
これより大きいと切り位置の手前に**山（レゾナンス）**が立ちます。
遮蔽や素材の調整に使うフィルタで山が立つと、「こもらせた」つもりが
**特定の帯域だけ持ち上がる**ので、狙いと逆の結果になります。

⚠ **素直に書くと壊れる所** ── 端でも係数を作って掛け続けること。
20000 Hz の低域通過は**振幅はほぼ素通りでも、位相は回ります**。
「切っているつもり」で位相だけ変わるので、**切り忘れに気づけません**。
だから端では `on = false` にして**掛けない**。画面も名前の隣に「（切）」と出します。

**守り方** ── 検査「つまみを端に置くとフィルタは素通りする」
（端では実効値の差が 0.000000）。

⚠ **もう 1 つ** ── 係数を替えたら `clear()` で内部状態を捨てること。
前の係数で積んだ値を新しい係数で回すと**弾けます**。頭出しで飛んだときも同じ。

### 実時間スレッドの負荷は「1 回に渡される数」で割る

`Middleware/src/audio_device.*`

**⚠ ここは一度間違えました。**負荷率が **2.2 倍甘く**出ていました
（0.159 % と表示 → 正しくは 0.350 %）。

デバイスが確保している輪は **970 サンプル**ですが、WASAPI 共有モードは
**デバイス周期ごとに起こしてくる**ので、**1 回に渡されるのは 441**（＝10.00 ms）。
持ち時間は後者で決まります。輪で割ると、実際より余裕があるように見えます。

**どう気づいたか** ── 波形の周期が計算と合わなかった（4.4 周期のはずが 9.7 周期）。
**数字だけ見ていたら気づけませんでした。**

### 画面が触る 1 本を、null を返さない形で渡す

`Middleware/src/app_main.cpp`

```cpp
auto cur = [&]() -> af::ClipSource& {
    af::ClipSource* c = bus.find(selected);
    return c ? *c : bus.idle();

```

**なぜこの形か** ── 本が複数になったとき、画面の 40 箇所が触る先を
**1 つの入口**にまとめる必要がありました。

⚠ **素直に書くと壊れる所** ── `ClipSource*` を返して呼ぶ側に null を確かめさせること。
**40 箇所のうち 1 箇所忘れただけで落ちます。**空の本を返せば、
