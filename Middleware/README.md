# Middleware — AcousticFlow の開発環境

**いまの状態: システムを載せていない。** 音響エンジンにリンクしていないし、include もしていない。

このプロジェクトにとってエンジンは **依存先ではなく、実行時に読み込む対象**です。
だからエンジンが壊れていても、まだ存在しなくても、このホストは立ち上がります。

---

## ひとつだけ守る線

> **`Middleware/` は `AcousticEngine` にリンクしない。**

`target_link_libraries(AfHost PRIVATE AcousticEngine)` を書きたくなったら、その前に
「エンジンが無いとビルドできない道具になっていないか」を確かめてください。
リンクした瞬間、これはミドルウェアではなくテストハーネスになります
（`AcousticEngineTest/` の 5 本は全部リンクしていて、**あちらはそれで正しい**）。

トップの `CMakeLists.txt` からも呼ばれません。独立して構成・ビルドします。

```
cmake -S Middleware -B Middleware/build -A x64
cmake --build Middleware/build --config Release
```

---

実行ファイルは `Middleware/build/bin/Release/` に 2 つ出ます。

| | 種別 | 大きさ | 用途 |
|---|---|---|---|
| `AfHost.exe` | **Windows アプリケーション** | 1,057 KB | 本体。窓・監視パネル・音データ |
| `AfHostCheck.exe` | コンソール | 296 KB | 検査用。**キーボードも画面も無い所で回せる** |

### 配れるか（実測 2026-08-30）

**exe を 1 つ渡せば動きます。**依存しているのは OS の DLL だけです:

```
COMDLG32 / ole32 / AVRT / d3d11 / D3DCOMPILER_47 / KERNEL32 / USER32 / GDI32 / SHELL32 / IMM32
```

⚠ 最初は `MSVCP140.dll` `VCRUNTIME140.dll` にも依存していました。開発機には Visual Studio が
入っているので気づけませんが、**入っていない機械では起動しません**。
CMake で `/MT`（ランタイムを実行ファイルへ）にして消しました。646KB → 890KB。

| 確かめたこと | 結果 |
|---|---|
| 起動する | `Responding=True` / 題名 `名称未設定 — AfHost` |
| 閉じる | 終了コード **0**。掴んだまま残らない |
| 配置を覚える | `AfHost.ini` が出来る |

### アイコン

`assets/icon.ico` を `src/app.rc` 経由で実行ファイルに焼き込んでいます。
**6 寸法**（256 / 128 / 64 / 48 / 32 / 16）。元絵は `assets/icon_src.png`。

```
powershell -ExecutionPolicy Bypass -File Middleware/assets/make_icon.ps1 -Source Middleware/assets/icon_src.png
```

絵を差し替えたいときはこれを回すだけです（`-Source` を省くと `assets/icon.svg` から焼きます）。

★ .NET には複数寸法の `.ico` を書く口が無く、ImageMagick も入っていないので、
**ICO の容器を直に組み立てています**。256/128 は PNG 圧縮、64 以下は 32bit の DIB
（PNG 入りは古い経路で小さい寸法が出ないことがあるため）。

⚠ **`System.Drawing` で確認してはいけません。**PNG 入りの項を読めず、
「NG 256 → 128」のように**ファイルは正しいのに見張りが嘘をつきます**。
Windows が実際に使う経路（`PrivateExtractIcons`）で 6 寸法とも確認済みです。

⚠ 元絵は 804×800 の風景画で、**アイコンとして描かれたものではありません**。
16px では月の白い点しか残りません。ここを詰めるなら、小さい寸法用に
月と稜線だけの簡略版を別に描くことになります（`assets/icon.svg` はその下敷き）。

### SoundLibrary ── 音の在り処の台帳

> 2026-09-01 に **AudioBank から SoundLibrary へ改名**しました。
> **中のクラス名が最初から `SoundLibrary`** で、画面だけ別の名前を出していたためです。
> バンクという器は 2026-08-30 に廃してあり（フォルダと働きが重複していた）、
> 名前だけが残っていました。⚠ **画面の名前と中の名前は揃えること** ──
> 揃っていないと、話すときと書くときで語彙が変わります。

**保存するだけ**です。Wwise と違い、ここは音を細かく操作する場所ではありません。

**持たないもの**（決定済み・蒸し返さない）:
音量・ピッチ・フィルタ・ランダム化・切り替え・バス・RTPC。

#### ★ 2026-08-30、バンクという器を廃しました

以前は `.afbank` という別ファイルにしていましたが、**容れ物としての働きが
フォルダと完全に重複**していました。バンクが余分に持っていたのは
「別ファイルであること」だけで、**それを何にも使っていませんでした**。

| | バンク | フォルダ |
|---|---|---|
| 中に音源を入れる／名前を変える／掴んで運ぶ | ○ | ○ |
| 入れ子にする | ×（1 階層のみ） | ○ |
| 保存 / 別名で保存 / エクスプローラで表示 | ○ | ── |

実際のミドルウェアでバンクが独立しているのは**焼いて配る単位だから**です。
焼く道具がまだ無い以上、名前だけ借りた空の器になります
（「中身の空いた機能を並べない」に反する）。**焼く段になったら、
そのとき本当に要る単位を改めて決めます。**

畳んだことで、こうなりました:

- **ファイルは `.afproj` 1 つだけ。**保存も 1 回
- 相対パスの基準も 1 つ（プロジェクトのフォルダ）。**別バンクへ運ぶときの
  付け替え**という、いちばん壊れやすかった処理が丸ごと不要になった
- 「バンクを保存し忘れる」という心配ごとが、心配ごとごと消えた

⚠ 引き換えに、**素材のまとまりを単体で持ち出せなくなりました**。
他へ渡すときはプロジェクトごとです（いま誰も使っていない機能でした）。

#### 触り方は既存のオーサリングツールに合わせてある

Wwise / FMOD と同じで、**ツリー ＋ 右クリック**が基本です。
ボタンの列だけだと、項目が増えたときに置き場所が無くなります。

| | |
|---|---|
| **ツリー** | **フォルダ → 音源**。名前だけ（素性は Audio タブ） |
| **右クリック（フォルダ）** | フォルダを作る（この中に）/ WAV を取り込む… / 名前の変更 / **削除（中身はひとつ上へ）** |
| **右クリック（音源）** | 試聴 / 名前の変更 / **フォルダへ移動** / エクスプローラで表示 / 引き直す / 台帳から外す |
| **右クリック（空白）** | WAV を取り込む… / フォルダを作る。**操作の入口はここ**（上のボタンは廃止） |
| **F2** | その場で名前を変える（フォルダ・音源）。Esc で取り消し |
| **Del** | 選んでいる音源を台帳から外す |
| **掴んで運ぶ** | 音源もフォルダも。**表の外へ落とすと一番上へ**戻せる |
| **Ctrl+Z / Ctrl+Y** | 元に戻す／やり直す。**編集メニューに何を戻すかが出ます** |
| **スペース** | **再生／一時停止**（DAW・Wwise と同じ）。⚠ 止める（頭へ戻す）のは ■。文字を打っている間・つまみを掴んでいる間は効かない |
| **二度押し** | その音を試聴 |
| **放り込み** | **エクスプローラから WAV を窓へ落とすと取り込みます**（選んでいるフォルダへ入る） |

#### フォルダ ── 性質で分けるための仕切り

**音には何も影響しません。**並べ方だけです。`足音/石` のように入れ子にできます。

★ **空のフォルダも作れます。**「項目が指しているから在る」だけにすると、
先に仕切りを作ってから素材を入れる、ができません。だから明示的に持っています。

★ **フォルダを消しても中身は消えません。ひとつ上へ移ります。**
仕切りでしかないものを消して素材まで消えるのは筋が違うからです。

★ **名前を変えると入れ子ごと付いてきます。**`足音` を直すと `足音/石` も一緒に動きます
（ここを名前の一致だけで見ると、子が親を失って迷子になります）。

移動は**掴んで運ぶ**か、右クリックの「フォルダへ移動」から。

#### 掴んで運ぶ

| 運べるもの | 落とせる先 |
|---|---|
| 音源 | フォルダ／表の外（＝一番上へ戻す） |
| フォルダ | 別のフォルダ／表の外。**中身ごと動きます** |

★ **表の外にも落とし先を置いています。**無いと、いったんフォルダへ入れた音源を
一番上へ戻す手が右クリックしか無くなります。

★ **荷札は 1 種類にまとめています。**音源とフォルダで別の荷札にすると、落とす側が
両方に対応することになって条件が二重になります。

★ **フォルダの移動は「親を差し替えた改名」で済ませています。**`renameFolder` が
入れ子ごと連れて行くので、専用の移動処理は書いていません（同じことを 2 通り書かない）。

⚠ 自分自身や自分の子の中へは落とせません（入れ子が自分を含んでしまうため）。

★ **操作の入口は右クリックだけ**です。上に並べていたボタン（WAV を取り込む／
フォルダを作る）は廃しました。ボタンの列だと、項目が増えたときに置き場所が無くなります。

⚠ **表に `ScrollY` を付けてはいけません。**付けると表が**別の窓**になり、
その中で右クリックしても親の窓のメニューが出ません
（＝「空き場所の右クリック」が届かなくなる）。SoundLibrary の窓ごと縦に流します。

⚠ **窓の空白は埋めないこと。**`Dummy` などで場所を取ると、それ自体が「項目」になり、
`NoOpenOverItems` に引っかかって**逆にメニューが出なくなります**。何も置かないままで
当たり判定になります。

★ **キーボードは文字を打っている最中は効かせません。**名前の変更中に `d` を打った
瞬間に消えたら困るので、`WantTextInput` を見て止めています。

⚠ **名前を変えている最中も、節点は必ず作ること。**見出しを空にして横に入力欄を出します。
最初は「変更中は節点を作らない」としたうえで `TreePop()` だけ呼んでいて、ImGui に
`Missing TreePop()` / `PopID() too many times` と怒られました。しかも子を描く条件まで
外れていたので、**音源の名前を変えようとすると行ごと消えて編集欄に辿り着けません**でした。
節点の作りと押し戻しは 1 対 1 に保つこと。

#### 元に戻す（Undo）

★ **台帳とイベントをまとめた「写し」を積む形**にしています（操作の逆再生ではなく）。

逆再生（コマンド方式）は操作ごとに「戻し方」を書く必要があり、
**1 つ書き忘れると、そこだけ静かに戻らない**道具になります。台帳は数百項目の見込みなので、
まるごと写しても安く済みます（64 段で数 MB）。安さと引き換えに、取りこぼしが起きません。

★★ **台帳とイベントは同じ 1 段に入れます。**分けてはいけません ──
イベントは音源を**番号**で指しているので、**台帳だけ戻すと、戻した先に居ない音源を
指した状態になり「見つかりません」が勝手に生えます**。逆にイベントだけ戻すと、
消したはずの動作が復活します。だから必ず一緒に動かします。

> 2026-09-01 以前はイベントが対象外でした。**半端に片方だけ戻すくらいなら
> 戻さないほうがまし**という理由で分けてあったものを、1 つの写しにまとめて畳みました。
> 結果として `editEvents()` という関数が**消えました**（`edit()` と同じものになったため）。

★ **触る所は `edit()` という入口を必ず通ります。**
そこで「写しを積む」と「未保存の印を立てる」の 2 つをやるので、
新しい操作を足しても書き忘れようがありません。

★ **つまみは掴んだ瞬間に 1 段だけ**積みます。動かすたびに積むと、少し動かしただけで
戻す先が何十段も埋まり、元の姿まで戻れなくなります。

★ **戻したあとに別の操作をすると、やり直しの先は捨てます。**
残すと「戻して・別のことをして・やり直す」で辻褄が合わなくなります。

★ **戻したあとは選択も詰めます。**選んでいたイベントが消えていることがあるので、
放っておくと、無い行を指したままプロパティが開き、そこで打った文字が別の行に入ります。

⚠ 元に戻せるのは**台帳とイベントへの操作だけ**です。プロジェクトの名前や試験信号の設定は
対象外にしています（打ち直せば済むため）。

⚠ **まだ無いもの**（既存ツールにはあります）: 複数選択。

#### 取り込みと素材

| | |
|---|---|
| 取り込む | WAV を複数まとめて。**読めないものは足しません**（理由をログへ） |
| 外す | 台帳から外すだけ。**ファイルは消しません** |
| 引き直す | ファイルから素性を読み直す |

対応する形式は **PCM 8/16/24/32bit と 32bit float**、1〜8ch、4k〜384kHz。
圧縮された WAV は取り込みません（黙って鳴らないより、断るほうを採る）。

★ **素性（周波数・チャンネル数・長さ）は保存していません。**ファイルを読めば
分かることを台帳にも持つと、素材を差し替えたときに片方が古くなります（決めごと #1）。
毎回ファイルから引くので、**素材が消えたらその場で「× 不明」と出ます**。

★ 素材の在り処は**プロジェクトからの相対**です（外にあるものは絶対）。
絶対だけで持つと、プロジェクトごと別の機械へ渡した先で全部見つからなくなります。

⚠ **別のフォルダへ保存したら、メモリ側の相対パスも付け替えること。**
基準だけ新しくしてパスを古いままにすると、その場では正しく見えるのに実体を見失います。
**これは検査が捕まえました**（`rebase`）。

### イベント ── ゲーム側からの発火点

**ゲーム側は `足音_石` のような名前だけを知っています。**どの音源が鳴るか・音量が
いくつかは知りません。差し替えても**ゲーム側のコードは 1 行も変わらない** ──
これが Wwise のイベントと同じ狙いで、**音の作り手と実装者を切り離す**ところです。

```
足音_石（1）
  └ 再生 → 足音
扉を開ける（2）
  ├ 再生 → 扉のきしみ
  └ 停止 → × 見つかりません
```

| | |
|---|---|
| **右クリック（イベント）** | 発火 / 名前の変更 / 動作を足す（再生・停止 → 音源）/ イベントを消す |
| **右クリック（動作）** | 種類 / 対象 / 動作を外す |
| **右クリック（空白）** | イベントを作る |
| **二度押し** | そのイベントを**発火**（＝実際に鳴る） |
| **掴んで落とす** | SoundLibrary から音源を落とすと「再生」の動作が付きます |

★ **道具から発火できることが、イベントが機能である条件です。**鳴らして確かめられないと、
イベントは「名前を書いただけの枠」になります。発火するとコントロールパネルの見出しが
**イベント名**に変わり、スケッチにあった枠がここで埋まりました。

★ **対象は音源の番号で指しています**（名前ではなく）。名前で指すと、改名した瞬間に
イベントが壊れます。Wwise が GUID でやっているのと同じ狙いです（検査あり）。

★ **同じ名前のイベントは作れません。**ゲーム側は名前で呼ぶので、重なると
「どちらが鳴るか分からない」という一番たちの悪い形になります。

★ **対象が消えたら「× 見つかりません」と赤で出ます。**黙って無音にしません。

⚠ **動作は「再生 / 停止」の 2 つだけ**です。遅延・フェード・確率・切り替えは
持ちません ── **まだ効かせる先が無いから**で、枠だけ作ると中身の空いた機能になります。

★★ **動作のぶんだけ同時に鳴ります**（2026-09-01 から。**8 本**まで）。

> ⚠ それまでは鳴らせるのが **1 本きり**で、動作を 2 つ持つイベントは
> **最後の 1 つしか鳴っていませんでした**。しかもログは「再生 2」と出していた ──
> **数えただけで鳴っていない**、いちばん質の悪い壊れ方です。
> 「A を鳴らして B も鳴らす」ができないなら、イベントは名前を付けただけの枠でした。
>
> 見つけ方は「次に何を作るか」を考えたときで、**検査も画面も嘘に気づいていません**。
> 対策として、出力パネルに**いま鳴っている本数**を出すようにしました
> （数えた数と鳴っている数を別々に出せば、食い違いがそこで見えます）。

★ **「停止」は、その動作が指している音だけ**を止めます。
⚠ 以前は鳴っているものを無差別に止めていて、**A を止めるつもりで B が黙りました**。

⚠ **これは「ボイス管理」ではありません。**優先度・スティール・上限の仕組みは持ちません
（**いまは**まだ持っていません）。**試聴に足りるだけの固定本数**で、埋まったら一番古いものを
使い回すだけです。ゲームの再生機構ではなく、道具の試聴機構です。

★ **足して溢れたら挟みます。**挟まないと重ねた瞬間に耳とスピーカーを痛めます。
歪んで聞こえるのは正しい ── 「重ね過ぎ」がそのまま分かります。

★ **イベントも元に戻す（Undo）の対象です。**台帳と**同じ 1 段**に入れて一緒に動かします。
片方だけ戻すと、イベントの指す先と食い違って余計に困るためです（[元に戻す](#元に戻すundo)）。

### コントロールパネル ── 触る場所

**SoundLibrary は見る場所、ここは触る場所**として分けています。既定では SoundLibrary の下。

上から:

1. **イベント名（発火したとき）または プロジェクト名 → 音源名**（音源名はここで変えられる）
2. **停止 ■ ／ 一時停止 ❚❚ ／ 再生 ▶**
3. **いまの位置 / 全体の長さ**と、**スペースで再生／一時停止（■ で頭へ戻す）**・**頭出しは音データを掴んで**の案内

**それだけです。**⚠ **頭出しの帯は 2026-09-01 に廃しました** ── プロパティの
**音データを直接掴む**形に移しています。素性はプロパティ、試験信号は試験信号タブ、
実費は 出力タブ。1 枚に詰め込むと、いま何を触っているのか分からなくなります。

★ **スペースは ▶ と同じ関数を呼びます**（`transportPlay`）。
ボタンとキーで別々に書くと、片方だけ直して食い違います（決めごと #1）。

★ **キーが割り当てられていることは、押してみないと分かりません。**
だから帯の下に一言出しています。⚠ **仕組みが動くことと、辿り着けることは別**で、
ここは過去 2 回落としています。

⚠ **スペースが効かない場面が 2 つあります。**どちらも意図してそうしています。
- **文字を打っている最中** ── 効かせると**名前に空白が入れられなくなります**
- **つまみや帯を掴んでいる最中** ── 動かしている途中で止まると、掴み直すことになります

★ **スペースは「再生／一時停止」です。**⚠ 止める（頭へ戻す）のではありません ──
聴きながら止めて、**同じ所から聴き直す**のが調整の手順なので、位置を捨てると使えません。
頭へ戻したいときは ■ を押します。

> 2026-09-01 に停止から一時停止へ直しました。最初は「止める」にしていて、
> **調整しながら聴き直せませんでした**。

⚠ **キー 1 つで回すのは 2 通りまで。**3 通り（再生・一時停止・停止）を回すと、
**押す前に何が起きるか分からなく**なります。停止は ■ に残しています。

### プロパティ ── 選んでいるものを見て直す場所

**真ん中**に置いています。**1 枚で全部を受け持ちます。**
選んだものに応じて中身が入れ替わります。

| 選んだもの | 出るもの |
|---|---|
| **音源** | ★**音データ**（L/R 別・掴んで頭出し・片側ミュート）／ その下で**「調整」と「情報」を切り替え** |
| **イベント** | 名前・**発火**・動作の表（種類と対象を選び直せる・外す・足す） |
| **フォルダ** | 直下の音源の数 |
| 何も選んでいない | 案内 |

★ **2026-09-01、「波形」パネルをここへ畳みました。**Wwise の Source Editor と同じで、
**選んだ音源の姿と、その設定は一緒に見たい**ものだからです。

★★ **中身も入れ替えました ── オシロ（出力の直近 1 ブロック）ではなく、
ファイルそのものの姿**を出します。作業中に見たいのは「いま 10 ms に何が出ているか」
ではなく「**この素材はどんな形か**」のほうでした。

⚠ **オシロは消していません。出力パネルへ寄せました。**
あれは**実時間スレッドが本当に回っている目に見える証拠**で、
上に並ぶ数字（1 回あたり・最悪・持ち時間の何 %）と対になっています。
消すと数字だけになり、確かめる手立てが減ります。

★ **チャンネルごとに 1 段ずつ**描きます（ステレオなら L と R の 2 段）。
左右を混ぜると、**片側だけ入っている素材が「両方に入っている」ように見えます**。
1ch の素材は「モノラル」の 1 段です。

★ **描くのは山と谷**（列ごとの最大と最小）で、平均ではありません。
足して平均すると、逆相のときに消えて、**鳴っているのに平らに見えます**。

★ **再生位置の線は、いま鳴っている音源のときだけ**出します。
別の行を選んで眺めている間に線が走ると、その音の位置だと勘違いします。

★ **頭出しはここを掴みます。**⚠ 掴んでいる間は鳴らしません ──
短い音を掴んだまま動かすと、その場所から鳴り続けて何を聴いているのか分からなくなります。
離したら、掴む前に鳴っていた場合だけ鳴らし直します。

> 2026-09-01 に**コントロールパネルの帯を廃しました**。
> 見ている場所と掴む場所が同じほうが、どこへ飛ぶか分かるためです。
> 両方に置くと同じ操作が 2 箇所になります（決めごと #1）。帯を描く関数も消しました
> ── 使わない関数を残すと「まだある機能」に見えます。

#### L / R を片方ずつ黙らせる

波形の下の **L ／ R ／ 両方鳴らす**で、片耳ずつ切れます。
**黙らせている段は暗く描く**ので、目と耳で同じことが起きているのが分かります。

★ **効くのは出口のチャンネル**です。モノラルの素材も左右へ複製して出しているので、
片方を切れば片鳴りになります（＝経路の確かめに使えます）。

⚠ **一気に 0 にせず、約 5ms の傾斜で落とします。**ここは聴き比べの道具なので、
切り替えるたびにプチッと鳴ると、**比べたいものが聞こえません**。

⚠ **プロジェクトには保存しません。**これは聴き比べの道具であって、音源の設定ではない
ためです。保存すると、片方を黙らせたまま閉じて、次に開いたとき
**原因の分からない片鳴り**になります。

⚠ **選ぶたびにファイルを読み直します。**試聴に足りるだけの短い音を前提にしているので
これで足りますが、長い素材を扱うようになったら**ここが引っかかります**
（そのときは焼いた素材の側に山谷を持たせるのが筋）。

★ **以前あった「Audio」タブもここへ畳みました。**種類ごとにパネルを作ると、
増えるたびにタブが増え、しかも同じ数字が 2 箇所に出ます（決めごと #1）。
★ **「いま何を選んでいるか」を 1 つだけ持ちます。**音源・フォルダ・イベント・動作は
同時に「選ばれている」状態になり得るので、**最後に押したものがどれか**を持たないと、
ここに何を出すかが決まりません。

★ **素性は台帳（SoundLibrary）には出しません。**同じ数字を 2 箇所に出すと、片方だけ
直して食い違います（決めごと #1）。台帳は名前だけ、数字はここ。

#### 波形の下は「調整」と「情報」の切り替え

★ **1 枚に両方並べると、どちらも幅が足りませんでした。**2 列に分けていた頃は
「16 bit PCM」が切れ、つまみも短いままでした。切り替えにして、**横幅を丸ごと片方に渡します**。

| | 出るもの |
|---|---|
| **調整** | 音量・ピッチ・低域通過・高域通過・ループ・既定に戻す・頭から試聴 |
| **情報** | 形式 / ch / 周波数 / 長さ / 大きさ / サンプル数 / 在り処 ／ エクスプローラで表示 |

⚠ **説明文を常駐させないこと。**「この値は保存されます」のような**1 度読めば済む文**を
出しっぱなしにしていたら、そのぶん縦を食って**下の「試聴」ボタンが見切れました**。
そういう説明はここ（README）に書きます。

#### 試聴の調整 ── 音量・ピッチ・低域通過・高域通過・ループ

⚠ **これは「台帳は保存するだけ」の線を越えています。**越えたのは発注者の指示によるものです。
**素材そのものは書き換えません**（鳴らし方だけ）。焼いた資産にこの値が乗るかどうかは、
**焼く道具を作る段の別の決めごと**です。

| つまみ | 範囲 | 中身 |
|---|---|---|
| **音量** | -60〜+12 dB | 掛けるだけ |
| **ピッチ** | ±24 半音 | **読む速さ**（2^(n/12)）を変える |
| **低域通過** | 20〜20000 Hz | 双 2 次（バターワース）。**上端＝切** |
| **高域通過** | 20〜20000 Hz | 同上。**下端＝切** |
| **ループ** | 入／切 | 端に来たら頭へ戻すだけ |

##### 数字を打つ／つまみで探る

★ **上に数字、下にスライダ**（既存のオーサリングツールと同じ形）。

**数字は打ち込めます。**つまみだけだと「-4.5 dB ちょうど」に合わせられず、
**狙った値を再現できません**。逆に数字だけだと、どのあたりが良いかを探れません。
両方要るので両方置いています。

⚠ **打ち込みは確定してから効かせます**（Enter か、欄から離れたとき）。
1 文字ごとに効かせると、「1200」と打つ途中の **「1」で耳を殴られます**。

⚠ **打ち込みは範囲の外も来ます。**挟んでから渡すこと。挟まないと、
20kHz を超える切り位置や半音 999 がそのまま実時間スレッドへ行きます。
検査で `999 → -24 半音 / 99999 → 20000 Hz / -5 → 20 Hz` を確かめています。

★ **数字とスライダの間だけ詰めています。**離れていると別々の項目に見えるためです。


⚠ **ピッチは時間も一緒に伸び縮みします。**読む速さを変えているだけなので、
1 オクターブ上げると長さは半分です。長さを保ったまま高さだけ変えるには位相ボコーダが
要りますが、試聴の道具には過剰で、しかも**素材の粗が隠れます**。
（検査で実測: ±0 で 25 ブロック → +12 半音で 13 ブロック）

★ **端に置いたら素通りさせています。**掛けっぱなしにすると、切っているつもりでも
位相だけ回り、**切り忘れに気づけません**。画面は名前の隣に「（切）」と出します。
検査で「端では 0.000000 の差」を確かめています。

★ **係数はブロックの頭で 1 回だけ**作り直します。三角関数を呼びますが、
**確保もロックもしない**ので実時間スレッドで構いません。値が変わった時だけ走ります。

★ **係数を替えたら中身を捨てます。**前の係数で積んだ値をそのまま使うと弾けます。
頭出しで飛んだときも同じ理由で捨てます。

⚠ **ピッチを上げると折り返し歪みが出ます**（線形補間で読んでいるだけ）。
試聴には十分ですが、焼く段で速さを変えるなら、そこはちゃんと帯域制限すること。

⚠ **持っていないもの**（既存ツールにはあります）: ランダム化（音量・ピッチのばらつき）、
イン点／アウト点、フェード。ランダム化は**ボイス管理とセット**なので、
「作らないもの」の側に当たります。

⚠ ループの継ぎ目を滑らかにする細工は**していません**。素材の頭と尻が揃っていないことが
そのまま聞こえるほうが、台帳としては正しいからです（道具が繕うと素材の粗が見えなくなる）。

★ **ボタンは字ではなく図形で描いています。**`■ ❚❚ ▶` は日本語フォントに無いことがあり、
豆腐になると「押せない」のか「字が無い」のか区別が付きません（`✔` で一度踏みました）。
自分で描けばフォントに依らず、押せる／押せないも色で出せます。

★ **頭出しは「注文」として渡します。**画面から再生位置を直に書くと、実時間スレッドが
進めている最中と衝突します。`seekTo` を 1 つ置いて、実時間スレッドがブロックの頭で
1 回だけ引き取る形にしてあります。

★ **帯を掴んでいる間は鳴りません。**頭出しのたびにその場所から鳴り続けると、
短い音では途切れない音になってしまい、何を聴いているのか分からなくなります。
掴んだら止め、離したら**掴む前に鳴っていた場合だけ**鳴らし直します。

★ **鳴り切っても試験信号へは戻しません。**戻すとデバイスを開け直すことになり、
帯と残り秒数が消えます。載せたままにしておけば、もう一度 ▶ で頭から鳴ります。
同じ音なら**載せ直さず続きから**鳴らすので、100ms の途切れも起きません。

★ **スケッチにあった「イベント名」の枠が埋まりました。**イベントから鳴らしたときは
その名前が青で出て、直接鳴らしたときはプロジェクト名に戻ります
（何で鳴っているかについて嘘をつかないため）。

★ **つまみはここにしか置きません。**同じ値を 2 箇所から動かせると、どちらが正か
分からなくなります（決めごと #1）。ツールバーは値を**読むだけ**です。

⚠ 試聴の周波数変換は**線形補間**です。試聴に足りる品質という位置づけで、
ここを良くするのは配管の仕事なので後回しにしています。

⚠ 試聴の音を差し替えるときは**デバイスを止めてから**入れ替えます。
実時間スレッドが読んでいる配列を差し替えないための割り切りで、100ms 前後止まります。

### プロジェクトに何を入れるか

★ **中身の空いた機能を並べない**、を守っています。いま `.afproj` が持つのは
**本当に効く設定だけ**（名前・試聴する信号の周波数・大きさ・開いたら鳴らすか）と、
**音源の台帳**（フォルダ・在り処・音量・ループ）です。

Wwise を写経して sound id / バス / RTPC の枠を先に作ると、**観測する対象そのものが
存在しない**項目が並びます（`docs/SOUND_DEBUG_TOOL.md` §1 と同じ判断）。
焼いた資産を持つのは、焼く道具が出来てからです。

書式は 1 行 1 項目の `key = value`。バイナリにしていないのは、**道具の設定は
git で差分が読めるほうが大事**だからです（資産は別書式になります）。

### 描画に Dear ImGui を使っている理由

Unity 側の監視窓は全部イミディエイトモード（`OnGUI` / `GUILayout`）で書かれています ──
`AcousticToolsWindow.cs` に 102 箇所、`StatusMonitorWindow.cs` に 58 箇所。
**同じ書き方のまま移せる**ので、10 枚の窓を運ぶ費用がいちばん安くなります。

⚠ 資料の「外部ライブラリなし」は**エンジンの主張**です。ここは道具なので既製品を使い、
浮いた時間を音に回します。**エンジン側は 0 本のまま**で、`AfHostCore`（音とモジュール）も
ImGui に依存していません ── だから検査は GUI 抜きで回ります。

### なぜ「原本を掴まない」が要だったか

Unity はネイティブ DLL を `LoadLibrary` したまま離しません。だから
**エンジンをビルドし直すたびに Unity を閉じる**必要がありました
（2026-08-19 には実際 `Device or resource busy` で DLL の差し替えが止まっています）。

ここでは読み込む前に**影武者（`%TEMP%\afhost\` への複製）を作って、そちらを読み込みます。**
原本は誰にも掴まれないので、**ホストを走らせたままエンジンをビルドし直せます。**

★ これは「掴んでいないはず」という主張ではなく**検査**にしてあります。
`--selftest` は、影武者を使わずに直接読んだ場合に原本が**掴まれること**も同時に確かめます。
そこが偽なら OS がそもそも掴まないということで、影武者は何も稼いでいないことになるからです。

## 使い方

```
AfHost.exe [プロジェクト.afproj]             窓を出す（引数のプロジェクトを開く）
AfHost.exe --tone                            起動と同時に試験信号を鳴らす
AfHost.exe --shot out.png [--frames 90]      自分の絵を PNG に書き出して終わる
AfHost.exe --panel SoundLibrary                 図を撮るとき、見せたいパネルを前に出す
AfHost.exe --select 1 --play                 台帳の N 行目を選んで鳴らす（図を撮る用）
AfHost.exe --rename                          名前の変更を開いた状態にする（図を撮る用）
AfHost.exe --menu                            空き場所の右クリックを開いた状態にする（図を撮る用）
AfHost.exe --fire 0                          N 番目のイベントを発火する（図を撮る用）
AfHost.exe --evedit                          イベントを 1 つ作って編集メニューを開く（図を撮る用）
AfHost.exe --info                            プロパティを「情報」側にして撮る（図を撮る用）

AfHostCheck.exe --selftest                   対話なしで一通り確かめて、戻り値で通知
AfHostCheck.exe [DLL のパス]                 コンソールで対話。h でキー一覧
```

窓の配置は `AfHost.ini` に覚えます（初回だけ既定の配置を組む。
`表示 > 配置を既定に戻す` でいつでも戻せます）。

★ **配置には版があります**（`AfHost.layout`）。窓を増減したり置き場所を変えたら、
`kLayoutVersion` を上げること。⚠ 上げないと、**前の配置を覚えた ini のせいで
消えた窓を探すはめ**になります（「波形」を畳んで「プロパティ」を真ん中へ動かした回で
実際に必要になりました）。上げた回だけ既定に組み直し、以後は覚えた配置を使います。

```
✔ 片側を黙らせても、もう片方は鳴っている ── 左 0.00000000 ／ 右 0.2588（実効値）
✔ 黙らせるとき一気に 0 にせず傾斜で落とす
✔ 範囲の外を打ち込んでも挟んで受け取る ── 999→-24 半音 / 99999→20000 Hz / -5→20 Hz
✔ 本を 2 つ載せると 2 つとも鳴る ── 2 本
✔ 重ねると本当に足し合わされる ── 1 本 17.191 → 2 本 34.381
✔ 止めたのは指した本だけ（もう 1 本は鳴り続ける） ── 1 本残った
✔ WAV でないものは取り込まない
✔ 影武者なしで直接読むと、原本が掴まれる（比較の土台）
✔ 影武者ごしなら、読み込んだまま原本を書き込みで開ける
✔ 掴み直す（ビルドし直した DLL を載せ替える）
✔ 解放する
```

⚠ **「輪の大きさ」と「1 回あたり」は別物です。**デバイスが確保している輪は 970 サンプル
ですが、共有モードはデバイス周期ごとに起こしてくるので **1 回に渡されるのは 441**。
持ち時間は後者で決まります。最初は輪で割っていて、**負荷率が 2.2 倍甘く出ていました**
（0.159 % と表示 → 正しくは 0.350 %）。波形の周期が計算と合わないことで気づきました。

### 別の機械（ノート）から触る

**実行はこの機械のまま、手元だけノートにします。**行き来させません。

理由は数字です。`1 回 441 サンプル（10.00 ms）` も `最悪 0.0346 ms ＝ 持ち時間の 0.346 %` も、
**Yamaha AG03MK2 で測ったから意味がある**値です。環境ごとノートへ移すと全部測り直しで、
資料に載せた数字も撮り直しになります。だから**動かすのはこの機械に固定**します。

道は 2 本あって、**要るものが違います**。

| | 画面を配信する | SSH |
|---|---|---|
| 画面を見て**触る** | ○ | ✕（PNG を撮るだけ）|
| **音を聴く** | ○ | **✕**（文字だけ）|
| 負荷率・遅延の数字 | ⚠ **化ける**（下記）| ○ **本物のまま** |
| 要るもの | Steam（導入済み）| OpenSSH サーバ（未導入）|

普段は**画面配信**、数字を採るときだけ **SSH**、と使い分けます。

#### 画面を配信する ── Steam Remote Play

⚠ この機械は **Windows 11 Home** なので、**Windows のリモートデスクトップ（ホスト側）は
使えません**。Home に機能自体がありません。代わりに Steam を使います。**入れ足すものはありません** ──
Steam は導入済みで、`27036` 番が既に待ち受けています。GPU も **RTX 4070 Ti SUPER** なので
NVENC で圧縮でき、道具の窓のように**毎フレーム全面を描き直すもの**でも耐えます。

1. この機械の Steam を起動したままにする（設定 > Remote Play を有効に）
2. ノートに Steam を入れ、**同じアカウント**で入る
3. ノートの Steam から、この機械を選んで**デスクトップを配信**
   （道具だけ映したいときは、`AfHost.exe` を「Steam 以外のゲーム」として登録）

LAN でも外からでも繋がります（Steam が中継します）。Hamachi は要りません。

⚠ **音の数字はこのとき当てになりません。**Steam は配信中、既定の出口を
`Steam Streaming Speakers` に差し替えます。道具は**既定の出口を開く**ので、
負荷率も 1 回あたりのサンプル数も、そちらのものに化けます。

**見分けは付きます** ── ステータスバーの左端に**開いたデバイスの名前が出る**ので、
`Yamaha AG03MK2` 以外が出ていれば、その数字は配信経路のものです。

> 数字も本物のまま画面も欲しい場合は **Sunshine + Moonlight**（自前・アカウント不要）で、
> 既定を差し替えず**実デバイスを覗き見る**設定にできます。Steam で不足を感じたら。

#### 締め出されたときの生命線 ── Chrome リモートデスクトップ

⚠ **Steam Remote Play はロック画面・サインイン画面を映せません。**サインイン済みの画面しか
掴めない仕組みなので、`Win+L` で鍵を掛けた後や、**Windows Update が再起動した後**は
外から入れなくなります。この機械は自動サインインも無効です。

Chrome リモートデスクトップは **Windows のサービス（`chromoting`）として動く**ので、
鍵のかかった画面もサインイン画面も出せます。

##### ★ RustDesk を見送った理由（蒸し返さないための記録）

一度は RustDesk で進めかけました。落としたのは**機能の差ではありません**。

- **winget に居ない。**ESET が `RemoteAdmin.RustDesk` として検知したことで審査を通らなくなり、
  登録が削除されたまま。マルウェアだからではなく、**遠隔操作という機能そのもの**が
  「望ましくない可能性のあるアプリ (PUA)」に分類されるため。
- ⚠ **この機械にはウイルスバスター クラウドが常駐している。**同じ分類で止めにきます
  （Defender 側は PUA=2＝記録のみで素通り）。除外登録で入れることはできますが、
  **留守中に定義更新で隔離されると、入り直す手段そのものが消えます。**
  バックアップが自分で消えるのと同じで、いちばん要るときに無い、という壊れ方をします。

Chrome リモートデスクトップは検知されないので、この risk ごと消えます。
**必要条件（サービス動作・ロック画面・再起動後）は同じく満たします。**
遅延は大きめですが、**普段の作業は Steam** なので、この道具に速さは要りません。
生命線に要るのは速さではなく確実さです。

##### 入れ方

前提は Chrome。この機械には入っています（`152.0.7977.64`）。

1. Chrome で **`remotedesktop.google.com/access`** を開く
2. 「**リモート アクセスの設定**」→ `chromeremotedesktophost.msi` が落ちてくるので実行
3. この機械の名前を決める
4. **PIN（6 桁以上）**を決める

⚠ **PIN が唯一の関門ではありません。**この機械が見えること自体が Google アカウントに
紐づいているので、**アカウント＋PIN の 2 段**になります。RustDesk の
「9 桁の ID ＋パスワード」より、ID を晒さないぶん堅いです。
それでも PIN は**誕生日のような当てやすい 6 桁にしないこと**。

##### ⚠ その下に SSH を敷いてある

上が何であれ、**入り直す道具が倒れる可能性は残ります**（サービスの停止、Chrome の更新事故、
アカウントの認証切れ）。OpenSSH は Microsoft 純正なので検知されず、**ロック画面でも
再起動後でも生きています**。倒れてもここから入って直せます。

```
Middleware\remote.ps1 -Health
```

で足回りを一覧できます。★**ビルドもせず、走っているものも止めません**
（締め出されていないかを見る窓なので、副作用があってはいけない）。

```
  OK  Chrome リモートデスクトップ        Running
  OK    └ Chrome               152.0.7977.64
  OK  SSH（最後の砦）                Running
  OK  Steam                    画面配信の側
  --  AfHost                   動いていない（異常ではない）
  --  最後の起動                    2026/08/29 17:31:30（2.4 日前）
  OK  再起動待ち                    なし
```

倒れていれば戻り値 1 と直し方を出します。**SSH が居ないときは赤で言い分けます** ──
その状態で締め出されると戻れないからです。`AfHost` が動いていないのは異常ではないので
灰色に留めました（赤にすると本当の異常が埋もれる）。

#### 使い分け

| 場面 | 使うもの |
|---|---|
| 普段の作業（画も音も要る）| **Steam Remote Play** |
| 鍵がかかった／再起動された後 | **Chrome リモートデスクトップ**（サインインし直す）|
| **その道具ごと倒れたとき** | **SSH** ── 純正なので検知されず、最後まで残る |
| 数字を採る・ビルドする | **SSH** ＋ `remote.ps1` |

Chrome リモートデスクトップでも音は届きますが、画質と遅延は Steam のほうが上です。**入り直すための道具**と
割り切って、鍵を開けたら Steam に持ち替えるのが軽いです。

⚠ **つけっぱなしの間、この机の画面は点いたまま・鍵も開いたままです。**
人が居る部屋なら見えるし触れます。鍵を掛けて防ぐ運用にできるのは、Chrome リモートデスクトップを入れた後です。

#### SSH ── 数字を採る／直す

音は届きませんが、**数字が本物のまま**なのはこちらだけです。

```
Middleware\remote.ps1 -Check                      ビルドして自己検査（戻り値で通知）
Middleware\remote.ps1 -Shot プロパティ             画面を PNG に撮る（引数は前に出すパネル名）
Middleware\remote.ps1 -Check -Shot イベント -Project foo.afproj
Middleware\remote.ps1 -NoBuild -Shot SoundLibrary    ビルドを飛ばす
```

撮った PNG は `Middleware/shots/`（追跡外）。`scp` でノートへ引けます。
走っている `AfHost` は先に止めます ── **exe 自身は掴まれる**ためで、
原本を掴まない話は読み込む DLL に限った性質です。

##### 下ごしらえ（この機械側・一度だけ）

OpenSSH サーバは未導入です（クライアントはあります）。**管理者の PowerShell**で:

```
Add-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0
Set-Service sshd -StartupType Automatic
Start-Service sshd
New-NetFirewallRule -Name sshd -DisplayName "OpenSSH Server" -Enabled True -Direction Inbound -Protocol TCP -Action Allow -LocalPort 22
```

既定のシェルを PowerShell にしておくと `remote.ps1` をそのまま叩けます:

```
New-ItemProperty -Path "HKLM:\SOFTWARE\OpenSSH" -Name DefaultShell `
  -Value "C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe" -PropertyType String -Force
```

ノートから: `ssh <ユーザ>@192.168.11.2`（同じ LAN）／外からは Hamachi の `25.13.44.234`。

⚠ **パスワード認証のまま外へ晒さないこと。**鍵認証にして
`%ProgramData%\ssh\sshd_config` で `PasswordAuthentication no` にするか、
LAN と Hamachi の中だけに留めてください。

コメントに「これはボイス管理ではありません」と書いてありますが、**いずれ本物にします**。

### いま無いもの ── ゲーム側から呼ぶ口

**このミドルウェアには、ゲームがリンクできる物がまだ 1 つもありません。**
あるのは道具（`AfHost.exe`）と検査（`AfHostCheck.exe`）だけです。
ここが最大の空白で、資料の必須 32 項目の大半はその向こう側にあります。

### 併用の形

音響エンジンは、**ボイス 1 本ぶんの空間化 DSP** として挿さります。

```
音源（dry・モノ） → ミドルウェアの調整 → [AF_VoiceRender] → ステレオ → バス → 出力
                                          ↑ ここだけがエンジン
```

★ **ミドルウェアはエンジンを知りません。**両方を知るのは Bridge だけ
（＝いまリンクしていない状態を、最終形でも保つということです）。

⚠ エンジンは**尾の共有バス**（部屋ごとに 1 本）を持ちます。
ミドルウェアのバス階層は、**それを載せられる形**にしておく必要があります。

### まだ作らないもの

**インタラクティブミュージック / 多チャンネル出力（5.1・Atmos）/ 畳み込みリバーブ等の高度な DSP /
VST・CLAP ホスティング。**削る判断そのものを説明できる状態にしておきます。

## 構造

| ファイル | 役目 |
|---|---|
| `src/block_source.h` | **ミドルウェアとシステムの境目。**実時間スレッドが音を要求する唯一の口 |
| `src/voice_bus.h` | 試聴の音を**同時に数本**束ねる。⚠ ボイス管理ではない（優先度もスティールも持たない）|
| `src/audio_device.*` | WASAPI 共有モードの出力。外部ライブラリ 0 本（`ole32` / `avrt` のみ） |
| `src/project.*` | `.afproj` の読み書き。**オーサリングツールの形の芯** |
| `src/wav.*` | WAV を読む。**読むだけ**（加工は持たない） |
| `src/library.*` | 音源とフォルダの台帳。**プロジェクトが直接持つ** |
| `src/events.*` | イベント。**ゲーム側からの発火点**。音源は番号で指す |
| `src/undo.h` | 元に戻す／やり直す。**台帳とイベントをまとめた写しを積む** |
| `src/module.*` | 影武者ごしの DLL 読み込み |
| `src/selftest.*` | 自己検査。**GUI 版とコンソール版が同じものを呼ぶ**（答えを 2 つ持たせない） |
| `src/host_util.h` | 探索候補などの小物。**両方で共有**（同じ理由） |
| `src/app_main.cpp` | Windows アプリケーション（ImGui + D3D11） |
| `src/console_main.cpp` | コンソール版 |
| `third_party/imgui/` | Dear ImGui（docking 版）を同梱。15 ファイル・3.7MB |

依存の向きは `AfHost（GUI）→ AfHostCore + imgui` / `AfHostCheck → AfHostCore`。
**`AfHostCore` は ImGui にもエンジンにも依存しません。**

エンジンを載せるときは、**読み込んだ DLL を呼ぶ `BlockSource` を 1 つ足すだけ**です。
デバイス出力も実時間スレッドも一切変わりません。

## 開いている点

- 実時間スレッドの規律は**確保しない・待たない**を書き手が守っているだけで、まだ検査が無い
- `--selftest` は音が**出た**ことと**取り込んだ音がブロックとして出てくる**ことは見ますが、
  **鳴っている音が正しいか**は確かめていません（波形の一致までは見ていない）
- 名前（`Sounding`）は仮称。仮称のうちは資料と連絡板にしか書かない
  （target 名・ディレクトリ名に入れると変更費用が跳ね上がるため）
