### 2026-08-19 システム側 — B1 実装（回折タップの HRTF）

`33232c2`。遮蔽中、実エネルギーを運んでいる回折タップに定位の手がかりが載るようになった。

実測（kemar 710方向/139タップ、右 60° の開口・直接音は透過まで落とした状態）:

| | 変更前（等パワーパン） | 変更後（HRTF） |
|---|---|---|
| ITD | **0 us** | **−1000 us**（右耳が先） |
| 前後の差 | **−180 dB**（＝完全に同一の音） | **−1.2 dB** |
| 総エネルギー | 基準 | **+1.75 dB**（方向ごとの頭部の影ぶん） |
| 乗り換えの段差 | — | 重み 0.25 刻みで最大 **1.95 dB** |
| コスト（1 音源） | 2.80 %（0.298 ms/block） | **3.89 %（0.415 ms/block）** |

**「前後の差 −180dB」が B1 の核心。** 等パワーパンは到来方向を左右軸へ投影した値しか
持たないので、正面の開口と真後ろの開口が**ビット単位で同じ音**になっていた。

コストは**遮蔽されている間だけ**。回折タップが 1 本も無いフレームは HRTF を回さないので、
見通せていれば従来と同じ（実装として `hasHrtfBus()` で切っている）。

設計上の決めごと:

- 載せるのは**最強の F タップ 1 本**。拮抗した 2 開口で選択が振動すると像が左右に暴れるので、
  **2dB のヒステリシス**を入れた（`diffractionHrtfMarginDb`）。同一開口の判定は index ではなく
  **到来点の位置**（タップの並び順はフレーム間で保証されない）
- 載せ替えはタップ補間（30ms）が受け持つ。1 フレームで切り替えると段差になる
- 回折バスだけ HRIR の平均パワーゲイン（kemar 2.11 ＝ **+3.2dB**）で割ってパンと同音量に揃えた。
  揃えないと「HRTF に載せた」だけで回折が 3dB 持ち上がり、D⊕F の連続クロスフェードが壊れる。
  **直接音側は触っていない**（尾の較正がその音量前提で決まっているため）

インスペクタ: `diffractionHrtf`（既定 ON）/ `diffractionHrtfMarginDb`（既定 2dB）。

⚠ **★ABI が変わった。DLL と C# を必ず一緒に差し替えること。**

`AF_VoiceTap` に `hrtfWeight` が増えて **44 → 48 バイト**になった。
古い DLL のまま新しい C# を動かすと、マーシャラが別の刻み幅で書き込んで
**例外も出さずにタップの中身が化ける**。

そこで `AF_AbiVersion()` を新設し、`VoiceConvolver.Awake` で照合するようにした。
不一致なら `Debug.LogError` を出して**鳴らさない**（黙って化けるより止める）。
A1 の教訓「人手で同期する約束は守られない」を機械にやらせた形。

## システム側へ返したい確認

- ~~**屋外の広い自由空間は部屋グラフで「部屋」になるか？**~~
  → **回答済み（2026-08-19 システム側）。ならない。`RoomVolumeAt` は 0 を返す。**

  `2e63c46` で検査として固定した（`scene_regression.cpp` の `testOutdoorIsNotARoom`）。

  | 形 | 部屋数 | 実効体積 |
  |---|---|---|
  | 地面だけ 90×90m | 0 | 0 m³ |
  | 地面＋腰高の塀 1.2m | 0 | 0 m³ |
  | 地面＋壁＋天井 | ≥1 | >0 m³ |

  仕様として決まっている：**格子の外周に届く成分は部屋にしない**。壁だけでは足りず、天井が要る。
  したがって屋外の残響は**フォールバック経路**（レベル全体の外形 AABB 体積 ＋
