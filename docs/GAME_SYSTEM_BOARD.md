### 2026-08-19 システム側 — B1 実装（回折タップの HRTF）

`33232c2`。遮蔽中、実エネルギーを運んでいる回折タップに定位の手がかりが載るようになった。

実測（kemar 710方向/139タップ、右 60° の開口・直接音は透過まで落とした状態）:

| | 変更前（等パワーパン） | 変更後（HRTF） |
|---|---|---|
| ITD | **0 us** | **−1000 us**（右耳が先） |
| 前後の差 | **−180 dB**（＝完全に同一の音） | **−1.2 dB** |
| 総エネルギー | 基準 | **+1.75 dB**（方向ごとの頭部の影ぶん） |
| 乗り換えの段差 | — | 重み 0.25 刻みで最大 **1.95 dB** |
| コスト（1 音源） | 2.80 %（0.298 ms/block） | **3.89 %（0.415 ms/block）** |

**「前後の差 −180dB」が B1 の核心。** 等パワーパンは到来方向を左右軸へ投影した値しか
持たないので、正面の開口と真後ろの開口が**ビット単位で同じ音**になっていた。

コストは**遮蔽されている間だけ**。回折タップが 1 本も無いフレームは HRTF を回さないので、
見通せていれば従来と同じ（実装として `hasHrtfBus()` で切っている）。

設計上の決めごと:

- 載せるのは**最強の F タップ 1 本**。拮抗した 2 開口で選択が振動すると像が左右に暴れるので、
  **2dB のヒステリシス**を入れた（`diffractionHrtfMarginDb`）。同一開口の判定は index ではなく
  **到来点の位置**（タップの並び順はフレーム間で保証されない）
- 載せ替えはタップ補間（30ms）が受け持つ。1 フレームで切り替えると段差になる
- 回折バスだけ HRIR の平均パワーゲイン（kemar 2.11 ＝ **+3.2dB**）で割ってパンと同音量に揃えた。
  揃えないと「HRTF に載せた」だけで回折が 3dB 持ち上がり、D⊕F の連続クロスフェードが壊れる。
  **直接音側は触っていない**（尾の較正がその音量前提で決まっているため）

インスペクタ: `diffractionHrtf`（既定 ON）/ `diffractionHrtfMarginDb`（既定 2dB）。

⚠ **★ABI が変わった。DLL と C# を必ず一緒に差し替えること。**

`AF_VoiceTap` に `hrtfWeight` が増えて **44 → 48 バイト**になった。
古い DLL のまま新しい C# を動かすと、マーシャラが別の刻み幅で書き込んで
**例外も出さずにタップの中身が化ける**。

そこで `AF_AbiVersion()` を新設し、`VoiceConvolver.Awake` で照合するようにした。
不一致なら `Debug.LogError` を出して**鳴らさない**（黙って化けるより止める）。
A1 の教訓「人手で同期する約束は守られない」を機械にやらせた形。

### 2026-08-19 システム側 — C1 実装（ポータルの自動生成＋適用範囲を経路単位へ）

`f05b654`。**当て木「`AcousticPortal` を手で置く」は外せる**（当て木欄から消した）。

#### 先に §7.7 を直した ── これが本体

自動生成そのものより、こちらが関門だった。以前は
`if (!portals_.empty())` ＝ **シーンに 1 枚でもあれば回折はポータルが全部決める**。
手置き前提なら実害が出にくかったが、**自動生成すると全シーンがその状態になる**。

| | 変更前 | 変更後 |
|---|---|---|
| 無関係なポータル 1 枚が柱の回り込みに与える影響 | **−3.3 dB** | **0.0 dB** |

二値切り替え（「線分が矩形を通るか」）は**却下済み**（実測 8.8 dB の崖）なので採らず、
**矩形と線分の距離**から作った連続量 `portalGovern`(0..1) にした。
支配下では置き換え、範囲外は一般の稜線回折へ滑らかに戻る。

| | 実測 |
|---|---|
| 支配の境目を 0.1m 刻みで歩いたときの最大隣接差 | **1.77 dB**（崖なし） |

支配下で「混ぜずに置き換える」性質は維持した。混ぜると閉じた扉の所で
回折が −39dB の床を作る問題が復活するため。

#### 自動生成

開口ボクセルの外接箱から矩形を作る（法線の最強軸を面の向きとみなし、残り 2 軸で張る）。

| | 実測 |
|---|---|
| 戸口 0.90 × 2.00m の検出 | **0.90 × 1.95m**（格子 0.15m） |
| 戸口越しの生存ゲイン 手置き(実寸) vs 自動 | **差 0.01 dB** |
| 自動生成での帯域傾き 4k/125 | **−3.12 dB**（ポータル無しは −1.75 dB）＝フレネルが走っている |
| コスト（5部屋・音源8本） | 自動 OFF **11.14 ms** → ON **9.75 ms** |

**速くなっている。** ポータルが稜線探索を肩代わりするぶん。
遠い口は `portalGovern`（内積数回）で落ち、高い `portalCoupling` は呼ばれない。

**手置きは消えない。** 自動ぶんだけがリスト末尾で入れ替わる（OFF→ON→OFF で検査済み）。
枠の内側ぴったりに置きたい所だけ手で置けばよい。

#### 置き忘れの警告（最低要求だったもの）

部屋が 2 個以上あるのにポータルが 0 枚なら **1 度だけ**警告する。
`AF_SceneGetPortal` で矩形を読み出せるようにしたので、**ギズモで確かめられる** ──
自動生成が戸口を正しく見つけたかは音では気づけないので。

インスペクタ: `autoPortals`（既定 **ON**）/ `autoPortalMinArea`（既定 0.25 m²）/
`portalGovernRange`（既定 1.0m）。

⚠ **ABI 版が 3 になった。B1・C7 と同じ差し替えで一緒に入る。**
