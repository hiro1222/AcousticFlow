# 何を焼けて、何は焼けないか ── 再導出

2026-08-24。`HYBRID_TRADEOFF.md` の切り分けは**実測で否定された**ので、
前提から立て直す。この文書が現行の判断。

---

## 0. 前の基準が何を間違えたか

前は **「変わるか」**で切ると書いてあった。文としては正しいが、**当て方を間違えた。**

尾（残響）を「焼く」に入れた根拠は:

> 尾は**部屋の形にしか依存しない**／秒で遅れてよい／重い（48.5%）

このうち **1 つめが偽**だった。実測（`diagnoseTailProbeDensity`）:

| 吸う小部屋・音源も同室 | 減衰 | RT60 | 量 |
|---|---|---|---|
| 扉 開 | 181.1 dB/s | 0.33 s | 13.50 dB |
| **扉 閉** | **447.4 dB/s** | **0.13 s** | 13.56 dB |

**量は 0.1 dB しか動かないのに、形が 266 dB/s 変わる。**
連成残響 ── 扉が開いていると隣の響く部屋とつながって減衰が遅くなる。

★間違いの正体は **「部屋の形」と「音の通り道」を同一視したこと**。
部屋の形は動かない。だが**音が通る道には動く物が入る**。

### 念のための裏取り ①: 機構は本当に連成か

連成なら、効きは**2 部屋の残響時間の差**で決まるはず。小部屋の吸音率を振った:

| 小部屋の α | 扉 開 | 扉 閉 | **差** |
|---|---|---|---|
| 0.10（隣室と残響が近い） | 84.8 | 85.7 | **1.0 dB/s** |
| 0.20 | 114.2 | 118.5 | 4.2 |
| 0.40 | 165.3 | 238.1 | 72.8 |
| 0.60 | 239.4 | 397.4 | **158.0 dB/s** |

★**残響差が無いと扉はほとんど効かない（1.0 dB/s）。差が開くほど効く。**
機構は連成残響で確定。

### ★ここから出る判定基準

> **焼けるかどうかは「隣り合う空間の残響差」が決める。**

- 隣室と残響が近い場面（同じ材質の部屋が並ぶ）→ 扉は尾に効かない。**焼ける**
- 響く空間と吸う空間が扉でつながる → **焼けない**

この作品は**後者を狙っている**（洞窟／部屋、扉の開閉が主題）。だから焼けない。
⚠ 逆に言えば「一般論として尾は焼けない」ではない。**この作品の狙いが焼けなくしている。**

### 念のための裏取り ②: 測定そのものが信用できるか（Sabine と突き合わせ）

扉を閉じれば小部屋は孤立するので `RT60 = 0.161V/(Sα)` が当てはまるはず:

| α | 実測 RT60 | Sabine | ずれ |
|---|---|---|---|
| 0.10 | 0.934 s | 1.073 s | −13% |
| 0.20 | 0.507 s | 0.537 s | −6% |
| 0.40 | 0.252 s | 0.268 s | −6% |
| 0.60 | 0.151 s | 0.179 s | −16% |

★**エンジンの残響は Sabine と 6〜16% で合う。**測定も模型も壊れていない。

⚠ ここへ来るまでに**測り方で 2 回間違えた**（記録として残す）:

1. **試験場面の小部屋に穴があった。** 床と側壁を x∈[1,5] にしていたが内寸は
   x∈[0.65,4.85]。**仕切り際に 0.35m の隙間**が空いてエネルギーが漏れ、
   RT60 が理論より一貫して短く出た（最大ずれ 37%）。塞いで 13% に。
2. **跳ね返りの打ち切り。** 既定 32 回では α=0.10 で 1 回 0.46dB ＝
   **32 回で 14.6dB しか落ちない**。尾が減衰しきる前に切れて当てはめが速くなる。
   256 回にすると 0.700 → 0.934 s（穴を塞いだあとで初めて見えた）。
   → ★**響く空間では、実行時の尾も同じ理由で短い。**これは実装の既知の限界として残る。

## 1. 新しい基準

> ### 焼けるのは「動く物が触れられない量」だけ。

「静的な形状から出るか」ではない。尾は静的な形状から出るが、
**戸口を通る経路に扉が入る**ので焼けない。

判定は 2 段:

| | 問い |
|---|---|
| ① | その量の**計算に、動く物が入りうるか**（経路上・入力に） |
| ② | 入るなら、その依存を**焼いた側で表現できるか**（引数化できるか） |

尾は ① で「入る」、② で「できない」だった。
② ができない理由: 焼いたエコグラムは**ビンごとの和**なので、
「どのエネルギーが戸口を通ってきたか」が足した時点で消えている。
あとから引くには近似スカラを当てるしかなく、それは扉の効きに**2 つめの式**を作る（決めごと #1 違反）。

## 2. ★見えてきた線: 「構造」は焼ける、「エネルギー」は焼けない

再導出して並べると、きれいに 2 種類に割れる。

### 焼ける ── **構造（集合・分割）**

動く物は構造を**書き換えない**。せいぜい「その先で遮る」だけで、それは後段の判定。

| 量 | 中身 | 状態 |
|---|---|---|
| 部屋の分割 | ボクセルからの部屋 id | ✅ 実質もう焼いている（動く実体は入力から外してある: `if (in.moved) continue`） |
| 戸口（ポータルの矩形） | 部屋グラフから自動生成 | ✅ 同上 |
| **静的な稜線の集合** | 部屋の角・柱・戸口の枠 | ⬜ **未着手。ここが残っている本命** |
| BVH の静的部分 | 走査の加速構造 | △ 差分更新で足りている（作り直しの代金は**測定ノイズ以下**） |

★構造を焼いても**答えは 1 つのまま**。稜線は「線分の集合」なので、
焼いた集合と実行時の集合を**合流**させても、同じ表現の同じ量が増えるだけ。
決めごと #1 に触れない。

### 焼けない ── **エネルギー（量・形）**

経路に動く物が入る。入った瞬間に値が変わる。

| 量 | 動く物がどう触れるか | 判定 |
|---|---|---|
| 残響の尾 | **扉で連成が変わる**（実測 266 dB/s） | ❌ 焼けない |
| 早期反射 | 扉が反射面と経路を塞ぐ | ❌ 焼けない（※下記） |
| 遮蔽・回折・開口積分 | **主題そのもの** | ❌ 意図的に実行時 |

※ 早期反射は「焼く／焼かない」の問題ですらなかった。
レイがリスナー中心でエコグラムと同じ形なのに、**音源ごとに撃っていた**だけ。
共有して解決済み（取り分 8.2% → 4.4〜6.0%、ビット一致）。

## 3. 費用はどうなったか ── **焼く動機がほぼ消えた**

焼こうとした最大の動機は「尾が重い（48.5%）」だった。
それは**焼かずに消えた**（部屋ごとの共有）。

| | 前 | 後 |
|---|---|---|
| エコグラム（音源 16 本） | 16.798 ms | **2.927 ms** |
| フレーム全体（12 音源・4 コア） | 3.182 ms | **1.982 ms** |

残る 2.927 ms は**レイ側の固定費**で、音源数で伸びない。

いま焼ける対象の取り分:

| | 取り分 |
|---|---|
| エッジカタログ | 0.299 ms（6.3%） |
| 部屋分割・自動ポータル | 約 1.3% |

★**焼いても速くならない。** 焼く理由は費用ではなく**品質**になった。

## 4. だから「ハイブリッド」の意味が変わる

| | 前の言い方 | いまの言い方 |
|---|---|---|
| 何のために焼くか | 重い尾を焼いて軽くする | **探索の不安定を焼いて消す** |
| 焼く対象 | エネルギー（尾） | **構造（稜線・部屋）** |
| 得るもの | 費用が半分 | **音の安定** |
| 差別化 | 「焼いた場の再生」の土俵に降りる | **降りない。場は実行時のまま** |

★資料の言い方（`HYBRID_TRADEOFF.md` 欠点 1）は書き直しが要る。
**エネルギーの場は焼いていない**ので、Steam Audio / Project Acoustics と
同じ土俵に降りたことにはならない。

言えるのはこう:

> **構造は前もって整えるが、音のエネルギーは全部その場で解く。**
> だから扉を閉めれば部屋が乾き、洞窟に壁を置けば響きが変わる。

## 5. 残っている仕事（優先順）

### ① 静的な稜線を焼く ⬜ ← 次

**なぜ**: 探索の不安定の源がここ。リスナー中心のキューブマップを 3 フレームに 1 回
作り直すので、動くと稜線が現れたり消えたりして候補が点滅する
（実測: く字の廊下で 51 点中 22 点・切り替わり 11 回）。

**やり方**: 静的な形状から一度抜いて空間に持つ。動く物の稜線は実行時にその周りだけ抜いて**合流**。

```
焼く    地形・建物・柱・戸口の枠   → 空間に持って引くだけ
実行時  置かれた壁・扉・動く物     → その物の周りだけ抜く（数が少ないので安い）
合流    候補探索は両方を見る
```

⚠ **縛り**: 焼く側と実行時側は**同じ模型**でなければならない。
焼いた稜線が BTM、実行時が前川、では継ぎ目が段差になる。
→ **BTM を焼く側に使う案は、この縛りと引き換え。**（`HYBRID_TRADEOFF.md` 利点 3 の再評価が要る）

### ② 固定費 2.9 ms をどう扱うか ⬜

焼くのではなく、**レイ数か分割の見直し**で。焼いても主題が死ぬだけなので。

### ③ 本番ステージで測り直す ⬜

§0 の測定は箱で組んだ 2 部屋 1 対。**長い廊下・L 字・高低差では違う数字が出る。**
`diagnoseTailProbeDensity` をそのまま当てられる形にしてある。

## 6. この再導出で守るようにした検査

| 検査 | 何を守るか |
|---|---|
| `扉を閉めると吸う部屋は速く乾く（連成が切れる）` | **焼かない判断の根拠そのもの**。崩れたら体験が壊れる |
| `尾の減衰は部屋の中より部屋をまたぐ方が大きく変わる` | 部屋という単位が意味を持っているか |
| `同じ部屋の音源は同じ尾を共有する` | 共有の契約 |

★**判断の根拠を検査にしてある。** 数字が動いたら、判断ごと見直す合図になる。
