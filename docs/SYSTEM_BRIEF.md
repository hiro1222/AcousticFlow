# AcousticFlow — サウンドシステム技術ブリーフ

他の作業者（人・AI）へ引き継ぐための自己完結した説明。
実測値はすべてこのリポジトリの回帰テストが出した数字。

---

## 1. 何を作っているか

**実行時に形状が変わる空間のための、非ベイク音響レンダリングエンジン。**

- 扉の開閉、壁の破壊、手続き生成で形状が変わっても**事前計算をやり直さない**
- 毎フレーム、音源ごとにインパルス応答（IR）を組み立てて畳み込む
- コンセプト: **周辺環境の変化を音で伝える**（扉がどのくらい開いたか、部屋に入った瞬間）
- 対象ジャンルはホラー

### 設計上の第一制約は「連続性」

精度ではなく連続性を優先する。幾何音響は「どの稜線か」「見えるか否か」「どの経路か」という
**離散的な判定**の上に建っており、その離散性がリスナーや形状が動いた瞬間に
**知覚的な跳び**として出る。これがこのプロジェクトで繰り返し出た問題の共通原因。

### 幾何と波動の役割分担

| 担当 | 手法 |
|---|---|
| **方向（定位）** | 幾何音響（レイ・稜線探索） |
| **開口を通るエネルギー** | 波動側（フレネルゾーン、キルヒホッフの開口積分、合成透過率） |

理由: 幾何音響は**開口面積という概念を持たない**（レイと稜線しか知らない）。
前川の式は半無限スクリーンの実験式でエネルギー保存から導かれていない。
「隙間をどれだけのエネルギーが通るか」を稜線探索から絞り出そうとして 6 回失敗した経緯がある。

## 3. 1フレームの流れ

```
Unity: 形状を収集（BoxCollider/Mesh）→ AF_SceneUpdateInstance で反映
  ↓
AF_SceneUpdate(dt)   役割ごとに更新レートが違う
    役割1（毎フレーム）  遮蔽・回折
    役割2（4フレーム毎）  残響エコグラム
    早期反射（3フレーム毎）／回折二次音源（2フレーム毎）／エッジカタログ（3フレーム毎）
  ↓
Unity: 音源ごとに「タップ」を組む（SourceTaps）
    直接タップ  = ソフト遮蔽の6帯域透過 × 距離減衰
    反射タップ  = 早期反射の像源（位置→遅延・6帯域ゲイン）
    回折タップ  = 開口の方向・経路長・遮蔽割合
  ↓
VoiceConvolver → AF_VoiceSetTaps → C++ 側で畳み込み
    タップ畳み込み（6帯域分割・クロスフェード補間）
    ＋ 後期尾IR（エコグラムから生成、分割FFT）
    ＋ HRTF（直接音のみ）
```

### 帯域

全体で **6 帯域**（125 / 250 / 500 / 1k / 2k / 4k Hz）。
DSP のクロスオーバーは 177 / 354 / 707 / 1414 / 2828 Hz の直列ローパスで、
「低域を抜いた残りを次へ送る」補完型（全帯域同じゲインなら完全再構成）。

## 4. 主要アルゴリズム

### 4.1 遮蔽（ソフト遮蔽）

単一レイの二値判定をやめ、音源まわりの円盤をサンプルして
「一部だけ遮られる」状態をそのまま数値にする（見通し 1.0 → 境界 約0.5 → 影 材質の透過）。
分岐が要らないので連続。

### 4.2 回折（中核）

```
稜線探索 → クラスタリング → 開口点の決定 → ゲイン算出
```

**稜線候補**: ブロッカーの箱の 12 稜線＋エッジカタログ（キューブマップ由来）＋メッシュの回折稜線。
稜線上で `g(t)=|from−P|+|P−to|` を三分探索し、可視領域に制約した最小点を二分探索で求める。

**ブロッカーの範囲**: 直接線が交差する箱（1m 膨張）**＋ それと同一平面の箱**。
後者が無いと、仕切りが左右2枚でできているとき開口の片側の縁しか候補に入らない。

**可視判定（跨ぎ判定）**: 経路の向きに最も沿う箱の軸で回折点を挟む線分が塞がっていないか。
「縁の向こうが実際に開いているか」を直接聞く。これが幻の経路問題の解。

**掠め判定**: 貫通区間の端点が回折点からどれだけ離れているかを **0〜1 の重み**で返す
（`penNearWeight`）。二値の閾値にすると候補が満額で生まれ／消えて跳ぶ。

**クラスタリング**: 方向 25° 以内を同じ開口とみなす。さらに
**同一平面かつ間が開いている**クラスタどうしは 1 本に統合（櫛形フィルタ対策）。

**開口点**: 「開口の幾何的中心（掠め重みの重心）」と「リスナー側へ寄る重心（δ 重み）」の**中間**。
定位と経路長の両方にこの点を使う。実在の候補点 `Pc` は 2 次の起点や幅測定に別途使う。

**ゲイン**: `maekawa(δ) × openGain`。
`openGain` はフレネルゾーンの開口積分をコントラスト写像に通した値。

### 4.3 開口率（フレネル積分）

遮蔽物を「面で切った断面」ではなく**リスナーから見た影**として面に落とす（透視投影）。
影は凸多角形の和集合。面上を行ごとに走査し、δ 重み核（第1フレネル半径サイズ）で積む。

- **測る面は複数**。経路が横切る面をすべて拾い、最小を採る（ダクトは最も狭い断面で決まる）
- 所属判定は「実体に当たるか」ではなく「**面を横切るか**」。
  戸口を通り抜けても面は横切っているので落ちない。床・天井は水平経路と交わらないので入らない

### 4.4 ポータル（任意・精度の上積み）

矩形として開口を宣言する。**authoring が要る**ので唯一の手段にはしない方針。
`portalOpenBands`（矩形上のシルエット積分）＋ 指向性 cos ＋ 迂回の広がり損失。
`addPortalEchogram` で「塞がっている部分を透ってくる残響」を隣室へ流す
（＝**閉じた扉の向こうの響き**。幾何だけでは復元できない情報なので、ここがポータルの本領）。

**注意**: 現状ポータルが1枚でもあると稜線探索を**丸ごと迂回**する（`return np2`）。
同じ形状で両経路の差は最大 30 dB あるので、混在時の挙動に注意。

### 4.5 早期反射・後期残響

- 早期反射: レイトレースで像源を求め、位置→遅延・6帯域ゲインのタップに落とす
- 後期残響: エコグラム（512本×24バウンス）→ 帯域別の減衰を持つ尾 IR を合成 → 分割FFT畳み込み
- 散乱: 鏡面 √(1−s) と拡散 √s に分け、遅延とともに拡散へ寄せる

### 4.6 HRTF

KEMAR 実測データ。**直接音のみ**に適用。反射・回折タップは等パワーパン。

## 5. 設計上の決めごと（守るべき）

1. **同じ問いに2つの答えを持たせない。** 片方が古くなって矛盾する。
   このプロジェクトで繰り返し出た失敗の型
2. **連続量に二値の閾値を置かない。** 跨いだ瞬間に跳ぶ。重みへ写す
3. **実測は参照であって目標ではない。** 形は物理から採り、絶対値は演出で決める
4. **扉を特別視しない。** 扉は「影を落とす物体の一つ」。開口・戸口・開き角を名指ししない
   一般の規則で書く（手続き生成でも効くように）
5. **回折が運ぶ情報は「どこから聞こえるか」と「どれだけ遠いか」。**
   こもり（LPF）は壁を抜ける透過音が担う。役割を分ける
   （根拠: 700Hz 以下では ITD しか定位手がかりが無いので、回折を強くローパスすると
   定位させたい成分の高域を削る自己矛盾になる）
6. **数字で切り分ける。** 症状→実測→原因→対策→再実測。感覚で直さない

## 7. 未解決の課題（優先度順）

### 7.1 残響送出の飽和 ★最優先

部屋を移る境界で **−8.4 → 0.0 dB** と 10 dB 跳ね、以降 0.0 に張り付く。
`AF_SceneGetSourceOcclusion`（反射込みの生存）が見通した瞬間に 1.0 で頭打ちになるため。
**「隣の部屋に移った瞬間に音が変わりすぎる」の主犯はこれ。**回折側ではない。

### 7.2 早期反射の暴れ

隣接位置で −8.6 / −5.4 / −6.9 / −3.6 dB と **5 dB 級**に振れる。
本数は 4 で一定なので、どの面を拾うかが入れ替わっている疑い。回折で解いたのと同じ型かもしれない。

### 7.3 影境界でのゲイン段差（回帰 FAIL 1件目）

0.228（−4.5 dB）@ 影境界の 0.5m 先。
原因は特定済み: `openGain` の作り方が境界の両側で違う。
遮蔽側は `apertureContrastMap` を通して 1.0 に飽和、
見通し側は[生のフレネル値のまま](../AcousticEngine/src/Core/scene.h)。
`apertureContrast=1` では両側 0.5 前後で偶然そろっていたが、実機の 4 にすると片側だけ飽和して段差になる。

### 7.4 開口率のコントラスト飽和（回帰 FAIL 2件目）

扉 54° で出力が 1.0 に到達し、90° まで変化しない。
一方**ポータル開口率は 0.416 → 0.851 と上がり続けている** ── 幾何が出した情報を
`min(pow(x/ref, contrast), 1)` のクランプが捨てている。ref=0.278 に対し扉は 40° で既に 0.269 なので、
ほぼ全域が飽和側にいる。**「開口率をどう音量へ写すか」の設計をやり直す必要がある。**

なお `apertureContrast` は「幅の効き」も作っている（隙間 0.06→2.00m の効きは
contrast=1 で +4.7 dB、4 で +18.6 dB、8 で +37.2 dB）。
**連続性と幅の効きが同じつまみを取り合っている**のが構造的な問題。

### 7.5 その他

- **メッシュ壁**は跨ぎ判定が使えず従来のゲートのまま（幻・崖が残りうる）
- **0.03m 以下の隙間**は候補 0（稜線を面から 2cm 押し出す margin の分解能限界）
- **最悪フレーム 24.3 ms**（予算の 146%）
- 幅→量が広い側で頭打ち（2m 以上で差が出ない）

## 8. 試して却下した案（再挑戦しないための記録）

| 案 | 結果 |
|---|---|
| 開口を「開口率最大のポータル」として評価（距離＋幅だけ） | **衝立で破綻**。幅の法則は「壁の穴」の量で、有限の遮蔽物には定義されない。影の中が 0.000 になり 2/151 FAIL |
| 開口を複数点に散らして櫛形を埋める | **逆効果**。等間隔なので周期的なノッチが深くなる（3点で −27.4 dB、5点で −28.3 dB） |
| 稜線の可視割合を8点サンプルして重みにする | 経路長の跳び 2.65→2.44m しか改善せず、フレーム 7.0→8.1 ms（+15%） |
| 掠めの許容を入射角で伸ばす（t/sinθ） | 固定値と**1点も変わらなかった** |
| 芯（core）の面内の殻を margin まで締める | 幻は消えるが、厚い衝立を上から回り込む**正当な**経路が死ぬ（4件 FAIL） |
| 跨ぎ判定の軸を「箱の最も薄い軸」にする | 立方体で軸が恣意的に決まる（3軸同値） |
| 跨ぎ判定を稜線の2面の外向きにする | 幻が落ちない（0.088 → 0.183 と悪化） |
| UTD の採用 | 厳密解だが影境界で不連続（最良 3.8 dB / 最悪 17.6 dB の段差） |
| 段ごとの実行位相をずらす | 効果なし（18.65 → 19.35 ms） |

**幻の経路の教訓**: 正当な経路（厚い衝立の上）は縁から 0.11m 内側で中心面を横切るのに対し、
幻は 0.038m ── **幻の方が縁に近い**。だから距離・貫通量・位置のどの閾値でも分離できない。
違いは「縁の向こうが実際に開いているか」というトポロジだけだった。

## 9. 開発上の注意

- **日本語コメントを含むソースを PowerShell の `Set-Content` で書き換えない。**
  `Get-Content` が既定で ANSI として読むため文字化けし、改行まで消える（実際に scene.h を破壊した）
- コメントは「なぜそうしたか」「何を試して駄目だったか」を実測値つきで残す方針。
  コード量よりコメント量が多い箇所が多数ある
- `AF_DIFF_DEBUG=1` で回折の内訳（候補の棄却理由・開口率・2次経路）が stderr に出る
- 回折の二次音源は **2 フレームに 1 回**しか再計算されない。
  テストで位置を変えて測るときは `AF_SceneUpdate` を 2 回呼ばないと前の位置の値が返る
- エンジン既定とホスト（Unity）の設定が食い違うと、**テストが出荷しない設定を守る**ことになる。
  実際 `apertureContrast`（エンジン 1.0 / Unity 4.0）でこれが起き、誤診の原因になった
