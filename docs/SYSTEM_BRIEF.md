## 1. 何を作っているか

**実行時に形状が変わる前提で作られた、非ベイクの幾何音響エンジン。**

コンセプトは **「周辺環境の変化を、音によって伝える」**。
扉がどれだけ開いているか、部屋に入る瞬間、柱の陰に回り込んだこと ── それが音で分かる。
用途はホラーゲーム。

競合（Steam Audio / Wwise Reflect 等）との違いは **ベイクを前提にしていない**こと。
壁が壊れる・LOD で降りる・手続き生成で増える、を最初から想定して全部が実行時計算になっている。

### 設計上の第一制約は「連続性」

このプロジェクトで潰してきた音の不具合は、ほぼ全部**同じ型**だった。

> 連続量に二値の判定を置くと、跨いだ瞬間に音が跳ぶ。

実例（すべて実測）:

| 症状 | 原因だった二値判定 |
|---|---|
| 影境界で 12 dB の段差 | 「見通せているか」で回折ゲインと透過を切り替えていた |
| 音源を 5cm 動かすと 8.8 dB 落ちる | 「直線が矩形を横切るか」でポータルを使う/使わないを切り替えていた |
| 扉 20°→30° で +14.9 dB 跳ぶ | 円盤標本の 1/N 粒度（32点中3点が抜けた） |
| 柱の陰へ 0.1m 入ると直接音が −27.6 dB | 同上（全標本が塞がれた瞬間に材質の透過だけが残る） |

**新しい機能を足すときは「この値が連続に動くか」を最初に確かめること。**

### 幾何と波動の役割分担

| 現象 | 手法 | 理由 |
|---|---|---|
| 遮蔽・透過 | 質量則 + ソフト遮蔽 | 壁のこもりは材質で決まる |
| 回折（回り込み） | 前川の式（δ の単調関数） | 稜線が乗り換わってもゲインが飛ばない |
| 開口の開き具合 | フレネル帯の開口積分 | 波長対開口幅が音色に出る＝コンセプトの核心 |
| 早期反射 | 像源法（レイ） | 方向と遅延が要る |
| 後期残響 | エコグラム → IR 畳み込み | 形は実測、量は物理式 |

UTD は**採用しない**（厳密解だが影境界で不連続。最良 3.8 dB / 最悪 17.6 dB の段差を実測）。

### DSP 経路が 2 本ある理由

`VoiceConvolver`（C++）と `IrConvolver`（C#）は**同じ設計を 2 回実装したもの**で、
A/B して差が出たらどちらかにバグがある、という相互検証に使う。
実際この方法で 5 箇所の食い違いが見つかった（後述）。

**同時に有効にすると二重に鳴る。** `OnEnable` で相手を降ろすようにしてあるが、
切り替えは Y キー（`SetDspPath`）で行うこと。

## 3. 1フレームの流れ

`AF_SceneUpdate(scene, dt)` を毎フレーム 1 回。中で段ごとに実行間隔が違う。

| 段 | 既定の間隔 | 位相 | 内容 |
|---|---|---|---|
| エッジカタログ | 3 | 4,7,10… | リスナー中心のシルエット稜線抽出 |
| 役割1（遮蔽・回折・透過・方向） | 1 | 毎回 | 音源ごと |
| 早期反射 | 3 | 3,6,9… | 音源ごと・像源法 |
| 回折二次音源 | 2 | 2,4,6… | 音源ごと |
| エコグラム | 4 | 5,9,13… | **音源ごと**（レイはリスナーから 1 回で共有） |

**位相はずらしてある。** 全部 1 から始めると重い段が同じフレームに揃い、最悪値を作る。
初回だけ全段を走らせる（ホストが 1 フレーム目に空を掴まない契約。回帰テストで縛ってある）。
→ `Scene::phaseStages_()`

### 帯域

全部 6 帯域: **125 / 250 / 500 / 1k / 2k / 4k Hz**。
`kNumBands = 6`。スカラに潰さない。

**単位規約**: 透過・吸音は**エネルギー**、回折（前川）は**振幅**。
比べるときは必ず揃える（揃えずに 9 dB 過小評価した事故がある）。

## 4. 主要アルゴリズム

### 4.1 ソフト遮蔽（直接音）

音源まわりの円盤を 32 点サンプル（フィボナッチ配置＝決定的。乱数だとリスナーが動くとガタつく）。
各点の透過をエネルギー平均してから振幅へ。

- 見通し 1.0 → 境界 約0.5 → 影 材質の透過、と**連続**に落ちる
- 「見通せているか」の分岐が要らない

**★重要な限界**: 標本は二値なので、全部が塞がれると材質の透過だけが残る。
コンクリなら 1e-4 級まで落ちる（実測: 遮蔽率 0.91→0.97 で 0.250→0.0104、**1 歩 0.1m で −27.6 dB**）。
**これは単体では崖だが、回折タップ（F）が遮蔽率に比例して立ち上がるので合計は連続**
（実測: D⊕F の合計は 0.1m あたり 1.3 dB）。
→ **崖を見つけたら D 単体ではなく D⊕F の合計で確かめること。**

### 4.2 回折（中核）

前川の式。符号付き δ（影で正・境界で 0・照射側で負）だけの関数なので、
稜線が乗り換わってもゲインが飛ばない。

```
outGain[b] = max_i( maekawa帯域(δ_i) × openGain_i )
```

`openGain` は開口幅ゲート（**スカラ**）。

**★回折の帯域依存は既定で捨てる**（`AF_SceneSetDiffractionFlat`、既定 ON）。
方針は「回折が運ぶのは**開口の方向**と**回り込んだぶんの距離減衰**。
こもりは**透過と吸音**が担当」。

実測（0.6m 角の柱を直線上に 1 本、生存ゲイン 125Hz〜4kHz）:

| | 125 | 250 | 500 | 1k | 2k | 4k | 傾き |
|---|---|---|---|---|---|---|---|
| 柱なし | 1.000 | 1.000 | 1.000 | 1.000 | 1.000 | 1.000 | 0.0 dB |
| 柱あり（平坦化前） | 0.895 | 0.883 | 0.834 | 0.774 | 0.679 | 0.584 | −3.7 dB |
| 柱あり（平坦化後） | 0.833 | 0.833 | 0.805 | 0.778 | 0.725 | 0.674 | −1.8 dB |
| 柱あり・表面が吸わない | 0.892 | 0.892 | 0.892 | 0.892 | 0.892 | 0.892 | **0.0 dB** |

残る −1.8 dB は壁の吸音が反射の高域を食っているぶん（物理的に正しい）。

### 4.3 ポータルのフレネル帯域積分 ★潰してはいけない

ポータルがあるシーンでは、開口経由の音は**ポータルだけ**が決める（`portalOpenBands`）。
フレネル半径 `r1 = √(λ d1 d2/(d1+d2))` が波長に依るので、帯域ごとに開口率が変わる。

**これが「扉がどれだけ開いているか」を音色で伝える当のもの＝コンセプトそのもの。**
低域はフレネル帯が広いので狭い隙間でも通り、高域は狭いので塞がれやすい。

**★平坦化を `if/else` の外に置くとこれを潰す**（一度やって「定位感がない」と報告された）。
`diffractionFlat_` の適用は `diffractionContinuous` を呼ぶ `else` の中だけ。
回帰テストで縛ってある（「隙間が狭いほど低域が相対的に通る」「全開なら帯域差はほぼ無い」）。

### 4.4 部屋と開口（`room_graph.h`）★今回の主要追加

静的な形状をボクセル化して自由空間を塗り分ける。

```
1) 静的な形状をボクセル化（動くもの＝扉は除く）
2) 各ボクセルの「壁からの距離」を測る（3-4-5 チャンファ、2 走査）
3) 距離が侵食半径以上のボクセル（＝種）の連結成分 ＝ 部屋
4) 種でないボクセルを最寄りの部屋へ塗り戻す（戸口の中にも部屋が付く）
5) 別の部屋どうしが接している面 ＝ 開口
6) 部屋ごとに境界面積と吸音率を集めて Sabine の RT60
```

**侵食が要る理由**: 素の連結成分だと戸口で繋がった空間が全部ひとつの部屋になる（扉の向こうも同じ部屋）。
壁から半径ぶん内側だけを残すと、幅が半径の 2 倍に満たない**くびれ**が先に千切れる。

実測（切り替わりは「幅 = 半径 × 2」にぴたり乗る。格子 0.10m）:

```
戸口\半径   0.00   0.30   0.45   0.60   0.75   1.00
  0.0m        2      2      2      2      2      2
  0.3m        1      2      2      2      2      2
  0.6m        1      1      2      2      2      2
  0.9m        1      1      1      2      2      2
  1.2m        1      1      1      1      2      2
  2.0m        1      1      1      1      1      1
```

既定 0.6m ＝ 人が通る戸口（〜1.2m）は分かれ、開けた口（2m〜）は分かれない。

**戸口以外の形でも特別扱いなしに妥当な答えが出る**（実測、格子 0.10m）:

| 形 | 部屋 | 口 | |
|---|---|---|---|
| L字の曲がり角 幅2.0m / 1.0m | 1 | 0 | 曲がるだけで広さは変わらない＝境界でない |
| 大部屋に柱 1本 / 4本 | 1 | 0 | 回り込めるので境界でない |
| 腰高の仕切り 高さ1.2m | 1 | 0 | 上が開いているので境界でない |
| 廊下(6m)で繋いだ2部屋 幅0.9m | 2 | 1（3.2m²） | |
| 　　同 幅1.2 / 2.0 / 3.0m | 1 | 0 | 広い通路はひと続きの空間 |
| 食い違い壁 隙間1.0m | 2 | 1（3.2m²） | 見通しは切れるが繋がっている |
| **壁に窓 1.0×1.0m だけ** | 2 | 1（**1.0m²** ＝ 窓の実寸） | |

**扉の特別視が要らない理由**: どこで割れるかは幅だけで決まる。分類を持ち込むと必ず authoring になる。

**開口は吸音率 1 として部屋の吸音面に数える。** そこから出た音は戻らないので音響的には穴＝完全吸音。
部屋どうしの結合が「開口の面積」として自動的に効く（結合のために別の仕組みが要らない）。

**Sabine（空気吸収込み）**: `RT60 = 0.161 V / (A + 4mV)`。
4mV を落とすと高域だけ不自然に伸びる。

### 4.5 部屋を音に使う唯一の入口 ★

**部屋番号で切り替えてはいけない。** プレイヤーが必ず通る戸口のど真ん中に不連続を置くことになる。

```c
AF_SceneRoomWeights(scene, p, radius, outRooms, outWeights, maxOut)  // 割合（合計1）
AF_SceneRoomVolumeAt(scene, p, radius)                              // 割合で混ぜた体積
AF_SceneRt60At(scene, p, radius, out6, count)                       // 同、残響時間
```

半径 radius の球の中で各部屋が占める割合。**この半径が「何メートルかけて隣の響きへ入れ替わるか」そのもの。**

なめらかさを詰めた経緯（0.1m 進むごとの割合の最大変化、半径 1.0m）:

| | 変化 | |
|---|---|---|
| 半径あたり3点(7³)＋核 (1−d²)² | 0.345 | 核が尖りすぎて実質 7 標本しか効かず量子化 1/7 |
| 半径あたり6点(13³)＋核 (1−d²) | 0.162 | まだ面で飛ぶ |
| ＋標本位置をばらけさせる | **0.110** | 等間隔だと標本間隔とボクセル刻みが噛み合い一斉に境界を跨ぐ |

球の平均という方式の幾何的限界（3/(4r) → 0.075）にほぼ到達。コスト 1 回 12.3 µs。

### 4.6 早期反射・後期残響

- 早期反射: 像源法。タップは遅延を**小数**で持ち、更新時は「遅延がいちばん近い現タップ」と
  対応付けて補間（index で対応させると別の開口を繋いで遅延が掃引され「ヒュン」と鳴る）
- 後期残響: エコグラム（レイ）→ 帯域別の包絡 → 独立ノイズに掛けて IR 化 → 分割畳み込み
  - **L/R は独立ノイズ**（無相関＝尾が広がる）
  - IR は**エネルギー1に正規化**され、絶対レベルは `tailGain = 自由音場の直接 × √target`
  - `target` = 残響/直接のエネルギー比 `(r/rc)²`、`rc = 0.057√(V/RT60)`

**尾の絶対レベルの式（両 DSP 経路で共通）**:

```
尾 = 自由音場の直接レベル × √target × tailLevel × srcLevel
```

- **自由音場の直接**（`SourceTaps.FreeFieldDirect`）= 距離減衰 + 空気吸収のみ、**遮蔽を含まない**
- `srcLevel` = 反射込みの生存（音源が部屋にどれだけ注げているか）
- **`wet` を掛けてはいけない**（残響/直接比は √target で既に決まっている＝二重計上）

### 4.7 HRTF

KEMAR 実測（710 方向 / 139 タップ）。ITD は頭囲から。
クロスオーバー 700 Hz（それ以下は ITD が主な手がかり）。
**直接音タップだけに掛かる。** 尾は通らない。

## 5. 設計上の決めごと（守るべき）

1. **同じ問いに 2 つの答えを持たせない。** 片方が古くなって矛盾する
2. **連続量に二値の閾値を置かない。** 跨いだ瞬間に跳ぶ。重みへ写す
3. **実測は参照であって目標ではない。** 形は物理から採り、絶対値は演出で決める
4. **扉を特別視しない。** 一般の規則で書く（手続き生成でも効くように）
5. **回折が運ぶ情報は「どこから」と「どれだけ遠いか」。** こもりは透過と吸音が担当
6. **部屋は割合で使う。** 部屋番号で音を切り替えない
7. **数字で切り分ける。** 症状 → 実測 → 原因 → 対策 → 再実測。感覚で直さない
8. **D タップと F タップは合計で見る。** 片方だけ見て崖と判断しない

## 7. 未解決の課題（優先度順）

### 7.1 残響が直接音を潰していて定位が立たない ★体験上の最優先

デモシーン（`occluderMaterial = Concrete` が既定）で
**実効V 332m³ / RT60 4.47s / 臨界距離 0.49m**。
0.5m より遠ければ部屋のどこにいても残響優位で、直接音が 6% しか残らない。

**これはエンジンの欠陥ではなく、裸のコンクリ箱として物理的に正しい値。**
以前の RT60 0.50s（エコグラムの窓に縛られた誤り）が残響を過小に見せていたため、
物理が正確になった結果としてシーンの素材が非現実的だったことが露出した。

吸音率と臨界距離の関係（12×4×14m、V≒672m³、r=5m）:

| 素材 | α | RT60 | 臨界距離 | r=5m の比 |
|---|---|---|---|---|
| 裸のコンクリ | 0.02 | 9.06s | 0.47m | 115 → 10.7 |
| **塗装コンクリ（デモの現状）** | 0.04 | 4.63s | 0.65m | 58.9 → 7.7 |
| 石膏ボード（既定壁） | 0.15 | 1.26s | 1.25m | 16.0 → 4.0 |
| 内装あり（家具・カーテン） | 0.25 | 0.76s | 1.61m | 9.6 → 3.1 |
| よく吸う（布・吸音材） | 0.40 | 0.47s | 2.04m | 6.0 → 2.5 |

**手は 3 つ。どれも「絶対値は演出で決める」の範囲で、選ぶのは人間の判断:**
- シーンの吸音率を現実的にする（臨界距離 0.49 → 1.6m）
- 先行音効果の圧縮 `reverbRatioExponent`（既定 0.5）を強める
- `tailLevel`（既定 1.0）を下げる

### 7.2 尾のハードスワップ

尾の IR はブロック境界で**クロスフェードなしに差し替わる**。分割畳み込みは過去の入力ブロックを
保持しているので、差し替えると「もう出ている尾」が別の IR で畳み直される。

「中身が変わっていないのに差し替える」は版番号ガードで止めた（毎秒 7.5 回 → エコグラム更新時のみ）。
**変わったときの段差はそのまま。** 部屋を移る・扉が動く場面で出る。

### 測定した（`diagnoseTailSwapDiscontinuity`）

48kHz / 1 ブロック 512 サンプル（10.67ms）/ 尾 1.0s / 直接音を切って尾だけ / 種を変えて 8 回平均。
響く部屋（尾-直接比 30.7）→ 吸う部屋（同 5.77）へ差し替える。

| | ピーク | 到達 | ±0.5dB に収まるまで | サンプル間の跳び |
|---|---|---|---|---|
| 同じ内容で差し替え（対照） | 0.27 dB | — | 1 blk | 1.20 倍 |
| **響く部屋 → 吸う部屋** | **+1.97 dB** | **10 blk（107ms）** | **33 blk（352ms）** | 1.30 倍 |

**本来はほぼ動かないのが正解。** 尾 IR はエネルギー 1 に正規化されるので、
単独で暖機した定常 RMS は響く部屋 0.24386 / 吸う部屋 0.24156 ＝ **差 −0.08 dB** しかない。
実際には +1.97 dB ふくらむので、この 2 dB がまるごと差し替えの人工物。

分かったこと:

- **クリックではない。** サンプル間の跳びは 1.30 倍（対照 1.20 倍）で、対照とほぼ変わらない。
  症状は「パチッ」ではなく **残響量が約 2 dB ふくらんで 0.35 秒続く**
- **差し替え直後の 1 ブロックは丸ごと旧 IR のまま**（対照群と出力が完全一致する）。
  測るときに 1 ブロックしか見ないと「何も起きていない」と誤診する
- 過去の入力ブロックが新しい IR で畳み直されるため。吸う部屋の IR は同じエネルギーが
  短時間に集まっているので、直近の入力に当てると一時的に過剰になる

### 手の選び方（測定を受けて）── **並走クロスフェードを試して却下した**

並走クロスフェードを実装して測ったら**悪化した**。

| | ピーク |
|---|---|
| 単一の器で差し替え（現状） | **+0.27 dB**（対照） / +1.97 dB（部屋変更） |
| 200ms 並走クロスフェード | **−3.26 dB**（対照） / −1.81 dB（部屋変更） |

原因は、新しい畳み込み器の**周波数領域遅延線(FDL)が空**なこと。FDL には過去の入力ブロックが
溜まっていて、それが無いと尾を出し切れない。フェードイン中の新側が痩せているので混ぜると凹む。
対照ケース（中身が同じ）まで −3.26dB 悪化するので採用できない。

**正しい直し方は「古い器の FDL を新しい器へ引き継ぐ」。** FDL が持っているのは変換済みの
**入力**で IR とは無関係なので、そのまま移せば新側も最初から完全な尾を出せる。
ただし FDL はオーディオスレッド所有で setIr は制御スレッドなので、受け渡しの設計が要る。未対応。

土台（2 面の畳み込み器・役割入れ替え・等振幅の混合）は入れてあり、`Config::tailCrossfadeMs`
で有効化できる。**既定 0＝無効**。FDL の引き継ぎを実装したら既定を戻すこと。

※無効時に役割を入れ替えると FDL が空の器へ切り替わって尾が無音になる（実測 −227dB）。
　入れ替えはクロスフェード有効時だけに限ること。

### 旧: 手の選び方

- **スペクトル補間は今回の症状には効きにくい。** あれは位相＝クリック対策で、
  出ているのは 0.35 秒続く量のふくらみ
- **並走クロスフェードが素直。** 古い畳み込み器を自分の IR のまま自然減衰させ、
  新しい器を別に立ち上げて混ぜれば、過去の入力が新 IR で畳み直されること自体が起きない
- 窓は測定値から **0.1〜0.35 秒**が目安。その間だけ尾のコストが倍（0.205 → 0.41 ms/block）。
  本作の音源数（3〜5 本）なら許容できる見込み

> ⚠ この測定は `targetRatio` を固定して **IR の形の差し替えだけ**を見ている。
> 実際の部屋移動では `tailGain`（＝ `√target` × 自由音場の直接）も動く。
> そちらはホスト側で平滑されており、別の話。

### 7.3 音源ごとのエコグラム ─ 実装済み・**未検証**

「別の部屋の音源が同じ尾で鳴る」問題への対処。

実測（手前=響く部屋にリスナー、奥=吸う部屋、音源を 1 本ずつ置いて比較）:

| 置いた音源 | 総和 | 50ms | 100ms | 200ms | 300ms | 500ms |
|---|---|---|---|---|---|---|
| 手前(響く)だけ | 86.20 | −0.5 | −1.2 | −3.4 | −6.9 | **−29.4** |
| 奥(吸う)だけ | 8.53 | −0.6 | −1.1 | −3.0 | −5.2 | **−20.3** |
| 両方（旧実装） | 94.73 | −0.3 | −1.1 | −3.2 | −6.5 | −26.8 |

- 届く量は 10.0 dB 違う → **これは既に `tailSrcLevel` で音源ごとに効いていた**
- 減衰の形も 500ms で 9.0 dB 違う → こちらが共有 IR に潰されていた
- 両方置くと単純な和で、どちらの形でもない中間になる

`computeEchogramBands` の積算先を `[音源][ビン][帯域]` に変更済み。
`AF_SceneGetEchogramBands(scene, index, outBins, numBins)` に音源インデックスを追加
（`-1` で全音源の和＝従来値）。
**レイ追跡はリスナーから 1 回で共有なので計算は増えない。増えるのはメモリだけ**
（音源あたり 100ビン×6帯域×4B = 2.4 KB）。

**⚠ 未検証**: ビルド出力の DLL がロックされていて確認できていない。
ビルドが通ったら以下を確認すること:
- 回帰 202/202 と DSP 97/97 が維持されているか
- フレームコストが増えていないか（増えないはず）
- ホスト（`VoiceConvolver` / `IrConvolver`）は `GetEchogramBands` を音源ごとに呼ぶよう直す必要がある
  （現状は旧シグネチャのままなので **Unity 側は未対応**）

### 7.4 音源数の上限 36

per-source エコグラムにすると尾を音源ごとに畳むことになり、この上限が確定する。

**共有バス化は厳密に等価**（実測: 音源 6 本で最大の差 −119.6 dB）だが、
それは**「今の実装と」等価**という意味でしかなく、その今の実装が既に間違っていた。
形が 9 dB 違うものを 1 本に潰しているのを最適化して固定するところだった。

**正しい順番**: 音源ごと（または部屋ごと）のエコグラムを先に持つ → そのうえで**部屋ごとのバス**にする。
部屋は 1〜3 個しか同時に聞こえないので、バスもその数で済む。

### 7.5 最悪フレーム 20.4 ms（予算の 122%）

段の位相をずらして 26.5 → 20.4 ms にした。**これで段の衝突は支配項ではなくなった。**
残っているのは**エコグラム 1 回が 1 フレームに重すぎる**こと（切ると最悪 10.4 ms）。

レートを下げても 1 回のコストは同じで、追従が悪くなるだけ。
**エコグラム自体を分割する**（レイを N 分割して数フレームで積む）か、別スレッドへ。
結果は次の更新まで使われないので 1〜2 フレーム遅れても問題にならない。
20 コアあるのに 2 本しか使っていない。

### 7.6 その他

- **メッシュ壁**は跨ぎ判定が使えず従来のゲートのまま（幻・崖が残りうる）
- **0.03m 以下の隙間**は候補 0（稜線を面から 2cm 押し出す margin の分解能限界）
- 部屋グラフの**八分木化**が未着手。0.25m で 40×10×40m のレベルは約 102 万ボクセル
- `IrConvolver.cs` の退役（C++ 経路が本命になったので、A/B が済んだら消す）
- **デモの音源が商用曲**（Rokudenashi / TokyoGeto.wav）。配布前に差し替え必須。`*.wav` はコミットしない

## 8. 試して却下した案（再挑戦しないための記録）

| 案 | 結果 |
|---|---|
| 開口を「開口率最大のポータル」として評価（距離＋幅だけ） | **衝立で破綻**。幅の法則は「壁の穴」の量で、有限の遮蔽物には定義されない |
| 開口を複数点に散らして櫛形を埋める | **逆効果**。等間隔なので周期的なノッチが深くなる（−28.3 dB） |
| 稜線の可視割合を8点サンプルして重みにする | 経路長の跳び 2.65→2.44m しか改善せず、フレーム +15% |
| 掠めの許容を入射角で伸ばす（t/sinθ） | 固定値と**1点も変わらなかった** |
| 芯の面内の殻を margin まで締める | 厚い衝立を上から回り込む**正当な**経路が死ぬ |
| 跨ぎ判定の軸を「箱の最も薄い軸」にする | 立方体で軸が恣意的（3軸同値） |
| UTD の採用 | 影境界で不連続（最良 3.8 / 最悪 17.6 dB の段差） |
| **ソフト遮蔽に回折の床を足す**（`max(透過, 回折)`） | **二重計上で定位が壊れた**。D は音源方向・F は開口方向なので同じ音が別の場所から 2 つ出る。D 単体の崖は F が補うので合計は連続 |
| **尾の共有バス化を先にやる** | 順番が逆。音源ごとのエコグラムが先。間違いを高速化するところだった |

**幻の経路の教訓**: 正当な経路（厚い衝立の上）は縁から 0.11m 内側で中心面を横切るのに対し、
幻は 0.038m ── **幻の方が縁に近い**。距離・貫通量・位置のどの閾値でも分離できない。
違いは「縁の向こうが実際に開いているか」というトポロジだけだった。

## 11. ゲームに組み込むときの最低限

1. 静的な形状を `AF_SceneAddInstanceBox` / `AF_SceneAddInstanceMesh` で登録
2. 動くもの（扉）は `AF_SceneUpdateInstance` で毎フレーム更新
   → 自動的に「動くもの」と判定され、部屋の塗り分けから外れる（戸口が消えない）
3. 毎フレーム `AF_SceneSetListener` / `AF_SceneSetSource` → `AF_SceneUpdate`
4. 音源ごとに `AF_SceneGetSourceOcclusion` / `GetArrivalDir` / `GetEarlyReflections` /
   `GetDiffractionSources` を読み、タップを組んで `AF_VoiceSetTaps`
5. 残響は `AF_SceneRoomVolumeAt` / `AF_SceneRt60At` から `target` を作り、
   `AF_VoiceRebuildTail` へ

**部屋の設定の目安**:
- `RoomCellSize` 0.25m（戸口 0.9m がぎりぎり。細かくすると精度は上がるがコストも上がる）
- `RoomSeedRadius` 0.6m（人が通る戸口で分かれる）
- `roomBlendRadius` 2.0m（何メートルかけて隣の響きへ入れ替わるか）

**素材は現実的な吸音率にすること。** 裸のコンクリだと臨界距離が 0.5m を切り、
部屋のどこにいても残響優位で定位が立たない（7.1 参照）。
