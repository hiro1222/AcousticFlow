# 尾を「場合ごとに焼いてクロスフェード」で作る案の形（2026-09-09、設計だけ）

発注者の判断「IR はめっちゃ重いから、ケースに応じてクロスフェードする焼き付けのほうが
音的にも作りやすい」を受けて、**何が重いのか**を数字で分け、**焼くならこの形**というのを書きます。
実装はしていません。

## 何が重いのか（実測）

| 段 | 費用 | どこで |
|---|---|---|
| 尾の畳み込み（部屋ごとに 1 本のバス、1.0 s） | **0.294 ms / ブロック**（8 音源で個別 1.530 → バス 0.294） | オーディオスレッド |
| 1 音源の全部入り（直接＋早期＋HRTF＋尾） | 0.320 ms / ブロック ＝ 1 コアの **3.0%** | オーディオスレッド |
| 尾 IR の組み直し | 0.891 ms、133 ms に 1 回 | 制御スレッド |
| **エコグラムのレイ**（尾の材料を実行時に撃つ） | **2.9 ms / 周**（固定費。音源数で伸びない） | ワーカー |

**畳み込みは重くありません。**重いのは**尾の材料を実行時にレイで作っている所**です。
「IR は重い」の中身は、畳み込みではなく**IR の元を毎フレーム計算していること**です。

したがって「焼く」で消すべきは**レイ**で、畳み込みは残せます。畳み込みを FDN に替える理由は
費用の側からは出ません（形と即時性の話は `REVIEW_PROBE_BAKE_REPLY.md`）。

## 焼くならこの形 ── 波形ではなく包絡を焼く

**波形（IR そのもの）を場合ごとに焼いて線形に混ぜてはいけません。**別々に作った IR は
位相が揃っていないので、混ぜるとコムが立ち減衰が二重に聞こえます（発注者の案の文面にある
とおり）。回避は 2 つで、こちらは既に片方を持っています。

- ○ **包絡（6 帯域 × 時間ビン）を焼き、固定ノイズで波形にする。**今の `ReverbTailIr` が
  まさにこれ（`ノイズ(t) × √包絡(t)`、ノイズの種は固定）。2 つの包絡を混ぜても
  `n(t)·(w·eA + (1−w)·eB)` ＝ 包絡の補間そのもの。コムは立たない（同一 IR 再投入 −128.6 dB）。
- △ 場合ごとに固定の畳み込み器を置いて**送り量**をクロスフェードする。渡りの間だけ畳み込みが
  2 本になる。破綻しないが、上の方法があるなら要らない。

つまり**今の作りのうち「エコグラムを実行時にレイで作る」だけを「焼いた包絡を引く」に替える**
のが、いちばん小さい変更です。それより下流（包絡 → 固定ノイズ → 部屋ごとの畳み込みバス →
スペクトルの 2 世代混ぜ）は**そのまま**使えます。

## 場合の切り方

- **部屋 × 隣接する扉の状態**。部屋ごとに、その部屋に面した扉の開閉の組み合わせで焼く。
  扉が 2 枚なら 4 通り。遠い扉は要らない（結合は隣室越しの二次なので落とす）。
- 1 場合 ＝ 100 ビン × 6 帯域 ＝ 600 個の float ＝ 2.4 KB。30 場合でも 72 KB。
- 焼く時間: レイ 1 周 2.9 ms × 場合数。30 場合で 0.1 秒。起動時でも問題ない。

## 扉（連続量）はどう出すか

扉の角度 θ に対して、開口率 α（帯域別、`portalOpenBands`、既にある）で

```
包絡 = 閉の包絡 + α · ( 開の包絡 − 閉の包絡 )
```

「開」の焼きには隣室の遅い尾が入っているので、この式は
「自分の速い減衰 ＋ α × 隣室の遅い減衰」＝**連成残響の 2 指数の和**に近い形になります。
08-24 に却下したのは「開で焼いて、閉じるぶんを**引く**」（引く量が定義できない）で、
**2 つの焼きを α で混ぜる**のは別物です。こちらは成り立ちます。
検査: 08-24 の測定（扉を閉めると減衰 181 → 447 dB/s、量は 0.1 dB）が同じ向きに出ること。

## リスナーの位置

まず**部屋ごとに 1 つ**（位置に依らない）。08-24 の測定では部屋の中のばらつき 3.2 dB/s に対し
部屋をまたぐ差が 6.0 dB/s で、余裕は 2 倍。L 字や長い廊下で足りなければ、部屋の中に
プローブを数点置いて**包絡を**補間する（発注者の案のプローブ）。包絡の補間なので
固定ノイズの下では同じくコムが立たない。

## 作りやすさ（ここが本当の利点）

焼いた包絡は**そのまま編集できます**。帯域ごとの減衰カーブを見て詰められる。
あるいは包絡を生で触らせず、帯域別 RT60・初期減衰・量のつまみから包絡を**生成**する形にも
できる（Wwise 的な触り心地）。**どちらを authoring 面にするかは決めどころ**で、
作業の中身が変わります。

## 得る物と失う物

| | 今（実行時レイ） | 焼いた包絡 |
|---|---|---|
| ワーカーの固定費 | 2.9 ms/周 | **0** |
| 尾の追従 | 形 26〜54 ms、方向 250〜317 ms | 包絡の混ぜは**即時**（α は毎フレーム） |
| 扉 | 幾何から自動 | 扉ごとに 2 状態を焼き α で混ぜる（**扉をポータルとして登録する前提**） |
| 動く壁・崩れる床 | 自動で追う | **追わない**（焼き直し） |
| 形の精度 | その場の幾何 | 焼いた時の幾何。部屋の中は 1 つ |
| 作りやすさ | 材質とプリセットだけ | **包絡かつまみを直接触れる** |

失うのは「扉以外の動く物」への追従です。この作品は扉が主題なので、扉さえポータルとして
持てば失う物は小さい、が見立てです。`portal-is-precision-not-mechanism` の判定
（「プローブを部屋ごとの自動配置だけにしても音が出るか」）はここでも効きます。
**扉をポータルにするのは既に自動生成でやっているので、authoring は増えません。**

## 順番（やるなら）

1. 焼く口: `AF_SceneBakeTailEnvelope(room, doorStateMask)` — 今のエコグラム計算をそのまま
   1 周回して包絡を返す。実行時レイを止める切替 `tailSource`（0 ＝ 実行時・既定／1 ＝ 焼き）。
2. 実行時: 部屋 × 扉状態の包絡を α と `roomShare` で混ぜて `ReverbTailIr` へ。下流は無変更。
3. 検査: 連成（181 ↔ 447 dB/s の向き）／同一場合の再投入で −100 dB 以下／歩行の連続性。
4. authoring 面を決めて（包絡そのまま or つまみ生成）、Inspector と HUD。
5. 採用が固まったら実行時レイを消す（規約どおり）。

## 発注者の案: 「動かすことのできる Object にだけ設定しておく」（2026-09-09）

**これで決まりです。しかも印は既にあります。**

### 既にある物

- エンジン: インスタンスに `dynamicTag`（制作時の宣言）と `moved`（観測）の 2 つの印。
  `dynamicTag` は「音響的に動く物。焼く層に入れない」と定義済み（`scene.h` の Instance）。
- ホスト: `AcousticFlowSceneDemo.dynamicOccluders`（Transform の一覧）に加えて、
  **`SwingDoor` が付いた物と Rigidbody 付きは自動で動く物**になる（`BakeStaticFaces`）。
  つまり扉には**もう印が付いています**。authoring は増えません。

### 案がこの印に足す意味

いま `dynamicTag` が効くのは**面の見通しの焼き**だけです（外して実行時に生で解く）。
案は、同じ印を**尾の焼きの状態軸**にも使う、ということです。

```
静的な物          → 焼く（面の見通し・部屋グラフ・尾の包絡）。動かない前提
動く物（印あり）  → 面の見通しは実行時。尾は「状態ごと」に焼き、実行時に混ぜる
```

### 全部の動く物が状態軸になるわけではない

尾（残響）は部屋の**境界**で決まります。動く物のうち尾に効くのは、**開口を塞ぐ物**だけです。
Rigidbody の木箱は動く物ですが、部屋の吸音面積を数%変えるだけで、状態軸には要りません
（Sabine の A に対して無視できる）。

したがって規則は 1 行で書けます。

> **動く物 かつ 閉じた姿勢で部屋グラフの開口に重なる物 ＝ 尾の状態軸。**

これは幾何から自動で判定できます（閉じた姿勢の OBB が `Room::openArea` の面と交わるか）。
チェックボックスは要りません。扉は自動で状態軸に、木箱は自動で状態軸から外れます。
判定結果は HUD に出して、意図と違えば `dynamicOccluders` で上書きできる形にします。

### 直す所（小さい）

1. **部屋グラフが `dynamicTag` を見ていない。**`roomGraph()` は `moved` だけで外しているので、
   宣言された扉でも**一度も動く前**は静的な壁として戸口を塞ぎ、開口が幾何から消えます。
   `moved || dynamicTag` にそろえる（1 行）。
2. **焼く口。**`AF_SceneBakeTailEnvelope(room, stateMask)`。ホストが状態ごとに扉を
   閉じた姿勢／開いた姿勢に置いてから呼ぶ（`SwingDoor` は 0 度と `autoMaxDeg` を知っている）。
   エンジンは今のエコグラム計算を 1 周回して包絡（100 ビン × 6 帯域）を返すだけ。
3. **実行時。**部屋ごとに状態軸の扉 D 枚、焼きは 2^D 個。各扉の開口率 α_k（帯域別、
   `portalOpenBands`、既にある）で多重線形に混ぜる（D=1 なら `閉 + α·(開 − 閉)`）。
   混ぜた包絡を `ReverbTailIr` へ。下流は無変更。
4. **切り替え。**`tailSource`（0 ＝ 実行時レイ・既定／1 ＝ 焼き）。採用が固まったらレイを消す。

### 組み合わせの数

部屋に面した扉は普通 1〜3 枚。2^3 = 8 焼き × 2.4 KB × 部屋数。焼く時間は 1 焼き 2.9 ms。
100 焼きでも 0.3 秒。遠い扉（隣室の向こう）は状態軸に入れません（結合は二次）。

### 動いたのに印が無い物

`moved` が立った瞬間に面の見通しは焼き直す仕組みが既にあります（「タグを忘れても、動いた瞬間に
焼き直す」）。尾も同じで、印の無い物が動いたら**尾は追わない**（焼いた包絡のまま）。
直接・早期・回折は実行時なのでそちらは追います。HUD に「印の無い物が動いた」を出せば
制作時に気づけます。
