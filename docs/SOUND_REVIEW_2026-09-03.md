## 1. コードレビュー

### 1.1 良い所（壊さないこと）
- **決定性**。同じ入力で同じ数値が出る（回帰 335 件を 2 回回して完全一致）。走査・定点・キャッシュの全部がこれに乗っている。
- **コメントが設計ログ**。「試して却下」「実測でこう出た」「なぜこの定数か」が式の横にある。読めば判断の経緯が追える。消さない。
- **戻せる切り替え**。半影（`AF_SceneSetDirectPenumbra`）、外へ開く口（`AF_SceneSetOutsideApertures`）、扉の定点（ホスト `portalTail`）。聴き比べの土台。
- **回帰に「型紙」がある**。跳び・破れを機械が拾う（`[キャプチャ]`、`型紙1`）。歩行の走査もこの上に載せた。
- **C ABI で Core/Dsp がホスト非依存**。`render_wav.cpp` が Unity 無しでホストの面をほぼ使える。ミドルウェア化の土台はある。

### 1.2 構造のリスク（順に効く）
1. **`scene.h` が 6.8k 行の単体**。直接経路・回折・開口積分・部屋・エコグラム・診断が 1 クラス。読み手の負担と、ビルド時間。
   → 割るなら「面（開口積分）」「回折経路」「部屋・定点」「診断」の 4 つ。いまは割らない（聞き心地を先）。
2. **同じ問いに答えが複数ある所**（決めごと #1 の温床）。
   - 1 次回折の直線の窓 vs 2 次回折の起点からの測り（外開きの段の正体）。
   - `AF_SceneRoomWeights`（部屋どうし）と `AF_SceneRoomShareAt`（空間版）。後者は屋外境界用に意図して分けた。V/RT60 はまだ前者。
   - フレネルが使えない時の「隙間幅」の旧式（`slitWidthGain`）。前川・フレネル・隙間幅の 3 つ目の式。
   - 尾の比: ホストの `(r/r_c)²`（音源 0 の距離だけ）。
3. **診断が本体の中に住んでいる**。thread_local 26 本、`apDiag()` の印字、`AF_SceneDebug*` 5 本。動作には無害（静的 bool）だが、読み手には雑音。
4. **ホストと C++ の二重実装**。タップの組み立て（C# 121 行／C++ 60 行）、比の式、既定値（`echogramBounces` など）。既に 3 回ずれた記録がある。
5. **C API の増殖**（163 本）。診断口が本番口と同じ場所にある。版は構造体を変えた時だけ上げる約束（現在 5）。

### 1.4 ホスト側のリスク
- `TailBusRenderer` の辞書 `_buses` をオーディオスレッドから読む（既存）。定点はハンドルの写しを主スレッドで渡す形にして辞書を触らない。
- `PortalEmitter` は無音クリップの `AudioSource` が鳴っていないとフィルタが呼ばれない。入力は 1 ブロック前のバス出力。
- 形の index → 部屋番号は代表音源の位置で控える。音源の無い部屋には定点が出ない（尾も無いので正しいが、気づきにくい）。
- **DLL の配布は Unity が掴んでいると失敗する**（IOException）。今回それが起きて Plugins は 03:27 の版のまま。古い DLL でも鳴るように逃げ道を入れたが、Unity を閉じて `tools/dev.ps1 deploy` を要再実行。
- 主スレッドの計測 `音響計算` はエンジン更新から定点までの区間だけ。FPS は vSync（品質 Ultra で ON）と Editor とマシン負荷（Unreal Editor 19% など）で決まる。

## 2. 方針（確定事項の再掲と、次の手）

**前提**: 閉じた扉ごしの音（こもって、ぼんやり、左右上下がふんわり、隙間から高域だけ）。
**コンセプト**: 扉が開くときの音色の変化。どちら側から開くかで、どの音が先に届くかも変わる。
**ピラー**: S1 響きには向きがある／S2 形は空間から、絶対値は耳から／S3 正しさより連続性を先に守る。
道具: T1 立っている場所で調整／T2 即座に聞き比べ／T3 複数人でリアルタイム共有。T4（機械が破れを拾う）はミドルウェアの必須機能。

**決まっている設計**
- 焼いたうえで変化に合わせて変調する。壁の破壊は切る。扉は角度軸で焼く。置物は実行時＋更新エリア（物体が申告、部屋グラフで「するか」、境界で「どこを」）。
- 定点は**音源非依存**（部屋の中心＝響きの形と向き、扉＝隣室の響きが口を通る量）。音源依存の量は全部実行時。
- IR は残す。ただし形だけ。量・向き・扉を通る分は定点の数値で IR の外。差し替えは刻みが変わった時と出来事の時だけ。
- 補間はパラメータで、波形は混ぜない。周期 3 段（毎フレーム: 扉の角度と直接経路／5 フレーム: 定点の混ぜ重みと目標値／出来事: 申告範囲の再計算）。
- 音源ごとの固有化は残す。ネックはダーティーフラグで（依存は音源位置・リスナー位置・経路の管に入った物体）。
- 尾の量を遮られた直接音から作らない（既に一度踏んだ）。
- 波動ソルバは実行時に入れない。入れるなら低域の校正の参照として一度だけ。
- 順番: **システムの聞き心地を先**、前へ引き出すのは最小の実時間ホストだけ、その後ミドルウェア本体（出荷物、併用可）。

**聞き心地の段階（現在地）**
1. 外開き → 保留（2 回折れ。ゲーム側の扉の向き待ち）
2. 扉の定点 → **部品とホスト配線まで入れた（既定 OFF）。Unity で未試聴**
3. IR 差し替えの人工物 → 未着手（遅延線の引き継ぎ）
4. 更新周期と補間（段に周期を紐づけ、帯域ゲインを毎フレーム寄せる）→ 未着手
5. ゲームの通し場面で絶対値を決める → ゲームレーンが音を戻す段階

**次の 3 手（提案）**
- (a) 深い影の半影の標本（1.3 の #2）。外から近づく跳びの大半。標本を外の 2 環に足すか、通る標本が少ない時は開口積分に寄せる。
- (b) `Test_PlacedObject`。AcousticSurface 付きの箱を左ドラッグで動かし、材質を切り替える場面。置物で「直接・回折・早期反射は変わり、尾は変わらない」を耳で確かめる。
- (c) IR 差し替え: 当面は差し替えの閾値を上げ、根本は定点（部屋の IR）。
並行: 外開きの返事、V/RT60 を空間版へ（確認してから）、`echogramBounces` と `roomSeedRadius` の既定見直し（確認してから）。

**判断基準（変えない）**: 同じ問いに 2 つの答えを持たせない／絶対値は耳、形は空間／連続性を正しさより先に／模型の差し替えは戻せる形で／実測は参照であって目標ではない／締め切りを理由に機能を削らない。
