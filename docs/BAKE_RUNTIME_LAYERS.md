# 3 層構造 ── 焼くのは構造、状況は実行時、結ぶのは係数（2026-09-03 決定）

## 問い
デザイナが作れて調整できる形（制作時に焼く）にすると、扉の開閉や動く物のような「状況に寄った翳」が落ちる。どうするか。

## 答え
焼いた**答え**を再生するのではなく、焼いた**構造**から実行時に答えを出す。役割を 3 層に固定する。

| 層 | 持つ物 | 誰が触るか | 更新 |
|---|---|---|---|
| 焼く層（構造） | 部屋グラフ・開口・部屋ごとの尾の形と量・探針・静的な面のリストとセルごとの見通し・材質 | デザイナ（値ではなく構造と規則） | 制作時。編集で dirty な部屋だけ焼き直し |
| 実行時の層（状況） | 音源ごとの直接経路（透過・回折・半影）・扉のセンサー（口の結合率）・動いた物の遮蔽・動いた物の面 | エンジン | 毎フレーム（役割ごとの間隔と段で上限） |
| 結ぶ層（係数） | 尾 = 焼いた形 × 結合率 × 生存、方向 = 探針 ⇄ 定点の割合 w、早期 = 焼いた見通し × 動いた物の遮蔽 × 今の位置と重み | 規則 | dirty flag で局所的に |

デザイナに渡すつまみは「値」ではなく「構造と規則」: 材質プリセット、ポータルの手置き・上書き、部屋ごとの演出ゲイン、扉の開度→結合率のカーブ、半影の幅、音源の重要度、探針の密度、演出ボリューム（この範囲は物理より乾かす、など）。

## 焼くだけでは落ちる物と、その受け皿
| 落ちる物 | 受け皿 |
|---|---|
| 扉の開閉で変わる響き | 口の結合率（実行時） |
| 動く物・キャラの遮蔽 | 音源ごとの直接経路、動いた物の遮蔽（`dynamicBlock`）、柔らかい遮蔽（未実装） |
| 音源が動く | 音源ごとの経路（探針は音源非依存なので焼いたまま） |
| リスナーが部屋の中で動く | 探針の補間（焼き）＋部屋の占め方（実行時） |
| 置物を後から置く | 面の線が拾う（1 m² 以上）。尾は焼き直し |

「音響的に動く物」はタグで決める（`AF_SceneSetInstanceDynamic`、ホストは SwingDoor・Rigidbody・`dynamicOccluders` から自動）。タグを忘れても、静的として焼いた物が動いた瞬間に焼きが stale になり、次の更新でその物を除いて焼き直す（1 回だけ重い。箱部屋で 3 ms）。

## 第 1 段（同日実装）: 面の見通しの焼き
`Scene::bakeStaticFaces(cellSize, K)`（scene.h）。部屋グラフの格子を 1 m に粗くしたセルごとに、静的な面の中心線 K 点への見通し（円盤 9 標本の透過エネルギー、6 帯域）を焼く。セルは部屋の中だけ。実行時は 8 セルの三線形補間 × 動いた物の遮蔽（`dynamicBlockDisc`）。

**規則: 焼くのは部屋の中の見通しだけ。口をまたぐ脚は実行時に生で解く。** 1 m のセルでは戸口（幅 1 m）越しの見通しを補間で暈かしてしまい、扉を開けた後の隣室の面が生より 3.8 dB 小さくなった（回帰 [焼き] 8c）。口の向こうは扉が決めるので、ポータルと同じく実行時の層に置く。面には表側の部屋番号を持たせ、リスナー（音源）が同じ部屋のときだけ焼きを使う。

### 数字（scene_regression `[焼き]`、2026-09-03）
| 検査 | 結果 |
|---|---|
| 箱部屋 8×3×6 を 1 m セルで焼く | 129 セル / 面 6（裏・側面を落として 28 → 6）/ 3 ms |
| 焼き vs 生（同じ部屋） | 14.55 / 14.55 dB |
| 静的な柱の遮蔽（吸い切る材質） | 柱なし 14.55 → 柱あり 生 13.83 / 焼き 13.8 |
| 閉扉で焼く（扉はタグ） | 生 8.78 / 焼き 8.78 dB |
| 焼いた後に扉を 90° へ | 14.68 / 生 14.68 dB |
| タグ無しで焼いた扉が動く → 焼き直し | 14.66 / 生 14.68 dB（面 10） |
| 面の線だけの費用（同じ部屋、箱 7 個、音源 1） | 生 108 µs → 焼き 38 µs |

扉をまたぐ配置では脚が生に落ちるので費用は変わらない（1369 vs 1372 µs、役割1 込み）。焼きが効くのは「自分の部屋の壁」で、それが面の大半。

## 壊れる所・限界
- 焼いた見通しは面の**中心線**の値。実行時の線は鏡面点の高さを通るので、床のように短軸が長い面では位置がずれる（何が遮るかは面の上でゆっくりしか変わらない、という近似）。
- セルの外（部屋の外・実体の中）は焼かない → 生。屋外は全部生。
- 静的な物を焼いた後に足す／消すと、その物は焼きから外れて生（遮蔽としても面としても）。焼き直しは編集時の仕事。
- 焼きはまだメモリの中だけ（ファイルに書き出す口は次）。

## 外の作り手のための口（同日、GPU 化の下ごしらえ）
GPU 化は焼く物が増えてから 1 回で入れる。その前に、DLL の外で同じ木を走査し、同じ入れ物へ結果を戻せる口だけ足した。
- `AF_SceneBvhNodeCount / AF_SceneBvhOrderCount / AF_SceneExportBvh`: インスタンスの BVH を平らな配列で書き出す（節 = AABB / leftFirst / count。count > 0 が葉で order[] のインスタンス添字を指す）。走査の規則は `computeTransmission` と同じ。メッシュの三角形はまだ出さない。
- `AF_SceneGetInstance`: OBB・材質・geomId・active / moved / dynamicTag。
- `AF_SceneFaceBakeBytes / Export / Import`: 面の焼きをバイト列で出し入れ（版 1: ヘッダ → 面 → inBake → cellValid → vis）。実体の並び（数）が焼いたときと違えば受け取らない。
- ホスト `bakeFile`（StreamingAssets 相対）: あれば読んで焼きを飛ばす、無ければ焼いてエディタでだけ書き出す。これが「制作時に焼く」の最小形。

検査 `[口]`: 箱部屋の BVH が節 7 / 葉の和 6 = 実体 6、焼きを出して消して入れ直すとタップがビット一致で戻る（182,158 バイト。格子の外のセルも含むので、詰めれば半分）、大きさの合わない物は拒否。372/372。

GPU に渡す規則（決定）: **焼く側と周期の長い役割（面の焼き、探針・後期の方向の焼き、エコグラム）は GPU に出してよい。毎フレーム応答する役割（直接経路・扉・面の線の実行時）は CPU。** 主スレッドで GPU に出せるのはエコグラムの 1.2 ms（複数コアなら 0.3 ms）だけで、いま入れる理由は数字に無い。効くのは焼く側（街の規模で秒 → ms）。
