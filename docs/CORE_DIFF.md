# 新コア（Flow）と旧コア（Scene）の違い ── 段 10 の前の突き合わせ

2026-09-10。旧コアを消す前に「新コアでも数字で確かめられるか」を作り、その上で違いを洗い出した記録。

## 測り方

同じ場面・同じ信号・同じ長さを両コアで鳴らして、出た WAV を同じ解析にかける。

```
AfRenderWav <出力>            旧コア（AF_Scene）
AfFlowWav   <出力> [音源x]    新コア（AF_World）  ← 今回追加
AfAnalyzeWav <WAV>            どちらも同じ物差しで読む
```

場面は密閉した 2 部屋を幅 1.2 m の戸口で繋ぎ、蝶番 x=−0.6 の扉を 0°→90°→0° と 12 秒で振る。
リスナー (0,1.6,−4)、音源 (−2,1.6,3.5)。信号はピンク寄りの雑音で、種と式まで揃えてある。

`AfFlowWav` の摘み（環境変数）:

| 変数 | 既定 | 何を変えるか |
|---|---|---|
| `AF_ROOM_CELL` | 0.25 | 部屋グラフのボクセル一辺(m) |
| `AF_DOOR_HALF` | 0.6 | 戸口の半幅(m)。部屋が割れる境目を測る |
| `AF_WEIGHTS` | 全部 1 | 五成分の重み `直接,初期,後期,回折,透過` |
| `AF_NO_BUS` | 未設定 | 方向バスを外す（尾と初期が直に L/R へ出る） |
| `AF_DOOR_DEG` | 未設定 | 扉の角度を固定する |
| `AF_LISTEN_SWEEP` | 未設定 | 耳を x=−3→+3 へ振る（位置での入り切りを測る） |
| `AF_LEAK` | 0 | 漏れの模型 0/1/2/3 |
| `AF_SRC_R` | 0.2 | 音源の幅(m)。**開き始めの角度の緩衝**はここで決まる |

## 鳴らして出た数字

窓 100 ms、立ち上がりと終わりを外した 0.5〜11.5 秒。

| | 閉→開のふり幅 | 色の傾き（125 Hz − 4 kHz） | 広がり IACC 15°／90°（小さいほど広い） |
|---|---|---|---|
| 旧コア | 18.9 dB | 5.4 dB | 0.403 ／ 0.284 |
| 新コア | 21.8 dB | 18.7 dB | 0.833 ／ 0.825 |
| 新コア（後期を止めて） | 8.1 dB | 4.4 dB | — |
| 新コア（方向バスを外して） | 25.7 dB | 14.4 dB | 0.165 ／ 0.115 |
| 新コア 初期だけ | — | — | 0.135 ／ 0.075 |
| 新コア 後期だけ | — | — | 0.860 ／ 0.842 |
| 新コア 後期だけ・バスなし | — | — | 0.154 ／ 0.126 |

- **ふり幅は新コアの方が 2.9 dB 広い。**扉の効きはコンセプトの中心なので、ここは新コアが有利。
  止めると 8.1 dB に落ちるので、扉のふり幅は**尾が運んでいる**。
- **色は新コアが 13.3 dB 低域寄り。原因は尾。**止めると 4.4 dB まで下がり、旧コアの 5.4 dB とほぼ並ぶ。
  方向バスも 4 dB ぶん低域へ寄せている（18.7 → 14.4）。
  どちらが正しいかは実測の当てが無いので**耳で決める**。
- **広がりは初期反射がちゃんと出している**（IACC 0.135／0.075 ＝ かなり広い）。
  狭いのは尾で、しかも FDN 自体ではなく**方向バスに載せた所**で潰れている
  （後期だけ: バスあり 0.860 → バスなし 0.154）。バスを外した新コアは旧コアより広い。

⚠ 2026-09-10 訂正: 最初にここへ「後期を止めても傾きは変わらないので原因はタップ側」と書いたが誤り。
   摘みを足したときの置換が壊れて `AF_WorldBuild` ごとコメントの中に入り、部屋 0 個のまま鳴っていた。
   直して測り直した結果が上の表。

## 仕組みの違い

| | 旧コア（Scene） | 新コア（Flow） |
|---|---|---|
| C API の関数 | 160 | 36 |
| 幾何 | 箱＋メッシュ（BVH、面の焼き） | **箱だけ** |
| 部屋 | 自動分割＋**ポータルを宣言できる**（`AF_SceneAddPortal`） | 自動分割のみ。宣言する入口が無い |
| 直接音 | ソフト遮蔽（帯域別の透過率） | 円盤の見通しの割合（走査線＋二分探索＋erf） |
| 回折 | 前川／UTD／Kirchhoff／BTM の 4 模型＋稜線カタログ | 前川＋フレネル隙間の 1 本 |
| 早期反射 | 面の線音源（`earlyModel=1`）／旧の像源レイ（0） | 虚像 ISM（方向と正規化重みだけ）＋方向なしの残り |
| 後期 | エコグラム畳み込み／FDN の 2 本立て（`tailModel` で A/B） | FDN だけ |
| タップの組み立て | DLL 内（`tap_builder`）。ホストが写す | `AF_WorldApplyVoice` が全部やる |
| 録音（capture） | 録る・読む・走査・回帰生成・ABI 経路まで一式 | **無い** |
| 焼き | 面の見通しの焼き（export/import） | **無い** |
| 検査 | 441 件 | 120 件 |

作りのいちばん大きな違いは**ホストの仕事の量**。旧コアは `render_wav.cpp` が 170 行かけてタップを
組んでいたが、新コアは `AF_WorldApplyVoice` の 1 行で済む。`render_wav_flow.cpp` が短いのはそのため。

## 見つかった不具合

### ① 幅 1.2 m の戸口では部屋が割れない

0.25 m 格子で戸口の幅を変えて測った。

| 戸口の幅 | 部屋 | 戸口（Aperture） |
|---|---|---|
| 1.2 m | **1** | **0 個** |
| 1.0 m | 2 | 3 個 |
| 0.8 m | 2 | 3 個 |
| 0.6 m | 2 | 1 個 |

部屋グラフは「くびれ」でしか割らないので、幅 1.2 m は太すぎて 1 部屋になる。
そうなると戸口が 0 個になり、**扉で響きを変える仕組み（`applyOpenings`）がまるごと効かない**。
格子を 0.15 m に細かくしても割れないので、格子の粗さではなく閾値の問題。

旧コアはここをホストが `AF_SceneAddPortal` で宣言していたので起きなかった。
新コアには宣言する入口が無い。**決めること: 戸口を宣言できるようにするか、閾値を見直すか。**

### ② 音源が戸口から外れていると、扉を開けるほど回折が消える

音源 x=−2（戸口の正面から 2 m 外れ）で、45° 以上で回折が 0 になる。

| 角度 | 回折 | 箱/稜線 | 隙間 a | 重み |
|---|---|---|---|---|
| 0° | −44.6 dB | 0/7 | 0.151 | 0.19 |
| 15° | −45.0 dB | 0/7 | 0.137 | 0.19 |
| 30° | −48.5 dB | 0/7 | 0.111 | 0.10 |
| 45°〜90° | **無し** | −1/−1 | − | **0.00** |

原因は候補の取り方。回折の候補は**音源の円盤に影を落とした箱**からしか取らない（段 6 の決定）。
この場面で影を落とすのは左の仕切り（箱 0）だけで、その稜線は蝶番と同じ x=−0.6 にある。
扉が開くとその稜線のすぐ脇に板が立つので脚が潰され、重みが 0 に落ちて候補が空になる。
**右の戸口枠（x=+0.6）は音源に影を落とさないので、最初から候補に入っていない。**

旧コアは同じ場面で 0°〜90° を通して回折を 1 本保ち、到達エネルギーが 0.0074 → 0.40 と単調に増えた。

音源が戸口に正対しているとき（x=0）は新コアも正しく動く。見通しが 0 → 0.26 → 1.00 と開き、
回折は −35.8 → −27.6 と増えてから、見通しが 1 になった所で 0 になる（設計どおり）。

**決めること: 候補を「影を落とした箱」だけでなく、直線が壁を横切った所の近くの箱まで広げるか。**

### ③ 閉じた扉が「隙間から漏れる」音を出すが、位置で入り切りする

扉を 0° に固定し、リスナーを x=−3 → +3 へ動かして測った（音源 x=−2、z=3.5）。

| 耳の x | 回折 | 隙間 a | 重み |
|---|---|---|---|
| −3.0 〜 −1.5 | **無し** | − | 0.00 |
| −1.0 | −48.0 dB | 0.151 | 0.19 |
| 0.0 | −44.6 dB | 0.151 | 0.19 |
| +1.0 | −42.3 dB | 0.151 | 0.12 |
| +1.5 〜 +2.5 | **無し** | − | 0.00 |

同じ場面の後期は −41 dB なので、この漏れは部屋の響きと同じくらいの大きさ。
それが幅 2.5 m ほどの窓の中でだけ鳴り、縁ではフェードせず**切れる**。

さらに、扉は閉まっているのに隙間の幅が 0.151 m と出ている。回折点を稜線から押し出した位置と
板との距離を測っているだけで、実際の隙間ではない。**この漏れは物理ではなく作り物。**

**原因**（2026-09-10 特定）: 隙間の幅ではなく**脚の重みの式**だった。
`diffraction.h` は「壁を本当に通る脚は 0.2 m 以上貫くので落ちる」という前提で許容を 7 cm に置いている。
ところが**扉の板は厚み 6 cm しかない**ので、板の面を真っ直ぐ通る脚でも貫通が 6 cm で止まり、
許容の中に収まって重み 0.19 が残る。閉じた扉から回折が漏れていた正体はこれ。

**入れた物**（試聴で A/B するための切り替え。既定は 0 ＝ 今まで）:

| `leakModel` | 何をするか |
|---|---|
| 0 | 今のまま。基準点 |
| 1 | 案A。貫通を**その箱自身の薄さ**に対する割合で測る。半分までは掠め、厚みぶんで通過＝0 |
| 2 | 案B。回折の量に戸口の空き具合（`openFrac`）を掛ける。戸口が要る |
| 3 | 両方 |

`AF_WorldSetLeakModel` で置く。Unity は `AcousticWorld` の `leakModel` を実行中に動かせる。
どちらも角度に二値を置いていない。1 は経路の幾何、2 は口の帳簿なので、効く場面が違う。

**★重要な見落とし**（同日、測っている途中で判明）: Unity の `SwingDoor` は板を枠より
**4 mm 小さく**作っている（自由端と上下だけ、蝶番側は密着）。「隙間から高域だけが漏れる」を
形として持たせるためで、作品の前提そのもの。ところが検査の `doorLeaf` はそれを持っておらず、
**隙間 0 の板**で測っていた。`clearance` を足して測り直した結果が下。

**結果**（回帰の 2 部屋、扉を閉じたまま耳を 25 か所へ。回折が板の透過を上回った所 / 最大の比）:

| 模型 | 隙間 0 mm | 隙間 4 mm（Unity と同じ） | 隙間 10 mm |
|---|---|---|---|
| 0 旧 | 18/25 +11.6 dB | 18/25 +11.6 dB | 18/25 +11.6 dB |
| 1 案A | 0/25 無し | 0/25 **無し** | 0/25 **無し** |
| 2 案B | 0/25 無し | 0/25 −10.2 dB | 0/25 −6.2 dB |
| 3 両方 | 0/25 無し | 0/25 無し | 0/25 無し |

- 模型 0 の漏れは**実際の隙間の大きさと無関係に一定**。作り物であることが確定した。
- **案A は本物の 4 mm の隙間まで消す。**寄せすぎなので既定にしない。
- **案B だけが隙間の大きさに比例した漏れを残す。**

⚠ **訂正（同日、試聴で判明）: 上の「案B だけが本物の隙間を残す」は誤り。**
中を見ると、閉扉で立っていた候補は箱 7（枠）の稜線で `a=0.201 / w=0.19` ＝ **板を厚みぶん貫く経路**だった。
枠との 4 mm の隙間は経路として最初から見つかっていない。案B が残していたのは
「本物の隙間の漏れ」ではなく、**作り物の漏れを 22 dB 下げた物**。案A が消したのは実在しない経路だけ。

さらに案B は半開きの**正しい回折まで下げる**。戸口の方向を運んでいるのは回折タップなので、
試聴で「扉に対しての方向性がだいぶ消えた」と出た。回折の取り分（総量に対する割合）:

| 角度 | 模型 0 | 模型 2 | 落ち幅 |
|---|---|---|---|
| 10° | 19.1% | 0.23% | −19.1 dB |
| 20° | 18.9% | 1.15% | −12.1 dB |
| 30° | 5.8% | 0.73% | −9.0 dB |
| 60° | 5.2% | 2.52% | −3.1 dB |

**決定（2026-09-10、訂正後）: 既定は案A（`leakModel = 1`）。**
閉じている間だけ効き、10°〜90° は模型 0 と 1 ビット違わない（実測で確認）。
戸口の方向は元のまま残る。

**残る宿題**: 枠との 4 mm の隙間を通る経路は、どの模型でも作られていない。
閉扉で「隙間から高域だけが漏れる」を出したいなら、それは別の機能として足す必要がある。

（以下は訂正前の記録）
**決定（2026-09-10）: 既定を案B（`leakModel = 2`）にした。**
扉の開き方は変わらない。閉 → 全開の総量は模型 0 も 2 も **+22.9 dB** で同じ、
途中の差は最大 0.9 dB（10〜20°）、70° 以降は完全に一致する。
変わるのは閉じかけの回折だけで、そこがまさに作り物だった所。

戸口が見つからない場面（不具合 ① の 1.2 m の戸口など）では案B は何もしない。
そこは「密閉の旗」をホストから渡す案が残っている。順番は耳で確かめてから。

### ④ 隣の部屋にいても、尾が全方向から来る（戸口の向きが無い）

2026-09-11、試聴の指摘「同じ部屋にいるときは LEV でいいが、隣の部屋では扉からの指向性のほうが強いはず」から。

**仕組み**: 後期は音源がどの部屋にいても、丸ごと「リスナーの部屋の FDN」1 本へ送る（`distribute.h` の送り）。
FDN の部屋は作った時点で 8 レーンに一様で、新コアは `FdnRoomMix::setListenerDirection` を一度も呼ばない。
旧コアは `scene.h` の `fdnRoomWeights` で、隣室の尾に戸口の向きと口の立体角ぶんの広がりを付けていた。作り直しで移っていない。

**耳に届く内訳**（`AF_ONLY=doorside`、耳は隣の部屋 z=−3、音源 z=+3、戸口 1.0 m。Unity の Flow_SwingDoor と同じ寸法）:

| 耳の x | 扉 0°: 方向あり / なし / 尾 | 扉 90°: 方向あり / なし / 尾 |
|---|---|---|
| −3.0 | 7.9 / 26.4 / 65.7% | 0.8 / 2.8 / 96.4% |
| 0.0 | 28.6 / 31.4 / 39.9% | 29.7 / 10.3 / 60.0% |
| +3.0 | 7.5 / 25.3 / 67.2% | 2.3 / 4.0 / 93.8% |

扉を開けるほど「向きの無い尾」の割合が増える ＝ **開けるほど両耳から均等に鳴る側へ寄る**。

**本来どれだけが戸口の向きから来るか**（`AF_ONLY=lateorigin`、レイ 8192 本。
後期の NEE の寄与を「放射した面が耳と同じ部屋に面しているか」で分けた。面の点は耳の側へ 0.3 m 押して部屋を引く）:

| 扉 | 耳 | 同じ部屋の面 | 戸口越しの面 | 戸口越しの集まり R | 戸口の中心とのずれ | 同じ部屋の R |
|---|---|---|---|---|---|---|
| 90° | (−3, −3) 隣 | 90.6% | 6.3% | 0.975 | 0.9° | 0.199 |
| 90° | (0, −3) 隣 | 80.6% | 16.8% | 0.972 | 0.8° | 0.058 |
| 90° | (+3, −3) 隣 | 92.1% | 4.8% | 0.975 | 1.1° | 0.204 |
| 90° | (0, −1) 隣 | 54.4% | 42.3% | 0.888 | 4.8° | 0.041 |
| 90° | (0, +1.5) 同 | 93.4% | 2.3% | 0.874 | 2.0° | 0.137 |
| 0° | (0, −3) 隣 | 80.2% | 11.7% | 0.918 | 0.6° | 0.121 |

（R は 1 で一点から、0 で全方向から。残りは部屋を引けなかった面で、90° で 2.5〜4.3%、0° で 6.3〜9.8%）

読み取り:
- 戸口越しの分は**ほぼ一点に集まり（R 0.97）、戸口の中心から 1〜2° 以内**から来る。今はこれが全方向に散っている。**ここが壊れている所。**
- ただし隣の部屋の後期の**大半は隣の部屋自身の響き**（戸口から入った音で励起された拡散音場、R 0.06〜0.20）。
  戸口から 3 m では戸口越しは 5〜17%、1 m まで寄ると 42%。
  「隣の部屋では後期も扉の向きが勝つ」は、この材質（吸音 0.2）では**戸口のそばでだけ**成り立つ。
- 同じ部屋では戸口越しは 2.3% で、LEV のままでよいことも確かめられた。

**直し方の案**（→ 下の「決定」で案1）:
- 案1（推す）: レイで分ける。後期の NEE を放射した面の部屋で分け、戸口越しの分は向き（エネルギー重みの平均）と R を持って
  **音源の部屋の FDN** へ送り、その部屋の FDN を「戸口の向き・広がり 1 − R」で聞く。自室の分は今どおりリスナーの部屋の FDN を一様で。
  戸口越しの分が向こうの部屋の RT60 で減衰するのも物理どおりになる。
  GPU には部屋の格子を送り、当たり点ごとに引く。部屋が割れない場面（①）では今と同じ動き（悪くも良くもならない）。
- 案2: 旧コアの式（戸口の立体角 × α²、向きは戸口の中心）を移す。軽いが戸口が要る。
  式の作りでは音源と耳が戸口から同じ距離のとき自室と隣室が半々になり、3 m ではレイ（17%）の約 3 倍に見積もる（式から読んだ見積もり）。
- どちらでも確かめる所: 扉が戸口の中にある角度では板の面の部屋が引けない（上の「不明」）。
  不明をどちらへ入れるかで開き始めに段が出うるので、扉の掃引（`clicks` / `doorsweep`）で測る。

**決定（2026-09-11）: 案1 を入れた。**既定 `World::lateThrough = 1`（Unity の `lateThroughDoor`、C API `AF_WorldSetLateThrough`）。
0 にすると旧（後期を丸ごと耳の部屋の FDN へ一様に）で、試聴の A/B に使える。不明（部屋を引けない面）は耳の部屋の側へ入れた。

結果（`AF_ONLY=latedir`、扉 90°）:

| 耳 | 送り | 戸口越し | 戸口の中心とのずれ | 集まり R |
|---|---|---|---|---|
| (−3, −3) 隣 | 2 本 | 6.1% | 1.0° | 0.974 |
| (0, −3) 隣 | 2 本 | 18.0% | 0.7° | 0.972 |

### ⑤ 壁の向こうの透過音がダブる ── 反射と残響が壁を抜けていた（2026-09-12）

試聴「壁奥の透過音がすごくダブって聞こえる。残響音や反射音は基本壁を抜けないから、direct の透過音だけ通してほしい」。

**何が起きていたか**: 壁を通る分は直接も反射も同じ透過率で縮むので、向こうの部屋の「反射÷直接」の比がそのまま壁越しに残る。
閉じた扉の向こうで、初期＋後期は透過の直接音の **8 倍**（9.3e-4 対 1.1e-4）。透過の直接音の数 ms 後ろに「方向なしの初期」の写しが 1 本立ち、尾も続く。
出どころは 2 つあり、影の線が壁を横切る分（τ 掛け）は全体の 12% だけで、**大半はレイそのものが壁を透過して**隣の部屋に入り、そこで反射した分（ロシアンルーレットの「透過」）。

**直し方**（`World::wallReflect`、既定 0 ＝ 通さない。1 で旧。`AF_WorldSetWallReflect`、Unity `wallReflections`）:
- レイの透過を引かない（当たったら反射だけ、重みは r）。透過するはずだった分は帳簿の escaped6 へ（保存則は保つ）
- 影の線が壁を横切る分と、当たった面の裏側にいる耳へ面を通して届く分は数えない
- 壁を抜けるのは解析で出す透過の直接音（distribute の kTransmit）だけ。開いた戸口を通る分は横切りが無いので変わらない

| 場面 | 旧 → 新 |
|---|---|
| 閉扉（隙間 0）: 初期 / 後期 / 透過の直接 | 3.50e-4 / 5.78e-4 / 1.11e-4 → **0 / 0** / 1.11e-4（不変） |
| 閉扉（隙間 4 mm）: 初期＋後期 | 9.04e-4 → 1.0e-4（4096 本・種 7）、5.5e-7（2048 本・World の種）★ |
| 全開: 初期 / 後期 / 直接 | 1.01e-2 / 2.78e-2 / 1.31e-2 → 8.39e-3 / 2.52e-2（−0.43 dB）/ 1.31e-2（不変） |

### ⑦ 先着の重み（precedence、2026-09-12）── 最初に届く音を重く

配分の**出口だけ**の重み付けで、帳簿（五成分の内訳）は物理のまま。重み = 10^(−X/10 · (1 − e^(−Δ/τ)))、Δ ＝ 直接の到達からの遅れ。
直接・透過は変わらず、回折・虚像は数 ms で少し、戸口の線音源は尾の器の立ち上がり（目安 15 ms）ぶん、部屋の響きはさらに 30 ms 後ろとして大きく下がる。

| 同じ部屋（見通しあり） | ±0 | −0.87 dB | ─ | −8.49 dB |
| 隣の部屋（戸口の正面 3 m） | ±0 | ─ | −3.80 dB | −8.13 dB |

耳に届く配分（`AfFlowWav`、戸口の正面 4 m・扉 90°）: 6 dB で 直接 27.5 → 44.1%、戸口から流した響き 54.0 → 34.0%。12 dB で 59.0% / 17.8%。

既定: **エンジンは 0 dB（物理のまま）、Unity は 6 dB**（演出の既定は載る側が持つ）。エンジンの既定を 6 にすると「出口の和 ＝ 帳簿」を見張る検査

### ⑧ 初期反射を受取面にした（earlyModel、2026-09-13）── 壁が近いと早く・大きく・広く

発注者の問い「今の ISM だと、壁が近いから反射音が近くなるとかの表現はできず方向性だけにならない？」→
「面をレイの受取面にして、面ごとのタップで鳴らす」（探り `AF_ONLY=receiver` で量が NEE と一致することを確かめてから B 案で組み込み）。

**仕組み**（`receiver_layout.h` / `receiver.h`、`World::earlyModel`、既定 1、0 で虚像の道）:
- レイは音源から面までを運ぶ。箱の面を 0.5 m の小片に割り、mixing より前の当たりごとに「小片・小片の中の位置・音源からの時刻・反射して出ていく量・入ってきた向き・何回目か」を置く。
- 耳の側（1 フレーム 1 回・全音源で共有）: 使われた小片ごとに、耳から見た立体角 Ω（閉じた式）と向きのベクトル（Lambert の多角形の式）。
- 受け取りごとに、当たった位置から耳へ影の線を引き、量 ＝ 出ていく量 × Ω/(π·面積) × 空気。耳のそばでも立体角で頭打ち（NEE の 1/d² の跳びが無い）。
- 面ごと・「1 回目の当たり／それ以降」ごとに 1 本のタップ。量はランバート（答えは 1 つ）、遅れと向きは鏡面の折り返しで重み、広がりは向きと到達の散らばり。
- タップの取り分・遅れ・向き・広がり・尾の開始は追従で均す（取り分と 1 回目の遅れは statSec、向きは directionSec、それ以降の遅れは 0.3 s）。
- GPU の道でも受け取りは CPU で取る（同じ種・同じ組のレイ）。

**壁に寄ると**（`AF_ONLY=recvnear`、7×3×7 m・α 0.2、耳を −x の壁へ）:

| 2.0 m | 11.3% / 0.00 | 11.6 ms / 7.6% / 0.13 |
| 1.0 m | 8.8% / 0.00 | 5.8 ms / 17.7% / 0.25 |
| 0.5 m | 7.7% / 0.00 | 2.8 ms / 24.8% / 0.35 |
| 0.1 m | 8.3% / 0.00 | 0.53 ms / 25.7% / 0.50 |

虚像の道は取り分と広がりが距離で変わらない。受取面は壁の反射が 3 倍に増え、広がる。1 回目の遅れは虚像の遅れと 0.05 ms 差（15.15 対 15.20 ms）。

**作る途中で踏んだ穴**（全部直した。receiver.h の「退けた書き方」に記録）:
1. 見え方を小片の見本点で決めると、小片が扉の板をまたぐ所で音源側の量を向こうへ配った（閉扉で初期 3.6e-4 漏れ）。

3. 細い隙間越しにしか見えない小片が丸ごと落ち、隙間が広がった瞬間にまとめて出た（扉 21〜24° で NEE より −5.5 dB、+4.4 dB の跳び）。
   → 受け取りごとの影の線にして 3 つとも消えた。
4. 面のタップの取り分と遅れを生で使っていた（組の入れ替わりで天井のタップが 18%・2.1 ms と 17%・5.8 ms に割れた）→ 追従で均す。
5. それ以降のタップの遅れが扉と一緒に 1 フレーム 1 ms 掃かれた（扉の板 11.7 → 7.5 ms）→ 0.3 s で均す。

### ⑩ 虚像を面でつなぐ（earlyModel 2、2026-09-14）── ⑧ を話していた形に作り直した

発注者「面での受け取りの話、壁の面じゃなくて ISM の虚像音源を面としてつなぐってしてなかった？」。
⑧ は壁を受取面にして虚像を作らず、向きと遅れを面の中の重み（lobe）で近似していた ── 話していた形からの黙った逸脱だった。
⑩ は虚像はそのまま作り（向き・遅れ・窓の可視率）、**量だけ**を虚像の面に届いたレイの受け取りから取る。⑧ の形は 1 で残す。

- 受け取りに「ひとつ前に当たった面」（`Deposit::prevKey`）を持たせた。1 次の虚像（面 f0）は「f0 に 1 回目に当たった器」、
  2 次の虚像（f1 → f0）は「f1 の次に f0 に当たった器」から引く。
- 器の量のうち **可視率 × (1 − 散乱率)** を虚像のタップへ。器の和（量・鏡面の重み・到達の和）を全部同じ割合で抜くので、
  残りの面のタップの平均の遅れと向きは 1 と変わらない。総量は渡す前に数える ＝ 帳簿の初期は 1 と 1 ビットも同じ。
- 虚像のタップの素性は ISM と同じ式（`imageTapId`）。配分では取り分だけ均し、遅れ・向き・広がりは虚像の値を生で使う（ISM の道と同じ）。
- 音源ごとの上書き: `World::setEmitterEarlyModel`（−1 で世界）、`setEmitterAdjacentContain`（負で世界）。
  C API `AF_WorldSetEmitterEarlyModel` / `AF_WorldSetEmitterAdjacentContain`、Unity `WorldVoice.earlyModelOverride` / `adjacentContainOverride`。
  `AcousticWorld.earlyModel` は Range(0,2)・既定 2、エンジンの既定も 2。

数字（検査 [虚像の面] と探り `recvnear`、壁から 0.1 m）:

| | 0 虚像 | 1 壁の受取面 | 2 虚像を面でつなぐ |
|---|---|---|---|
| その壁の 1 次（遅れ − 直接） | 0.57 ms | 0.53 ms（面の重み） | 虚像 0.57 ms ＋ 残りの面 0.53 ms |
| 取り分 | 8.3% | 25.7% | 虚像 **12.8%**（広がり 0）＋ 残り 12.8%（広がり 0.50） |
| 1.0 m での取り分 | 5.9% | 17.7% | 虚像 8.9% |

鳴っている音の段差（clicks、AF_LOUD=1）: 扉だけ 1: 0.754 → 2: 0.755 dB、歩き＋扉 1: 1.405 → 2: 1.395 dB（0 は 1.20）。
★最初の形は残りの面のタップの遅れを量で平均していて、戸口越しの床のタップの遅れが扉と一緒に 4.93 → 5.62 ms 掃かれ、扉だけ 0.754 → **1.89 dB** に悪化した。1 と同じ鏡面の重みに戻して直した。

GPU 0: 1.29 / 1: 3.80 / 2: **4.27 ms**（受け取りは CPU で取るまま）。受取面が重い音源は、上書きで選んだ音源だけに使える。

### ⑪ 虚像の網（earlyModel 3、2026-09-14）── 壁でなく「虚像を結んだ網」で受ける

発注者「ISM をつないで、その面を面として扱うんじゃないの？今は既存の壁メッシュが面になってない？」── ⑩ も受けているのは壁の小片で、
虚像は壁の器から量を分けてもらうだけだった。候補を 2 つ図で出し、発注者が「虚像どうしを結んだ面」、レイは A「音源からのレイのまま」を選んだ。

- **網**（`Flow/image_lattice.h`）: 虚像どうしを「経路が反射 1 回だけ違う」物で結ぶ。1 次の虚像の向き（−法線）で軸を束ね、軸の上に
  1 次と、平行な 2 枚を往復した 2 次を並べる。見えない虚像も網の角に残す（出入りで網の形を変えない）。箱の部屋なら目は角が虚像の箱。
- **点**: 受け取り 1 件を 2 つの見かけの音源の点にする。散乱の分（s）は「当たった位置から耳への向き × 音源 → 当たった位置 → 耳の道のり」、
  鏡面の分（1 − s）は「入ってきたレイの見かけの出どころを面で鏡に映した点」（1 回目の当たりなら当たった位置によらず 1 次の虚像に重なる）。
- **受ける**: 点が入った網の目の角の虚像へ、軸ごとの折れ線の山の掛け算で配る（箱なら三重線形、和は 1）。角が 0 枚 ＝ 音源の角 → 方向なしの 1 本、
  1〜2 枚 ＝ 虚像 × 可視率、3 枚以上・網の外・見えない → 残り（面のタップ）。
- **タップ**: 虚像ごとに 遅れ・向きは虚像のまま、量は網から受けた分、広がり max(1 − 可視率, 1 − |配られた向きの平均|)。
- **尾の開始**: 早い順に量を積んで 5% に届く時刻（網のときだけ。1・2 は「取り分 2% 以上の最短」のまま）。
- 帳簿の初期は 1 と 1 ビットも同じ（配る前の受け取りの和で数える）。`earlyModel` 既定 3（エンジン・Unity）、0/1/2 は切り替えで残す。

数字（検査 [虚像の網]、壁から 0.1 m / 1.0 m のその壁の 1 次）:

| | 2 虚像を面でつなぐ | 3 虚像の網 |
|---|---|---|
| 取り分 0.1 m | 12.8% | **14.7%** |
| 取り分 1.0 m | 8.9% | 11.1% |
| 広がり 0.1 m / 1.0 m | 0.00 / 0.00 | 0.03 / 0.03（壁に寄っても広がらない） |
| 初期のうち虚像のタップ（部屋の中の検査の場面） | 47% | 82%（音源の角 1%） |

網そのもの: 虚像の位置の点はその虚像へ可視率ぶん（差 0）、2000 点で重みの和の差 1.2e-7、1 cm 動かしたときの重みの動き最大 0.0026。

鳴っている音の段差（clicks、AF_LOUD=1）: 扉だけ 2: 0.755 → 3: 0.755 dB、歩き＋扉 2: 1.395 → 3: **1.51 dB**（悪化。最悪は 58.2° の −1.51 dB で、
1・2 にも同じ所に −1.20 dB がある ── 扉が開いて直接音が見え始める所。18.2° の段は 1.40 → 0.95 dB、59.5°・61.4° の段は消えた）。
費用（`manysrc`、17 本の中央）: CPU 5.72 → **5.76 ms**、GPU 4.28 → **4.34 ms**。

途中で踏んだ穴（どれも直した）:
1. 受け取りの量はランバートで数えているので、点を 1 つ（散乱の形）だけで配ると鏡面の壁でも面いっぱいに散り、0.1 m でその壁の虚像が 2.3%（1.0 m の 4.0% より小さい）
   → 面の器ごとに lobe で寄せ直す形は 0.1 m で 2.8% にしかならず（壁の真横は鏡面の向きの受け取りが面のごく一部で、下駄に埋もれる）→ 鏡面の分を鏡に映した点で配る形にした。
2. 尾の開始の「取り分 2% 以上の最短」: 遅れの短い小さな虚像のタップが 2% をまたぐたびに約 2 ms 跳び、扉だけ 0.755 → 1.02 dB（組の入れ替えを止めると 0.755 のまま）
   → 取り分 0〜4% で候補を +10 ms から滑らせる形は歩き＋扉 2.57 dB → 量の 5% 分位点にした。
