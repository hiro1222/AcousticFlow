# 新コア（Flow）と旧コア（Scene）の違い ── 段 10 の前の突き合わせ

2026-09-10。旧コアを消す前に「新コアでも数字で確かめられるか」を作り、その上で違いを洗い出した記録。

## 測り方

同じ場面・同じ信号・同じ長さを両コアで鳴らして、出た WAV を同じ解析にかける。

```
AfRenderWav <出力>            旧コア（AF_Scene）
AfFlowWav   <出力> [音源x]    新コア（AF_World）  ← 今回追加
AfAnalyzeWav <WAV>            どちらも同じ物差しで読む
```

場面は密閉した 2 部屋を幅 1.2 m の戸口で繋ぎ、蝶番 x=−0.6 の扉を 0°→90°→0° と 12 秒で振る。
リスナー (0,1.6,−4)、音源 (−2,1.6,3.5)。信号はピンク寄りの雑音で、種と式まで揃えてある。

`AfFlowWav` の摘み（環境変数）:

| 変数 | 既定 | 何を変えるか |
|---|---|---|
| `AF_ROOM_CELL` | 0.25 | 部屋グラフのボクセル一辺(m) |
| `AF_DOOR_HALF` | 0.6 | 戸口の半幅(m)。部屋が割れる境目を測る |
| `AF_WEIGHTS` | 全部 1 | 五成分の重み `直接,初期,後期,回折,透過` |

## 鳴らして出た数字

窓 100 ms、立ち上がりと終わりを外した 0.5〜11.5 秒。

| | 閉→開のふり幅 | 色の傾き（125 Hz − 4 kHz） |
|---|---|---|
| 旧コア | 18.9 dB | 5.4 dB |
| 新コア | 21.8 dB | 18.7 dB |
| 新コア（後期を止めて） | 23.4 dB | 19.6 dB |

- **ふり幅は新コアの方が 2.9 dB 広い。**扉の効きはコンセプトの中心なので、ここは新コアが有利。
- **色は新コアが 13.3 dB 低域寄り。**後期を止めても変わらないので、原因は尾ではなくタップ側。
  どちらが正しいかは実測の当てが無いので**耳で決める**。旧コアは開口の法則 1（高域 +10 dB）を
  差し戻した経緯があり、明るい側に寄っている可能性がある。

## 仕組みの違い

| | 旧コア（Scene） | 新コア（Flow） |
|---|---|---|
| C API の関数 | 160 | 36 |
| 幾何 | 箱＋メッシュ（BVH、面の焼き） | **箱だけ** |
| 部屋 | 自動分割＋**ポータルを宣言できる**（`AF_SceneAddPortal`） | 自動分割のみ。宣言する入口が無い |
| 直接音 | ソフト遮蔽（帯域別の透過率） | 円盤の見通しの割合（走査線＋二分探索＋erf） |
| 回折 | 前川／UTD／Kirchhoff／BTM の 4 模型＋稜線カタログ | 前川＋フレネル隙間の 1 本 |
| 早期反射 | 面の線音源（`earlyModel=1`）／旧の像源レイ（0） | 虚像 ISM（方向と正規化重みだけ）＋方向なしの残り |
| 後期 | エコグラム畳み込み／FDN の 2 本立て（`tailModel` で A/B） | FDN だけ |
| タップの組み立て | DLL 内（`tap_builder`）。ホストが写す | `AF_WorldApplyVoice` が全部やる |
| 録音（capture） | 録る・読む・走査・回帰生成・ABI 経路まで一式 | **無い** |
| 焼き | 面の見通しの焼き（export/import） | **無い** |
| 検査 | 441 件 | 120 件 |

作りのいちばん大きな違いは**ホストの仕事の量**。旧コアは `render_wav.cpp` が 170 行かけてタップを
組んでいたが、新コアは `AF_WorldApplyVoice` の 1 行で済む。`render_wav_flow.cpp` が短いのはそのため。

## 見つかった不具合

### ① 幅 1.2 m の戸口では部屋が割れない

0.25 m 格子で戸口の幅を変えて測った。

| 戸口の幅 | 部屋 | 戸口（Aperture） |
|---|---|---|
| 1.2 m | **1** | **0 個** |
| 1.0 m | 2 | 3 個 |
| 0.8 m | 2 | 3 個 |
| 0.6 m | 2 | 1 個 |

部屋グラフは「くびれ」でしか割らないので、幅 1.2 m は太すぎて 1 部屋になる。
そうなると戸口が 0 個になり、**扉で響きを変える仕組み（`applyOpenings`）がまるごと効かない**。
格子を 0.15 m に細かくしても割れないので、格子の粗さではなく閾値の問題。

旧コアはここをホストが `AF_SceneAddPortal` で宣言していたので起きなかった。
新コアには宣言する入口が無い。**決めること: 戸口を宣言できるようにするか、閾値を見直すか。**

### ② 音源が戸口から外れていると、扉を開けるほど回折が消える

音源 x=−2（戸口の正面から 2 m 外れ）で、45° 以上で回折が 0 になる。

| 角度 | 回折 | 箱/稜線 | 隙間 a | 重み |
|---|---|---|---|---|
| 0° | −44.6 dB | 0/7 | 0.151 | 0.19 |
| 15° | −45.0 dB | 0/7 | 0.137 | 0.19 |
| 30° | −48.5 dB | 0/7 | 0.111 | 0.10 |
| 45°〜90° | **無し** | −1/−1 | − | **0.00** |

原因は候補の取り方。回折の候補は**音源の円盤に影を落とした箱**からしか取らない（段 6 の決定）。
この場面で影を落とすのは左の仕切り（箱 0）だけで、その稜線は蝶番と同じ x=−0.6 にある。
扉が開くとその稜線のすぐ脇に板が立つので脚が潰され、重みが 0 に落ちて候補が空になる。
**右の戸口枠（x=+0.6）は音源に影を落とさないので、最初から候補に入っていない。**

旧コアは同じ場面で 0°〜90° を通して回折を 1 本保ち、到達エネルギーが 0.0074 → 0.40 と単調に増えた。

音源が戸口に正対しているとき（x=0）は新コアも正しく動く。見通しが 0 → 0.26 → 1.00 と開き、
回折は −35.8 → −27.6 と増えてから、見通しが 1 になった所で 0 になる（設計どおり）。

**決めること: 候補を「影を落とした箱」だけでなく、直線が壁を横切った所の近くの箱まで広げるか。**
