# Ⅰ. ピラー

## 音としての表現 ─ **その空間や世界が伝わる音**
## ゲームとしての遊び ─ **行動に対しての音の変化**

前者が原点で、後者が今回のエンジンが担当する範囲。

---

# Ⅱ. 論理武装

## 感情の根拠
自分が現実で、ドアを開けたり物を動かしたり移動したりして、聞こえ方がリアルタイムで変わる体験をいいと感じている。それを落とし込みたい。

出自：現実で楽器をやってきた。音が好き。サウンドデザイナーではなく、**サウンドのできるゲームプログラマー**として作る側に回る。

補強例（後から出す用）
- **Visage の扉**：奥を警戒しながら慎重に開ける。その過程が音で返ってきたら面白い
- **ブレワイのコログを鉄箱で閉じ込める**：籠りと金属反響が返ってきたら閉じ込めた感が増す

両方とも「こういうことができたら面白い」という同じ発想から出ている。

## 論理の根拠 ① 既存手法の限界
Switch / State / RTPC は代表的な状態変化には対応できるが、ほんの少しの細かな音色表現は苦手で、2値クロスフェードでは表現しきれない体験が出てくる。

## 論理の根拠 ② 総当たりの否定
Effect を全部用意すれば理論上は解ける。だが実装面の負担が大きく、**世界観の統一で違和感が生まれる**。世界の音としての決まりを持つことで、両方を解決する。

## 立場
- **既存手法は残す。** 扱いやすく伝えやすい。置き換えではなく補完
- **物理的忠実ではなく、期待に寄せる。** 期待の出所は現実の経験則
- **調整するのは開発者。** リスナーにさせたい体験を作るのが開発者だから
- **世界の音の決まりは、ゲームに応じて設定できる。** ルールと世界観を持てる
- 手法を原理主義的に選ばない。**場面で使い分ける**

# Ⅲ. 責務の三層

| 層 | 担当 |
|---|---|
| **エンジン** | 音の変化を伝える。開口・遮蔽・空間の鳴り |
| **State / Switch** | 材質の共鳴素材の切り替え（演出としての材質） |
| **音作り・デザイン** | 聞く価値のある音を作る |

※「材質」は二つの意味で使われる。**世界ルールとしての材質**（帯域別吸音・透過率）はエンジン側、**演出としての材質**（共鳴素材）は State 側。

# Ⅳ. 技術選定の経緯

**IR で実装 → FDN へ変更**
理由：残響の尾の畳み込み、生成時の演算時間から、連続性の保持が難しい

**要件**
- 動的性の担保
- アンサーの即効性（動かした／動いたことが即座に音でわかる）
- 計算の軽量さ

**空間印象 = ASW + LEV**（論文＋IR 実装経験より）

| | 担当 | 依存先 |
|---|---|---|
| ASW | ISM の虚像方向 → 方向性バッファ | 音源依存 |
| LEV | FDN | 空間・部屋依存 |

# Ⅴ. 音の五成分

**直接音 / 反射音 / 回折音 / 残響 / 透過音**

足し上げるのではなく、**全体エネルギーからの配分**として求める。帯域別（六帯域が軸、音源ごとに可変）。

---

# Ⅵ. 構成

```
音源（幅を持つ／遠距離・低優先度で点にクロスフェード）
 │
 ├─ レイトレース（BVH）── 素材の透過率・反射率でエネルギー分配
 │   └→ 帯域別エネルギー総量
 │       ├→ 直接音
 │       ├→ 回折音   ── 前川式（第一候補）
 │       ├→ 透過音
 │       ├→ 反射音（初期）──┐
 │       └→ 反射音（後期）─→ FDN
 │                          │
 └─ ISM（BVH）              │
     └→ 虚像方向 ＋ 正規化重み ┤
                             │
   各虚像エネルギー = レイ総量 × ISM正規化重み
                             ↓
                    方向性バッファ → ASW
                             ↓
部屋ごとの FDN ──────────────┤
 ↑ プローブ（帯域別RT60・体積・方向重み）
 └ 遅延線長は固定、帯域別減衰でパラメータ制御
   開度に応じた部屋間混合 → 出力行列 → LEV
                             ↓
                          リスナー
```

**ISM と FDN の境界**：FDN のエコー密度が十分になるまでを ISM が埋める。
**ISM は音量を持たない**：方向と正規化重みのみ。重みは距離 → 距離＋累積反射率、と段階的に上げられる。
**FDN は部屋ごと**：音源数に比例しない。プローブは IR ではなくパラメータを持つ。

# Ⅶ. 負荷設計

**レイ更新のフレーム分散。総予算は固定。**
- 音源が多い部屋：順に回す。聞き分けが難しいので目立たない
- 音源が少ない部屋：予算を集中し、更新頻度を上げる

**優先度**
1. プレイヤーの操作対象（最優先）
2. 距離
3. 音量
4. 変化量

環境背景音など、事前除外できるものは抜く。

→ **負荷設計がピラーと一致している。** 行動による変化を主役にするなら、計算資源も行動が関わる音源に寄せる。

# Ⅷ. 使い分けの基準

**2値フェードでいい**：開ける／閉めるの二択しか操作がない場面。単純な窓、部屋間移動
**方向を持った連続処理が要る**：開き具合を操作できる場面

判定軸：**プレイヤーに与えられている操作の解像度**。

# Ⅸ. 扉

## 選んだ理由
1. 頻度 2. 調整ができる 3. 視覚のサポート
上位理由：**遊びにできると思ったから**

## 扉が持つ変数
開度 / 扉板の向き / 開口の形 ─ 三つが同時に動く

## 確定した体験
- **ラウドネスは開き始めた瞬間に立ち上がる。** それが自然
- 開度の残り区間を担うのは**鮮明さ**
- 「扉を開けて視界が開けるのに応じて、音も開けていく」
- 扉の裏の音源は、開いて見えるところより少し暗い

**鮮明さを作る五要素**（それぞれ別の速度で動く）
高域の通り / 定位 / 直接音の比率 / 音源の部分遮蔽 / 向こうの部屋の初期反射

→ これが「2値クロスフェードでは表現しきれない体験」の正体。

## 四面の状態
| | 状態 |
|---|---|
| ① 直接音・鮮明さ | 方向確定。応答曲線は未定 |
| ② ISM と扉板 | 開＝吸音100、閉＝反射面。中間が未決 |
| ③ FDN とプローブ | 部屋ごとの FDN を開度で混合 |
| ④ 透過音 | レイ方式で解決 |

# ⅩⅠ. 一貫している思想

**配分で解く。** 扉の不連続、部屋間の接続、ISM とレイの結合、負荷配分。四箇所すべてが「何かを切り替える」ではなく「配分を動かす」で解けている。

**変化しているものに寄せる。** 計算資源も、方向解像度も、更新頻度も。行動によって変わるものを主役に置くという思想が、実装の隅々まで通っている。

# 追記（2026-09-10、サウンド側。承認済み）

設計を変える物ではない。書いていなかった所と、旧実装が身をもって知った所を足す。

## A. Ⅵ への注 ── 扉の開口は解析、統計はレイ
レイの総量は Monte Carlo で揺れる。平滑すると扉の立ち上がりが鈍る。旧実装は歩行の揺れがレイ追跡で 4〜7.6 倍、面の線音源で 1.1〜1.5 倍と測り、直接音の半影を標本点から解析積分に置き換えた。
→ **扉の開口（直接音の通る割合、開口率）は幾何から解析で出す。レイは統計（反射・透過の総量）だけを担う。**

## B. Ⅴ への注 ── 「総量」の定義と、回折の入り口
レイは面で反射・透過・吸収に分かれるので保存則を満たす。回折はレイでは出ない。
→ **総量 ＝ 音源から出て面での分配を経てリスナーに届いた帯域別エネルギー。回折は「遮られた直接音の代わり」で、自由音場の直接音に前川式の減衰を掛けた物。**これで配分の枠に入る。

## C. Ⅸ への注 ── 鮮明さ五要素の速度の表
「それぞれ別の速度で動く」の値。初期値は旧実装の実測。
| 要素 | 追従 | 出所 |
|---|---|---|
| 量（ラウドネス） | 毎フレーム | 8 フレームに 1 回だと段になった（ぷつぷつ） |
| 形（帯域の色） | 26〜54 ms | 傾斜入力での実測 |
| 方向 | 250〜317 ms → 扉は幾何で毎フレーム | 旧: プローブ平滑。新: 戸口の向きは幾何 |
| 尾の開始 | 跳びの 4 倍（1 チャンク〜200 ms） | 1 チャンクだと正弦で 11.7 dB 跳んだ |
| 尾の向き | 60 ms | 1 ブロックだと 4.3 dB 跳んだ |

## D. Ⅳ の要件に 4 つ目 ── 行動していないときは揺れない
「行動に対しての音の変化」の裏返し。揺れも変化に見えるので、これが無いとピラーが壊れる。測れる形は**歩行の連続性**（鳴っている音で隣り合うブロックの比を測る）。

## E. Ⅵ への注 ── プローブは形式、部屋グラフは生成器
プローブを手で置くと authoring になる。旧実装の部屋グラフ（ボクセル → 連結成分 → Sabine）が RT60・体積を自動で出すので、それをプローブ値として流す。手で置くのは上書きしたいときだけ。

## F. Ⅱ「世界の決まり」の具体
材質（帯域別吸音・透過率）のほかに、**配分そのものへの世界ごとの重み**（残響を強く／透過を弱く、の一組）。「ルールと世界観」の実体。

## G. 軽い ── 遅延線長は係数 1 つ残す
固定にすると広さの手掛かりが一つ減る。平均自由行程で伸縮させるのは部屋ごとに係数 1 つで、固定にしても軽くならない。

## H. Ⅹ の空欄「FDN なら BTM」の理由 ── 埋めた
BTM は時間領域の応答なので ISM のタップと合成できる。前川式は帯域別の減衰量だけなので、配分の原理と合う。**旧実装の BTM はタップ組みに整合していて、前川式は配分に整合している。**切り替えは一貫。

## 決めたこと（2026-09-10）
- 作り直す範囲は**コア**（旧 `scene.h` と幾何→DSP の受け渡し）。Dsp・部屋グラフ・BVH・材質・検査の物差し・Unity の薄い層は残す
- 早期反射は**設計文書どおり ISM**（方向と正規化重み。量はレイ総量から配る）
- **扉の開口は解析**（A）
