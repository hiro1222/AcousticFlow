# 03 エンジン②：音の届き方（レイ・見通し・回折・虚像）

音源から耳まで、音は 4 通りの道で届きます。**どの道をどの方法で解くか**がこの章です。

| 道 | 解き方 | ファイル | 理由 |
|---|---|---|---|
| 直接（見えている分） | 解析（自由音場 1/(4πd²)） | `energy_trace.h` | 決まった答えがある物を統計で出す理由が無い |
| 見通しの割合・透過 | 解析（円盤の走査線 ＋ erf） | `aperture.h` | **扉は解析**。レイの揺れを扉に通さない |
| 回折 | 解析（最短の稜線 ＋ 前川） | `diffraction.h` | 稜線が入れ替わっても値が飛ばない |
| 反射（初期・後期） | レイ（統計） | `energy_trace.h` | 部屋の中の多重反射は統計でしか出せない |
| 初期反射の向きと遅れ | 虚像（ISM）→ 面音源 | `image_sources.h` `image_surface.h` | 量はレイ、向きと遅れは虚像（答えを 2 つにしない） |

読む順: `emitter.h` → `budget.h` → `energy_trace.h` → `aperture.h` → `maekawa.h` + `diffraction.h` → `image_sources.h` → `image_surface.h` →（`Gpu/`）

---

## 1. 音源とリスナー `Flow/emitter.h`

- `Listener`：位置・前・上。`toLocal(v)` で世界の向きをリスナー座標（+x 右・+y 上・+z 前）に直す。**この変換はここ 1 か所だけ**。
- `Emitter`：位置・幅 `radius`（m、0 で点）・操作対象か・重要度 `loudness`・今いる部屋。
- `effectiveRadius(dist)`：幅は「見込み角」で点に落とす。θ = atan(r/d) が 2° 以上なら幅のまま、0.5° 以下なら点、間は線形。
  ★境を 1 点にすると、境をまたぐたびに幅が 0 と r を行き来して見通しが跳ぶ。線形の帯にしてある。
- `beginFrame(dt)` で移動の速さ（m/s）を出し、予算が「動いている音源」を優先するのに使う。

## 2. 予算 `Flow/budget.h`

総レイ数を固定（既定 1,536 本/フレーム）して、音源ごとに配ります。

```
点数 = 重要度 / (1 + 距離/4) × (1 + 3·操作対象) × (1 + 速さ/2)
段   = 点数の順に 厳密（6 本まで）→ 簡易（10 本まで）→ 保持
本数 = 厳密は満額（上限 512）、簡易は 1/4（下限 32）、保持は 0
```

- **保持は「止める」ではない**：最後の答えを保ちます（配分は前の `Mix` を出し続ける）。
- 段の上下にはヒステリシス（上がるのは 0.5 秒、下がるのは 1 秒続いたとき）。無いと境で音質が行ったり来たりして聞こえる。
- 保持のうちいちばん古い 1 本を毎フレーム簡易で解き直す（扉が開いても眠ったままにならない）。
- さらにレイを 4 組に分け、1 フレームに 1 組だけ飛ばして残りは前の結果を使う（`rayGroups = 4`、設計の「フレーム分散」）。

## 3. レイトレース `Flow/energy_trace.h`（★）

### 単位

「音源の出力を 1 としたとき、リスナーの点に届く強さ（1/m²）」。直接音なら 1/(4πd²)。

### 1 本のレイ

```
 出発: 一様な向き、エネルギー e = 1/N（帯域ごと）
 当たるたび:
   吸収 α·e を帳簿へ
   ★次イベント推定（NEE）: 当たり点からリスナーへ影の線を 1 本引き、
       届く強さ = e_side · cosθ / (π d²) · τ_途中 · 空気
     到達時刻 (経路長 + d)/c が mixing time より前なら「初期」、後なら「後期」へ足す
   続き: 反射率 r で重みを掛け、散乱率で 鏡面⇄拡散 の向きを選ぶ
 打ち切り: 帯域の最大が出発の 1e-4（−40 dB）を切るか、跳ね返り 40 回
 帳簿: 放射 = 吸収 + 残り + 逃げ（保存則。検査で確かめる）
```

**なぜ NEE か**：「レイがリスナーの球に当たったら数える」方式だと、当たる本数が少なすぎて 256 本では初期反射がほぼ 0 か 1 本になります。
当たり点ごとに耳へ線を引けば、全部のレイが寄与します（「diffuse rain」と呼ばれる標準の推定法）。

```cpp
// ── NEE: この当たり点からリスナーへ ──（energy_trace.h、抜粋）
const Vec3 toL = listener - h.point;
const float d = length(toL);
const Vec3 u = toL * (1.0f / d);
const float cosF = dot(nFace, u);
const bool front = cosF > 0.0f;                         // 耳が面の表側か
sceneTransmittance(sc, org, listener, h.index, tr, &cr); // 途中の壁の透過
const float tSec = (pathLen + d) / kSpeedOfSound;
const float geo = std::fabs(cosF) / (kPi * d * d);       // ★1/π を忘れると +5 dB
const bool passWall = (prm.wallReflect != 0 || (cr == 0 && front));   // 反射と響きは壁を抜けない（既定）
for (int b = 0; passWall && b < kNumBands; ++b) {
    const float eSide = e[b] * (front ? sp[b].reflect : sp[b].transmit);
    const float c = eSide * geo * tr[b] * airEnergy(b, pathLen + d);
    if (tSec < prm.mixingSec) out.early6[b] += c; else out.late6[b] += c;
}
```

### 大事な決まり

- **乱数の種は音源ごとに固定**（音源 × レイ番号）。静止していれば毎フレーム同じレイが飛び、答えがビット一致する ＝ 揺れない。
- **反射と響きは壁を抜けない**（`wallReflect = 0`、既定）。壁越しに聞こえるのは直接の透過だけ。以前は壁越しの反射まで数えていて、
  閉じた扉の向こうの音がダブって聞こえた（閉扉で直接の 8 倍）。
- **後期の出どころ**：後期のうち「耳と別の部屋の面から来た分」を `lateOther6` と向き `otherDir` に分けて持つ（総量 `late6` は変えない）。
  戸口越しの響きを戸口の向きから鳴らすのに使う（04・05 章）。
- 帳簿は double。float だと 4096 本 × 40 回で保存則の検査が落ちた。

### GPU の道 `Gpu/`（既定は切）

- `trace_kernel.h` の HLSL は `traceRay` を **同じ順・同じ式** で写した物（1 スレッド ＝ レイ 1 本）。
- `trace_gpu.h` が `TraceScene` を GPU の並びに詰め、全音源を 1 回のディスパッチで流し、CPU と同じ形の結果を返す。
- `compute_d3d11.*` はエンジンが自分で作る D3D11 デバイス（Unity や Unreal のデバイスを借りない ＝ 検査が単体で回る）。
- CPU と GPU はビット一致しません（丸め・sin/cos が違う）。守るのは「静止で毎フレーム同じ」「保存則」「CPU と dB で近い」の 3 つ。

## 4. 見通しと半影 `Flow/aperture.h`（★扉の主役）

### 見通しの割合 `discVisibility`

音源を「リスナーに正対した半径 r の円盤」とみなし、そのうち **何割が見えているか（0..1）** を出します。

```
 円盤の明るさはガウス（σ = r/2、縁で 2σ）
 円盤を水平な走査線（9 本）で切り、各線の上で「影の区間」を求める
   粗い標本（16 点）で明暗の切り替わりを見つけ → 二分探索（12 回）で境界を 1/65536 まで詰める
 明るい隙間のガウス重み付きの長さを erf で解析的に足す
 影を作った箱ごとの寄与から、遮っている物の透過率 τ_b も返す
```

★標本は「境界を探す」ためだけに使い、面積は erf で出すので、扉の縁が動いても値は連続です（段差は 1/65536）。
これが「扉が開くときに音が滑らかに変わる」の土台です。点の見通し（見えたら 1、見えなければ 0）だと、扉が横切る瞬間に 1 フレームで跳びます。

配分（04 章）ではこう使います：

```
直接 = 自由音場 × 見通し
透過 = 自由音場 × (1 − 見通し) × τ_遮っている物      ← 遮られた分だけが板を通る
回折 = 自由音場 × (1 − 見通し) × 前川の減衰²          ← 遮られた分だけが縁を回る
```

### 戸口の覆い `openingCoverage`

戸口の矩形を扉の板がどれだけ覆っているか（0..1）。板の 8 頂点を戸口の面に **正射影** → 凸包 → 矩形で切り抜き → 面積比。
正射影なので視点に依らない（部屋の性質）。閉じた扉は 1、90° に開いた扉は 厚み/幅 ≒ 0.03。
`1 − 覆い` が「戸口の開き具合」（`openFrac`）で、RT60（02 章の `applyOpenings`）と、戸口越しの響きの量（04・05 章）の両方に使われます。

## 5. 回折 `Core/maekawa.h`・`Flow/diffraction.h`

```
 1) 直線 L→S を遮っている箱の 12 本の稜線が候補
 2) 各稜線で、経路長 f(t) = |L−P(t)| + |P(t)−S| を最小にする t を黄金分割で探す（凸なので谷は 1 つ）
 3) 点 P を稜線の外側へ 1 mm 押し、L→P と P→S が他の箱に遮られないか確かめる
 4) 有効な候補のうち最短の経路を採る。迂回長 δ = f_min − |L−S|
 5) 前川: N_b = 2δ/λ_b、A_b = 5 + 20·log10( √(2πN) / tanh√(2πN) ) dB（上限 24 dB）
    高域ほど N が大きく減衰が強い ＝ 回折のハイ落ち（こもり）
 6) 向き = リスナーから P、到達 = f_min / c
```

**なぜ UTD でなく前川か**：UTD は稜線ごとの幾何（入射角・回折角・くさびの角）に依存するので、最短の稜線が入れ替わる所で最大 7.9 dB 跳びました。
δ は「候補の最小値」なので、入れ替わっても値は連続です（min は連続関数を保つ）。厳密さより連続性を取る判断で、商用の実装（Wwise は回折角 → 減衰カーブ）とも同じです。

★閉じかけの扉は、点を「扉と枠の隙間の中」に置くことで 1 本の稜線のまま扱います（2 本の稜線を回る経路にすると、どちらを回るかの選び直しで跳ぶ）。

## 6. 初期反射：虚像と面音源

### 虚像 `Flow/image_sources.h`

- 1 次の虚像 ＝ 面で音源を鏡に映した点。2 次 ＝ 1 次をもう 1 面で映した点。
  **音源とリスナーが同じ側にある面だけ**（忘れると壁の裏の面で虚像ができて、壁越しに反射が鳴る）。
- 経路長が mixing time ＋ 3 m を超える物は捨てる（それより後は FDN の仕事）。
- **見えているかは 0/1 でなく割合**：虚像のまわりの円盤（半径は下限 15 cm）が、鏡の面の矩形の中を通り、各脚が遮られない割合を、
  見通しと同じ走査線 ＋ erf で出す。点の虚像は面の縁で 0/1 に跳ぶ（歩くと揺れが 4〜7.6 倍）。割合なら 1.1〜1.5 倍。
- 重み_i,b = 割合_i × Π(面の反射率_b) / d_i²、帯域ごとに和を 1 に揃える。
  **量は持ちません**。量はレイの初期の総量で、虚像は「どの向きへ・いつ」を配るだけ（同じ反射を二重に数えない）。

### 虚像の面音源 `Flow/image_surface.h`（既定 `earlyModel 4`）

虚像を点で鳴らさず、耳から見て近い虚像どうしをつないだ「面」として鳴らします。

```
 つなぎの強さ k_ij = exp(−(角度_ij / (connectRad + α_i + α_j))²) · exp(−((t_i − t_j) / connectSec)²)
   ★しきい値で切らない（虚像が出入りしても重さが連続に変わる）
 面の向き = 量 × 向きの和の向き、面の幅 = √3 × 角度の標準偏差（ASW ＝ 部屋の広さ感）
 奥行きの重み = 集まり^densityPow × 近さ^nearPow を、初期の総量が変わらないように揃える（演出。出口だけ）
```

Unity・Unreal が渡している値（`AF_WorldSetImageSurface`）: 散乱の幅 20°、つなぐ角度 15°、つなぐ到達 5 ms、集まりの重み 1、近さの重み 1。エンジンの既定は重み 0（＝ 虚像の点と量が 1 ビットも同じ）。

狙い：①つなぐので動いても滑らか ②面の幅で部屋の広さ感 ③虚像が集まった所・経路が短い所を重くして奥行き感。
幅はタップの `width` として DSP へ渡り、方向バスのレーンへ幅で配られます（05 章）。
