## 1. 全体の絵（3 つの層）

```
┌─────────────────────────────────────────────────────────────────────────────┐
│ ホスト（ゲーム）            Unreal の地図 / Unity の場面                          │
│   壁・扉・音源・プレイヤーを置く。音の計算は一切しない                            │
└──────────────┬──────────────────────────────────────────────────────────────┘
               │ 毎フレーム: 箱の位置・耳・音源・摘み
┌──────────────▼──────────────────────────────────────────────────────────────┐
│ コネクタ層（器）                                                              │
│   Unreal: AAcousticFlowWorld ほか   Unity: AcousticWorld ほか                 │
│   Wwise : 自前プラグイン AF_Renderer（バス AcousticFlow に 1 つ挿す）           │
│   ★値を渡すだけ。計算はしない（同じ名前・同じ既定値を Unity と Unreal で揃える）  │
└──────────────┬──────────────────────────────────────────────────────────────┘
               │ C API（acoustic_world.h / acoustic_voice.h / acoustic_host.h）
┌──────────────▼──────────────────────────────────────────────────────────────┐
│ エンジン AcousticEngine.dll（C++17、ほぼヘッダだけ）                          │
│   Core  形・材質・部屋グラフ                                                   │
│   Flow  レイ・見通し・回折・虚像 → 五成分に配る（エネルギーで考える層）         │
│   Dsp   Voice・HRTF・方向バス・FDN（振幅で考える層。オーディオスレッドで回る）    │
│   Gpu   レイを GPU で解く道（既定は切）                                        │
│   Export C の窓口                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

**音の素材は Wwise が鳴らします**（Event `Play_AF_Test` → 音 `AF_TestTone`）。Wwise はその音を
バス `AcousticFlow` に届け、そこに挿した自前のプラグインが「この音はどの音源か」を引いて、
エンジンの Voice に通して左右 2 本の音にします。Wwise に戻るのは、その 2 本だけです。

## 2. 1 フレームと 1 ブロック（2 本のスレッド）

### ゲームのスレッド（毎フレーム。Unreal の `AAcousticFlowWorld::Tick`、Unity の `AcousticWorld.Update`）

```
 1) 動く箱（扉の板）の位置を送る            AF_WorldSetBoxTransform
 2) 耳の位置と向きを送る                    AF_WorldSetListener
 3) 摘みを送る（重み・先着の重み・影のこもり…）AF_WorldSet*
 4) 音源の位置を送る                        AF_WorldSetEmitter
 5) 1 フレーム解く                          AF_WorldUpdate   ← ここでエンジンが全部計算する
 6) 部屋グラフが組み直されていたら FDN の器を作り直す  AF_WorldFdnStale
 7) 音源ごとの答えを Voice に写す            AF_WorldApplyVoice
 8) 台帳に「どの Voice が今どこか」を公開      AF_HostBegin … AF_HostCommit
 9) 引退した Voice を 1 秒後に壊す           AF_HostTick
```

`AF_WorldUpdate` の中身（[04 章](04_engine_distribute_frame.md)）:

```
 部屋グラフ（必要なときだけ）→ 当たり判定の木 → 戸口の開き具合 → 予算（音源ごとのレイの本数）
 → 音源ごと: レイ（反射の統計）→ 見通し（半影）→ 回折 → 虚像 → 配分（五成分 → タップと送り）
 → 部屋ごとの FDN の重み・向き・戸口の線音源・壁までの距離でレーンへ配る形
```

### 音のスレッド（Wwise の 1 ブロック = 512〜1024 サンプル。プラグインの `Execute`）

```
 1) 台帳の写しを取る（待たない。取れなければ前の写し）  AF_HostSnapshot
 2) 届いた音ごと: モノラルに畳む → 結び付いた Voice へ  AF_VoiceRender（直接・初期・回折・透過を両耳に）
       └ Voice は同時に、部屋の FDN へ「送り」、方向バスへ「反射のタップ」を溜める
 3) 部屋の FDN を 1 回だけ回す                         AF_FdnMixRender（戸口の線音源もここ）
 4) 方向バスを 1 回だけ回す                            AF_DirectionBusRender（反射と響きのレーンを両耳に）
 5) 2〜4 を足した左右 2 本を Wwise へ返す
```

**重い計算（レイ）はゲームのスレッド、音のスレッドは掛け算と畳み込みだけ**、という分け方です。
音のスレッドでは、メモリの確保・ロック・例外を一切しません（途切れの原因になるため）。

## 3. 用語

| 用語 | 意味 |
|---|---|
| 五成分 | 直接（見えている分）・初期反射・後期（響き）・回折・透過。配分の単位。帳簿もこの 5 つで付ける |
| 帯域 | 125 / 250 / 500 / 1k / 2k / 4k Hz の 6 つ。量はいつも帯域ごとに持つ（`e6[6]`） |
| エネルギーと振幅 | Flow の中は全部エネルギー（振幅の二乗）。DSP へ渡す直前（`mix_to_voice.h`）で 1 回だけ √ を取る |
| タップ | 「いつ・どの向きから・帯域ごとにどれだけ」届く 1 本の到来。直接・透過・回折・初期反射がタップになる |
| 送り | 後期（響き）はタップにせず、部屋ごとの FDN へ「送る」 |
| FDN | 帰還遅延網。部屋ごとの響きを作る器。RT60 は部屋の形と材質から Sabine の式で出す |
| 方向バス・レーン | 耳のまわりの固定の向き（水平 8 本＋上下 2 本）。反射と響きはレーンに配ってから両耳にする（費用が音源の数に依らない） |
| 部屋・戸口（開口） | 形をボクセルに割って自動で見つける。くびれ（戸口）で部屋が分かれる |
| 見通し（visible） | 音源（幅を持つ円盤）がどれだけ見えているか 0..1。扉の縁で連続に変わる（半影） |
| 虚像（ISM） | 壁で音源を鏡に映した像。初期反射の向きと遅れを出す |
| mixing time | 初期と後期の境（部屋の平均自由行程の 3 倍 ÷ 音速、10〜120 ms） |
| Voice | 音源 1 本ぶんの DSP（`VoiceRenderer`） |
| 台帳 | ゲームのスレッドと音のスレッドの間の受け渡し（seqlock）。`acoustic_host.h` |
| 予算・段 | 総レイ数を固定し、音源を「厳密・簡易・保持」に分けて配る |

## 4. コードを読む前に知っておく決めごと

コードのあちこちにある「★」の理由は、だいたい次のどれかです。

1. **答えは 1 つ**。同じ量を 2 か所で決めない（例: 響きの長さは Sabine だけ。重みは配分の出口 1 か所だけで掛ける）。
2. **連続量に二値を置かない**。「見えたら 1、見えなければ 0」のような切り替えは段差（プツッ）になる。割合で持つ。
3. **形は空間から、量は耳で**。RT60・向き・遅れは形から出す。響きの量などの絶対値は、試聴して重みで決める。
4. **エンジンだけが音を計算する**。C#・Unreal・Wwise 側は値を渡すだけ。
5. **静止していれば毎フレーム同じ答え**。レイの乱数の種は音源ごとに固定（揺れない）。
6. **演出の摘みはエンジンの既定 0（物理どおり）、聞かせたい値は載る側が持つ**（先着の重み 6 dB・影のこもり 6 dB など）。
7. **Unity と Unreal は同じ形**。摘みは同じ名前・同じ既定値。決めた値は「Unity のスクリプトの既定・Unity の場面の保存値・Unreal の既定」の 3 か所に同時に書く。
