# 世界観

作成: 2026-08-19 / ゲームシステムレーン

草案書 v2 の §2 と §7 は**一方通行・順番固定**を前提にしていたが、
その後の判断で**ハブ構造**（扉は常設・ベルを集めると行き先が増える）に変わった。
この文書はその後の世界観を持つ。

**物語を書くものではない。** 草案 §9 の「テキストなし」方針は維持する。
ここで書くのは**画と音に出るところ**と、造形の判断材料だけ。

## 0. 芯

> **音が世界観を作る。**

これが全部の理由になっている。以下はそこから派生したもので、逆ではない。

### なぜ扉なのか

扉は誰でも知っているものだ。そして**基本的に閉まっていて、奥は見えない**。
けれど**音は漏れる**。

だから閉じた扉の前で、プレイヤーは**一度その奥を想像する**。
そして開けた瞬間に音が広がり、**想像との答え合わせ**が起きる。
思い描いたものに近い世界が見えたとき、それが嬉しさになる。

**これがこの作品の中心のループ。**

```
閉じた扉 → かすかに漏れる音 → 奥を想像する → 開ける → 音が広がる → 答え合わせ
```

★ **実装上いちばん重要な帰結**:
「かすかに漏れる」と「開けると広がる」は、**演出で作ってはいけない**。
§4.3 のフレネル帯域積分がまさにそれをやっている ──
隙間が狭いほど低域だけが通り、開くほど高域まで通る。
波長と開口幅の関係が音色に出る、というのが物理の答えで、
それを**そのまま体験の中心に据える**のがこの作品の主張になる。

### なぜベルなのか

1. **コール＆レスポンスで、いま自分がいる空間を音で分からせるため。**
   鳴らす→返る、の一往復が空間の測量になる。
2. **無人の幻想的な世界とベルの相性。**

### ★鳴らす動作は 1 つ。拾う前と後で鳴る物が入れ替わる

| | 鳴るもの | そこから分かること |
|---|---|---|
| **拾う前** | **落ちている断片だけ**（手持ちのベルは欠けていて鳴らない） | **経路**だけ ── 遅延・到来方向・こもり |
| **拾った後** | **自分のベル**（断片が戻った） | **自分の周りの空間**。音源が自分の位置に来るので |

手に入るのは行き先の鍵だけではない ── **聴くための道具**でもある。
「本来の力を取り戻す」が、テキストではなく**操作の変化**として出る。

副産物として、拾った時点で世界の音源が 1 本止まるので**フレームコストも下がる**
（実測でコストは「遮蔽された音源数」で効く）。

### 手触り

**アニメ調ではなく、異世界・幻想的。**

## 1. 設定

主人公は、**祭壇のような扉と別の世界とをつなぐベル**をもともと持っている。
そのベルは**欠けていて**、本来の力を失っている。

各世界に散っているのは「その世界のベル」というより、**同じものから分かれた力の断片**。
元が同じだから、**手持ちのベルを鳴らすと共鳴して、その世界の断片も鳴る**。

- 集めることは、**他の世界へ通じる資格を得ること**であり、
  同時に**自分のベルが本来の姿へ戻っていくこと**でもある
- 世界に人はいない
- 扉は世界に属さない。世界と世界の間にあるものが、そこに立っている

---

### 鍵の配置 — 進行は鎖、移動はハブ

**その世界に落ちているベルは、その世界の鍵ではなく「次の世界」の鍵。**

| 見つける場所 | 開くもの |
|---|---|
| 草原 | 崩壊都市 |
| 崩壊都市 | 洞窟 |
| 洞窟 | 雪山 |
| 雪山 | 海 |

自分自身の鍵をその世界に置くと、まだ行っていない世界へ永遠に行けなくなる（鶏と卵）。
一度開いた行き先は**溜まっていく**ので、**進行は鎖・移動はハブ**になる。

★**断片の声は「それが開く世界」の声**にした。結果として、
**まだ見たことのない世界の声を、いまいる世界で聞くことになる。**
§0 の「奥を想像する」が、扉の前だけでなく**探索している最中にも**効く。

## 2. 共鳴＝倍音（✅ 実装済み）

ベルは**非調和倍音の重ね合わせ**で合成している。
比は `0.50 / 1.00 / 1.19 / 1.50 / 2.00 / 2.55 / 3.01 / 4.10`。
鐘らしさの正体はこの非整数倍の並びで、**125Hz〜4kHz に満遍なく乗る**ようにしてある。

> **世界の断片＝プレイヤーのベルの倍音を 1 本ずつ抜き出したもの。**

| | 変更前 | 変更後（現在） |
|---|---|---|
| 手持ちのベル | 560Hz 固定・倍音 8 本 | **芯 2 本＋拾った断片の倍音だけ**が鳴る |
| 世界のベル | 世界ごとに勝手な基音（F4/A♯4/D♯5/G5） | **同じ 560Hz の倍音 1 本** |

| 断片の在り処 | 開く世界 | 倍音 |
|---|---|---|
| 草原 | 崩壊都市 | 1.19（短三度） |
| 崩壊都市 | 洞窟 | 1.50（五度） |
| 洞窟 | 雪山 | 2.00（ノミナル） |
| 雪山 | 海 | 2.55 |

芯（ハム 0.50 と基音 1.00）は失われていない。ここが無いと「同じベル」に聞こえない。

- **共鳴が本当になる。** 同じ音の一部なので、重なれば溶ける。「別の楽器が 2 つ」にならない
- **集めるほど音が豊かになる。** 進行の表示は**音そのもの**。数字も UI も要らない
- **音量は倍音の本数で変えない**（合成時に正規化）。
  減るのは「厚み」であって「大きさ」ではない。ここを揃えないと、
  欠けたベルが単に小さくなり、**距離の手がかり（レベル）に進行度が混ざる**

### 代償への対策 ── 打点の当たりを常設した

倍音を抜くと帯域が痩せる。欠けたベルは低域しか持たなくなり、
HRTF も帯域ごとの遮蔽差も効かなくなって**序盤が探索不能になりかねない**
（草案 §2 が「ベルは 6 帯域にきれいに乗る理想的なテスト信号」としているのは
倍音が揃っている前提）。

対策として、**撞いた瞬間の広帯域の当たりを倍音の本数と無関係に常設**した
（`AddStrike`。白色雑音を一極ローパス、e 折り 4ms）。

- **定位の手がかりは最初から確保**され、**響きの豊かさだけが育つ**
- 実際の鐘も撞点は広帯域なので、**演出ではなく物理として正しい**（決めごと #3 の側）

## 3. ステージ — 「音はどこにでもある」

> 時代・時間・季節・場所に関係なく、音はどこにでも存在する。
> だからいろんな景色を見せたい。

**世界どうしに時系列や地理のつながりは要らない。** 並列に置いてよい。
これは制約ではなく**自由**で、扉というモチーフがそれを許している。

| # | 世界 | 音響（確定） | 情景 |
|---|---|---|---|
| 1 | **草原** | 部屋 0・尾なし。直接音と HRTF だけ。α0.30 | 昼。無傷。扉が一枚だけ立っている。**基準** |
| 2 | **崩壊都市** | 屋根の残った建物だけが部屋になる。α0.15 / RT60 1.5s / rc 1.26m | 廃墟。風と水滴。**どの建物が生きているかが音で分かる** |
| 3 | **洞窟** | 食い違いの開口で直線が通らない。α0.038 / RT60 5.1s / rc 0.83m | 夜。灯りは手前だけ。**方向が嘘をつく** |
| 4 | **雪山** | 部屋 0・尾なし・高域から早期反射が消える。雪 α0.30〜0.92 | 夜。稜線の回折だけが頼り。**手がかりの喪失** |
| 5 | **海** | 未着手 | 潮汐案（草案 §6）。潮位で部屋グラフが割れ直す |

難易度としては 1→4 の並びだが、**ハブ構造なので順番は強制されない**。

## 6. 詰めるべき決定

倍音を実装したことで、**設定の穴が音の穴として見えるようになった**。
以下は「決めないと作れない」ものだけ。順に潰したい。

---

### 6-1 ★倍音が 2 本余っている ── 終わりの形はここで決まる

| 倍音 | 持ち主 |
|---|---|
| 0.50 / 1.00 | 芯（最初から） |
| 1.19 / 1.50 / 2.00 / 2.55 | 草原・崩壊都市・洞窟・雪山の断片 |
| **3.01 / 4.10** | **持ち主がいない** |

全部集めても**ベルは完全にならない**。これは設定の穴だが、
**そのまま終わりの形に使える**。案を 3 つ挙げる。

| 案 | 中身 | 効き |
|---|---|---|
| **A. 海が最後の断片を持つ** | 海に落ちている断片＝**3.01 と 4.10 の 2 本**。拾った瞬間ベルが 8 本すべてで鳴る | **終わりが音で分かる。** テキストも演出も要らない。いちばん芯（§0）に忠実 |
| B. 6 つめの世界 | 3.01 と 4.10 を別々の世界に割る | 尺が伸びる。作るものが増える |
| C. 余りを芯に含める | 最初から 3.01/4.10 を持たせ、断片 4 本で完成 | いちばん安いが、**完成の瞬間が薄い**（最後の 1 本が 2.55 の弱い倍音なので） |

→ **A を推す。** 海（§3 で「未着手・最後」）と役割が一致していて、
海の断片だけ**2 本ぶん一気に戻る**ので、最後の一撞きが明確に違う音になる。
海の断片が開くのは「次の世界」ではなく**元いた場所**、という形にできる。

**判断がほしい。**

---

### 6-2 ハブ構造は要るのか

いま**進行は鎖・移動はハブ**にしてある（§1）。だが正直に書くと:

- 鎖が一本道なので、**戻る理由が無い**
- §0 の「奥を想像する → 答え合わせ」は**初回訪問にしか効かない**。
  二度目の扉には想像の余地が無い

ハブが効いているのは実は 1 箇所だけで、**扉の前で断片を選んで鳴らす操作**。
行き先が 1 つしかなければ、この操作自体が消える。

| 案 | 中身 |
|---|---|
| **A. ハブは残すが、戻り先の中身は作らない** | 行き先選択の操作は残る。戻れるが、戻っても拾うものは無い |
| B. 一本道にする | 扉の行き先選択が消える。作るものは減るが、**鳴らして選ぶ**という一番ベルらしい操作を失う |
| C. 戻る理由を作る | 各世界に「後から取れるもの」を置く。**作るものが倍に増える** |

→ **A を推す。** 操作は残しつつ、作る量は増えない。

---

### 6-3 扉を開けたとき、奥は見えるのか ── ✅ 決定：**ちゃんと見える**（実装済み）

前室でごまかさない。**扉の向こうには本物の次の世界がある。**

張りぼてだと**答え合わせにならない**、というのが理由。
扉ごしに見えたものと、踏み越えた先が同じものでなければ §0 の芯が空回りする。

実装（`WorldPreview` / `WorldPortalView` / `WorldPortal.shader`）:

| | やっていること |
|---|---|
| 読み込み | 行き先が決まった時点で、次の世界のシーンを**追加読み込み**して 4000m 先へ置く |
| 描画 | プレイヤーのカメラを扉の基準 → 向こうの基準へ写像し、そこから RenderTexture へ描く |
| 貼り方 | 開口の板が**スクリーン座標で**サンプルする（板の UV で貼るとテレビ画面に見える） |
| 空気 | `Camera.Render()` の前後で空・霧・環境光を向こうのものへ差し替えて戻す |

★**開き具合に応じた「見える量」は作っていない。**
板は開口の面に固定で、扉の板と枠が普通に手前を塞ぐだけ。
隙間が細ければ細い帯しか見えない ── **§4.3 が音でやっていることの、画版**。

★**音響には一切触れていない。** 追加読み込みした世界はコライダーを全部無効化してある
（`CollectOccluders` は `!enabled` を弾く）ので、部屋グラフの格子は 1 ボクセルも増えない。
音の部品（`AudioSource` / `VoiceConvolver` / `AmbientSource` / デモ本体）も剥がしてある。

### 6-4 手触り ── ✅ 決定：**静かだが幻想的。自然を感じるように**

**ホラーには倒さない。** 失敗も、音を奪う仕掛けも作らない。

反映したところ:

| | |
|---|---|
| 空気（`WorldSky`） | 色は自然界にある範囲。**夜の世界も真っ暗にしない**（雪山は雪の照り返しで明るい） |
| 霧 | 怖さではなく**奥行き**のために使う。距離の手がかりになる |
| 環境音 | 全部が自然の音（風・葉擦れ・水滴・鳥・川）。**葉擦れ**を新規に追加 |
| 扉から漏れる音 | 世界ごとに「看板になる自然音」を 1 つ（草原=鳥 / 崩壊都市=葉擦れ / 洞窟=水滴 / 雪山=風） |

⚠ 環境音を足すと必ず**ベルを消す方向に働く**ので、量は世界ごとに変えてある:

| 世界 | 環境音 | 理由 |
|---|---|---|
| 草原 | 風・鳥（控えめ） | **基準の世界**。直接音と HRTF だけで探させる設計を壊さない |
| 崩壊都市 | 風・水滴・葉擦れ | 自然に還りつつある廃墟。いちばん厚くてよい |
| 洞窟 | 水滴のみ | **実測 14.41ms / 56fps でいちばん高い世界**。遮蔽された音源が高くつく |
| 雪山 | 風のみ | 主題が「手がかりの喪失」。環境音まで豊かにすると喪失感が消える |

葉擦れは 1k〜4kHz に居座って**ベルの打点の当たりと正面衝突する**ので、
定常には鳴らさず突風で切れ切れにして必ず谷を作ってある。音量で殴らない。

## 7. 広さと境界

### 7-1 広さ ── 変えなくてよい

**5 分は歩く時間ではなく、探す時間。** ここを取り違えると世界が無駄に広くなる。

| 世界 | 遊べる範囲 | ベルまで | 端から端まで歩く時間 |
|---|---|---|---|
| 草原 | 46 × 56 m | 27 m | 約 14 秒 |
| 崩壊都市 | 46 × 66 m | 41 m | 約 17 秒 |
| 洞窟 | 40 × 72 m | 44 m | 約 18 秒 |
| 雪山 | 60 × 80 m | 52 m | 約 20 秒 |

移動速度 4 m/s（Shift で 10 m/s）なので、**どの世界も 20 秒で横断できる**。
5 分の中身は

```
鳴らす → 最大 3 秒待つ → 返りの方向と遅延を読む → 少し動く → もう一度
```

の往復 10〜20 回。**歩く時間がコストになってはいけない**ので、これ以上広げない。
広げると「音で探す」が「歩き回る」に化ける。

★逆に、**5 分が短すぎるなら広さではなく崩し方で伸ばす**
（崩壊都市の「開口が +X 側だけ」、洞窟の食い違いの開口のような）。
広さは往復の回数を増やさず、1 回あたりの移動時間だけを増やすので効率が悪い。

### 7-2 境界 ── 見えないコライダーは使わない

**理由が音にある。**
デモは `BoxCollider` と `MeshCollider` をシーン全体から拾ってオクルーダーにする。
見えない壁を箱で置いた瞬間、それは**音響的に本物の壁**になり、
何も無いはずの場所から早期反射が返る。
「音が世界を伝える」作品で、見えない物が聞こえるのは端的に嘘になる。

だから 2 段構えにした。

| | 何が閉じるか | 音では |
|---|---|---|
| **本筋（造形）** | 丘・岩・稜線・瓦礫。**その世界の形で自然に閉じる** | 聞こえる。反射も回折も正しく返る |
| **保険（`WorldBounds`）** | 座標の押し戻し。隙間をすり抜けた／登った時だけ効く | **何も起きない**（無音） |

★**草原だけは壁で囲んではいけない。**
草原は「部屋 0 個・遮蔽なし・直接音と HRTF だけ」が役目の基準世界。
縁に垂直な壁を立てると早期反射が返り、その役目が壊れる。
→ **緩やかな丘で閉じる。** 丘は地面であって壁ではないので、
部屋にもならず（屋根が無いと部屋にならない・`2e63c46`）、反射も遠く弱い。

★押し戻しは**連続**（決めごと #2）。
境界の手前 4m から抵抗が滑らかに増え、境界には決して届かない。
カクンと止まると「見えない壁」の手触りになる。

### 7-3 ★ついでに見つかったこと ── いままで壁をすり抜けていた

`AcousticFlowSceneDemo.HandleMovement` は

```csharp
listener.position += move * speed * dt;
```

の直接代入で、`CharacterController` も `Rigidbody` も使っていない。
つまり**建物の壁も扉の板も素通りしていた**。デモとしては正しい（音の検証が目的なので）が、
ゲームとしては成立しない。

`WorldBounds.solidWalls` が `Physics.ComputePenetration` で押し出す。
サウンドシステムには触っていない（`LateUpdate` で位置を上書きする、
`PinPosition` / `FollowTransform` と同じやり方）。

★**ぶつかる相手を `BoxCollider` と `MeshCollider` だけに絞ってある。**
これはデモがオクルーダーとして拾う条件と**同じ**。
結果として「**聞こえる物にだけぶつかる**」が保証される ──
音では素通りなのに体は止まる、という食い違いが原理的に起きない。

## 8. 立ち上げ手順

**順番が大事。** `Build Settings に登録` はステージ生成の**後**でないと空振りする
（まだファイルが無いものは黙って飛ばす実装なので、エラーも出ない）。

### 一度だけやること

| # | メニュー | 何が起きるか | 飛ばすとどうなるか |
|---|---|---|---|
| 1 | `BellGame/Assets/1 マテリアルを作る (CC0 テクスチャから)` | 岩・雪・草・木扉などの材質を作る | 全部が白いマテリアルになる |
| 2 | `BellGame/Assets/2 スカイボックスを作る (HDRI から)` | `Sky_Day` / `Sky_Night` を作る | 空が**手続き生成の簡易な空**に落ちる（動きはする） |
| 3 | `BellGame/セットアップ/1. ポータル用レイヤーを作る` | `WorldPreview` レイヤーを 8 番以降の空きに作る | **扉の奥が描かれない**。実行時に警告が出る |

### ステージを作る（生成器を変えたので全部作り直し）

| # | メニュー |
|---|---|
| 4 | `BellGame/Stages/1 草原 (Grassland)` |
| 5 | `BellGame/Stages/2 崩壊都市 (Ruins)` |
| 6 | `BellGame/Stages/3 洞窟 (Cave)` |
| 7 | `BellGame/Stages/4 雪山 (Snow)` |

各メニューは**新しいシーンを作って保存する**ところまでやる。開いているシーンは閉じられる。

### 最後にもう一度だけ

| # | メニュー | なぜ最後か |
|---|---|---|
| 8 | `BellGame/セットアップ/2. ステージを Build Settings に登録` | **4〜7 でファイルが出来た後**でないと登録できない |

`Stage5_Sea` はまだ無いので、雪山の扉（行き先＝海）だけは
「シーンが Build Settings に無い」と警告が出て、奥が描かれない。**それで正しい。**

### 遊び方

`Assets/Scenes/Stage1_Grassland.unity` を開いて再生。

| 操作 | |
|---|---|
| WASD / 右ドラッグ | 移動・視線（Shift で 2.5 倍速） |
| **Space** | ベルを鳴らす。**拾う前は落ちている断片が、拾った後は自分のベルが鳴る** |

| 扉の前で閉じたまま Space | いま選んでいる断片の行き先へ扉を繋ぐ |

### 上手くいかないときに見るところ

| 症状 | 見るところ |
|---|---|
| 扉の奥が真っ黒／何も見えない | 手順 3 と 8 を実行したか。`WorldPortalView` の `drawing` と `WorldPreview` の `ready` |
| 扉の奥が本編と同じ空の下に見える | `WorldSkyLibrary` がシーンに居るか（手順 2 → 4〜7 の順でやり直す） |
| 扉の奥が「テレビ画面」に見える | `WorldPortal.shader` が見つかっていない（`Unlit/Texture` に落ちている）。Console に赤字が出る |
| フレームが落ちる | `WorldPortalView.resolutionScale` を下げる。それでも重ければ**音源数**を疑う（実測でコストは遮蔽された音源数で効く） |
| 壁をすり抜ける／出られない | `WorldBounds` の `solidWalls` と `softMargin` |
| ベルが鳴りっぱなし | `BellCallResponse.worldBellLoopClip` に何か入っている（聴き比べ用。空にする） |

★**ビルドするときは `WorldPortal.shader` を Project Settings > Graphics の
Always Included Shaders に入れること。** どのマテリアルからも参照されていないので、
そのままだとビルドから落ちて `Shader.Find` が null を返す。エディタ再生では起きない。
