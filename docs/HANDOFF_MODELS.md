# 造形レーン 引き継ぎ（見た目のメッシュ担当）

このレーンが受け持つのは **見た目のメッシュだけ**。音響には一切関わらない。

- 作業場所: `tools/StageModelGen/`（生成器）と `UnityDemo/Assets/Models/`（出力）
- 触らない場所: `AcousticEngine/`, `UnityDemo/Assets/Scripts/AcousticFlow/`,
  `UnityDemo/Assets/Scripts/BellGame/Editor/BellGameStages.cs`

進行と要求は [GAME_SYSTEM_BOARD.md](GAME_SYSTEM_BOARD.md) が持つ。**作業前に読むこと。**

---

## ★踏んではいけない線（3 つ）

### 1. コライダーを付けない

`AcousticFlowSceneDemo.CollectOccluders` が拾うのは **BoxCollider と MeshCollider だけ**。
コライダーが無いメッシュは部屋グラフにもエコグラムのレイにも入らない。

これが成立しているおかげで、**音響はブロックアウトの箱が担当し、見た目は自由に作れる**。
仕様書 §7.6「メッシュ壁は跨ぎ判定が使えず幻・崖が残りうる」も踏まずに済んでいる。
コライダーを 1 つ付けた瞬間にこの分離が壊れる。

配置は `BellGameStages.PlaceVisualMesh` が行い、
念のためコライダーを剥がし、覆われる箱の **Renderer だけ** 切る（コライダーは残す）。

### 2. 寸法をブロックアウトと一致させる

音響側の寸法は **RT60・臨界距離・部屋の割れ方**を決めている。見た目の都合で動かすと音が変わる。

| ステージ | 音響側の寸法（`BellGameStages` が真） |
|---|---|
| 神殿 | 外殻 内寸 20×24m・高さ 8m・厚み 0.4m、中心 (0,0,2) → 内側 x ±10 / z −10..14 |
| | 入口 −Z 中央に 1.1×3.0m ／ 仕切り z=−4 中央に 1.1×3.0m |
| | 列柱 x=±6、z=0,4,8,12 の 8 本。1.0×1.0×8.0m ／ 屋根 y 8.0..8.4 |
| 洞窟 | 外殻 内寸 24×40m・高さ 4.5m・厚み 0.5m、中心 (0,0,6) → 内側 x ±12 / z −14..26 |
| | 入口 −Z 中央に 0.9×2.2m ／ 仕切り z=−6/4/14、開口の x は −8/+8/−8（食い違い） |
| 雪山 | 地面（見た目）110×110m ／ 稜線 3 本・露岩 2 個は `Stage4Snow` の座標に一致 |
| 扉 | 枠 1.1×2.2m、柱と まぐさ 厚み 0.25m。**板は生成しない**（物理で回る別オブジェクト） |
| ベル | 原点＝鐘の胴の中心。音源が y=1.2 に置かれるのでそこに合わせてある |

**変えたくなったら board に書いて、ゲームシステム側と合わせること。**片側だけ動かさない。

### 3. UV は 1 ワールドメートル = 1 タイル

`ObjWriter.AddPolygon` が面の主軸で平面投影して自動で付ける。
マテリアル側（`BellGameDressing`）はこの前提でタイリングを決めているので、
別の付け方をすると全ステージのスケールが狂う。

## 道具

```bash
dotnet run --project tools/StageModelGen -- UnityDemo/Assets/Models
```

dotnet SDK 10.0.300 で動作確認済み。Python は入っていない（スタブ）。

### `ObjWriter.cs`

| API | 用途 |
|---|---|
| `m.Group(name, material)` | 以降の面をこの群・このマテリアルに |
| `m.AddPolygon(params V3[])` | 凸多角形を 1 面。**巻き方向は外向き法線になる順**（`cross(p1-p0, p2-p0)`） |
| `m.AddBox(min, max)` | 軸平行の箱。6 面 |
| `m.Write(path, mtlName)` | OBJ を書く |

面ごとに法線を出す（フラットシェーディング）。建築のブロックアウトなので、
柱の溝も岩肌もエッジが立っていたほうが陰影が出る。

### `Noise.cs`

`Noise.Fbm(p, freq, octaves, gain, lacunarity)` → −1..1。

**決定的であること**が要件。乱数だと生成のたびに形が変わり、
「見た目を直したら音が変わったように聞こえる」錯覚のもとになる
（実際には音響は箱が持っているので変わらないが、切り分けが面倒になる）。

### `Preview.cs`

`Preview.WriteSvg(m.Faces, path, w, h, yaw, pitch)` で SVG のプレビューが出る。
画家のアルゴリズム＋平行光の平坦シェーディング。**裏を向いた面は描かない**ので、
巻き方向の間違いもここで気づける。Unity に取り込む前に必ず 1 回見ること。

### 既存の部品（使い回せる）

`DisplacedPlane`（矩形をノイズで押し出す・開口をスキップ可）/ `SnowRidge` /
`Boulder` / `FlutedShaft`（溝彫り）/ `Prism` / `Taper` / `CircleRing` / `Blob` /
`Gable` / `WallWithOpeningX` / `LegQuad`

## マテリアル名（`BellGameDressing` と一致させること）

`.mtl` の `newmtl` 名がそのまま Unity のマテリアル名として照合される。

**テクスチャあり**（ambientCG の CC0・PBR 5 枚組）
`Stone_Wall`(トラバーチン) / `Stone_Column`(大理石) / `Stone_Roof` / `Temple_Ground` /
`Cave_Rock` / `Cave_Ground` / `Snow_Ground` / `Snow_Ridge` / `Snow_Rock` / `Grass_Ground`

**テクスチャなし**（色＋金属感だけ）
`Bell_Bronze` / `Wood_Beam` / `Wood_Door` / `Fire_Coals`（自己発光）

新しい名前を足したら `BellGameDressing.kMaterials` か `kPlain` にも足すこと（board 経由で依頼）。

## 頼みたいもの（優先順）

1. **草原の草木** — 草株・低木・小石。`Grass_Ground` の上に散らす。
   草案 §4.3 は草原を「遮蔽物がなく、地面もそこそこ反射する」基準の世界としているので、
   **背の高い遮蔽物は置かない**（音響側は箱で持っていないが、見た目が音と食い違う）
2. **洞窟の意匠** — 鍾乳石・石筍・岩の層理。いまは変位ノイズだけで単調
3. **雪山** — 吹き溜まりの縞、樹氷、露岩の割れ
4. **神殿** — 破風の彫刻、床の敷石、柱頭の意匠
5. **扉** — 枠の彫り。板は物理で回るので別（いま無地の箱）

見た目の密度を上げるのはどれも自由。**寸法とコライダーの線だけ守れば音は変わらない。**

## 音響側の事情（知っておくと判断が早い）

- 音響は箱で持っている。見た目のメッシュは**一切参照されない**
- ステージごとの性格（board にもある）:
  草原＝生の音 / 神殿＝反響と残響（RT60 1.4s・rc 2.6m）/
  洞窟＝回折の方向性（RT60 5.1s・rc 0.83m）/ 雪山＝乾いた音
- **ベルの在り処が見えてしまう飾りは置かない。**
  音で探すゲームなので、灯りや目立つ造形でベルの位置が分かると音響が飾りになる。
  火鉢を最奥に置いていないのはそのため
