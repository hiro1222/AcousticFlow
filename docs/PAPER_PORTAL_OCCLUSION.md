# 論文の読み取り: Dynamic Portal Occlusion（arXiv 2107.11548）

Nikunj Raghuvanshi, "Dynamic Portal Occlusion for Precomputed Interactive Sound Propagation"
（arXiv:2107.11548、6 ページ、IEEE TVCG Short papers 投稿予定）。
Microsoft の Project Acoustics 系。**実装はしていません。**何が取れて何が取れないかの判定だけです。

## 土台が違う

論文は**焼いた波動場**が前提です。音源・リスナーの各点対に対して、初期遅延 τ₀・初期音量 L・
初期方向 s₀・6 軸の間接音量 Rⱼ を焼いておき、実行時は引くだけ。扉はその**摂動**として扱います。

こちらは実行時の幾何で、焼くのは構造だけです（`BAKE_RUNTIME_LAYERS.md`）。
したがって論文の骨格 ── 場の引き当て、見かけの位置の string-tightening、補間誤差を
25 ms から 10 ms へ詰める話 ── は**そのままは入りません**。

取れるのは、扉を「開口率 α のポータル」として扱う部分の**式の作り方**です。
そこは土台に依りません。

## A. 尾の「量」が扉に応答しない ── 論文に答えがある（いちばん効く）

今日測って分かったこと（`DOOR_LAG.md`）。扉を 0° → 60° に開けると

- エコグラム（尾の材料）は **+17.1 dB** 動く
- 尾の比（＝尾の量）は **−0.20 dB しか動かない**

尾の**形**は扉に反応しているのに、**量**は反応していません。量は
`freeFieldDirect × √tailRatio × tailSrcLevel` で決まり、`tailRatio = (r/rc)²` は
部屋の体積と RT60 から出るので、扉が動いても変わらないためです。

論文は間接音の量をこう更新します。

```
Eₖ(x′,x) ≈ A(Oₖ)/(4π) · E(x′,xₖ) · E(x,xₖ)      … ポータル κ を通る間接エネルギー
Rⱼ ← 10 log₁₀ max{ β·Eⱼ ,  Eⱼ − (1−α)·Eⱼᵏ }      … β = 0.01
```

読み方は「**残響全体を α 倍するのではなく、そのポータルに帰属する分だけを (1−α) 引く**」。
引きすぎて完全に消えないよう、除去は 99% で頭打ちにします。

これはこちらの穴にそのまま当たります。いまは「形はエコグラムから、量は部屋の統計から」と
出どころが分かれていて、扉が量に効く経路がありません。**量の側にもポータル帰属の項を作る**、
というのが取れる考え方です。

- **どのピラーに効くか**: 「音の変化」に直接効きます。扉を開けたときに響きの量が動くのは、
  コンセプト（扉が開くときの音色の変化）の中心です。
- **傷める恐れ**: 尾の量は歩行の連続性の担保に絡みます（`walk-continuity-guarantee`）。
  ポータルに帰属する量が不連続に変わると、そこがそのまま段になります。

## B. 6 軸の指向性残響 ── 穴 #5 への直接の答え

論文は間接音を**6 軸の球面分布（cos² 基底）**として焼き、ポータル越しのぶんはこう配ります。

```
Eⱼᵏ(x′,x) = Eₖ(x′,x) / E(xₖ,x) · Eⱼ(xₖ,x)
```

つまり**ポータルを通ってきた残響は、ポータルの方向の分布を持つ**。

こちらの尾は方向の構造を持ちません（穴 #5）。あるのは方向プローブから作る
左右の帯域ゲイン（`_tailEarBandGain`）だけで、上下も前後もありません。
6 軸の分布は、その素直な拡張です。方向バスが既に「方向 × 耳のレーンへ振って
固定 HRIR で畳む」形なので、**尾も同じレーンへ流せば器はそのまま使えます**。

- **どのピラーに効くか**: 「空間印象」。そして「響きが戸口の方から来る」は
  コンセプトそのものです。いまは左右しか持っていないので、正面の戸口が出せません。
- **傷める恐れ**: 尾の方向はいま**いちばん遅い経路**です（追従 250〜317 ms、`DOOR_LAG.md`）。
  方向の情報量を増やすなら、その遅さが先に問題になります。順番としては追従が先です。

## C. 扉が閉じたときの RT60 の分離 ── 論文が「できていない」と書いている所

論文の限界として挙げられているのが、ポータルが閉じたときの**部屋どうしの残響時間の分離**です。
一次の摂動なので、扉を閉めても各部屋の RT60 は焼いたときのままになります。

**こちらは同じ穴を持っています。**部屋グラフは開口を吸音率 1 として数えますが
（`room_graph.h`）、扉は「動くもの」として静的な塗り分けから外してあるので、
**扉を閉めても開口は吸音率 1 のまま**です。閉じた部屋が響かなくなりません。

ただしこちらには部屋グラフがあります。開口の吸音率に開口率を掛ける、
つまり `α_開口 = α`（開いていれば穴、閉じていれば扉の材質の吸音率）にすれば、
Sabine の和がそのまま変わり、**両側の部屋の RT60 が扉で動きます**。
論文の枠組みには部屋という概念が無いので、この道は取れません。
**論文より先へ行ける可能性があるのはここだけです。**

- **どのピラーに効くか**: 「空間印象」。閉めた部屋が響き出すのは、広さの手掛かりとしても効きます。
- **傷める恐れ**: RT60 が動くと mixing time（√V）は動きませんが尾の比は動きます。
  扉の開閉のたびに部屋の RT60 が動くので、`roomBuilder_` の再構築の頻度と、
  尾の作り直し（133 ms 刻み）に乗るかを先に見る必要があります。

## D. 開口率は帯域に依らないスカラ ── 今日の差し戻しの裏付け

論文の α は**開口面積の割合というスカラ 1 個**で、帯域を持ちません。直接音は

```
L ← L + 10 log₁₀ α
```

だけです。帯域の色は材質の透過が持ちます。

今日 `apertureLaw` を 1 → 0 へ戻した判断（高域が抜けすぎ）と、
半影モード 3（透過の空間の重みを帯域に依らせない）は、どちらもこの向きです。
**「開口の幾何は帯域に依らせず、色は材質に持たせる」**が、出荷されている系の作りでした。
いまの既定はその形になっています。

## E. ポータルの絞り込み ── 規模が増えたときの安い足切り

最短回折経路の上にあるポータルだけを選ぶテストです。音源とリスナーを焦点とする
楕円体で切り、法線の向きで切り、経路が実際に矩形を貫くかで切ります。

```
|x̃′ − x̃ₖ| + |x̃ − x̃ₖ| ≤ c·τ₀(x′,x) + c·ε      （ε ≈ 10 ms）
```

こちらは毎更新で全ポータルに `portalOpenBands` を掛けています。ポータルが増えたら、
この楕円体テストは焼いた場が無くても書けます（回折経路長は稜線カタログから出る）。
**いまの規模では要りません。**覚えておく話です。

## F. 未確認 ── 直列するポータル

論文は直列するポータルを掛け算で合成します（α = ∏αₖ）。
こちらが扉を 2 枚またぐ経路でどうなっているかは**確認していません**。
`addPortalEchogram` はポータルごとに独立に足しているので、直列で圧縮されない可能性があります。
測るなら扉 2 枚の廊下を作って、1 枚閉じたときと 2 枚閉じたときの差を見ます。

## 取らない所

- 焼いた場の引き当て（τ₀ / L / s₀ / Rⱼ）と、見かけの位置の string-tightening、補間の改善。
  土台が違うので入りません。
- α の下限 0.001（−30 dB）というクランプ。こちらは複合透過損失
  `τ_eff = (1−a)·τ_leaf + a` で床が**物理から**出ます。クランプより素直なので、
  ここは変えません（むしろこちらの利点として資料に書ける所です）。

## 順番の見立て

C（部屋の RT60 が扉で動く）→ A（尾の量が扉に応答する）→ B（尾の 6 軸方向）。
C は部屋グラフがあるので一番安く、効きが大きい。A は C を入れると一部が自動で付いてきます
（開口の吸音率が変われば RT60 が変わり、尾の比も動く）。B は追従の速さを先に片付けてからです。
