# 回折の設計

> 状態: **設計確定・実装前**（2026-08-03）。着手は メッシュ → プローブ場 → **ここ** の順。
> 旧 `DIFFRACTION_UTD.md` を置き換える。UTD を音声経路から外した経緯は `DEV_LOG.md` G章。

---

## 1. 目的

**回折の目的は「遮蔽感」と「開口部の方向」を伝えること。**
どのあたりから、どこから音が聞こえてきているか。

**回折そのものの物理的な精度は目的ではない。**

この一文から以下すべてが導かれる。作品のコアが「周辺環境の変化を音で伝えること」であり、
個別現象の厳密性ではないため（`MEMORY.md` / portfolio-core-spatial-awareness）。

---

## 2. 出力

```cpp
struct DiffractionPath {
    Vec3  aperture;     // 鳴らす位置 = 音が抜けてくる開口。定位に使う
    float pathLength;   // listener → aperture → source の実長。遅延と距離減衰に使う
    float gain[6];      // 帯域別の減衰（前川の式・符号付き δ）
};

int findDiffractionPaths(const Vec3& listener, const Vec3& source,
                         DiffractionPath* out, int maxPaths) const;
```

**呼び出しは 1 回。音声タップも遮蔽感もこの結果だけを読む。**

現状は `diffractionContinuous`（ゲイン用）と `computeDiffractionSources`（方向用）が
別々に稜線を歩き、別々の重み・別々の上限を持っている。この重複が定数の食い違いと
挙動の不一致を生んでいるので、構造で消す。

持ち回る情報は上の 3 つだけ。UTD が必要としていたウェッジ幾何（入射角 φ'、回折角 φ、
ウェッジ角 n、Keller コーン角 β0）は**一切要らない**。非目標（§4）で精度を捨てたため。

---

## 3. 保証する性質

要件（§1）から直接出てくるものだけ。すべて回帰テストで固定する。

| # | 性質 | なぜ要るか |
|---|---|---|
| 1 | **連続性** — 何が動いても aperture も gain も飛ばない | 最優先。**不連続は「間違い」として聞こえる**が、数 dB のレベル誤差は気づかれない |
| 2 | **到達可能性** — aperture は実際に音が抜けてくる場所を指す | 壁を貫いて到達する稜線を開口と誤認していた（実機で観測） |
| 3 | **集中** — 開口が 1 つなら重みがそこに集まる | ぼやけると方向が伝わらない＝目的を満たさない |
| 4 | **周波数** — 低域ほど回り込む | **遮蔽感の正体はハイ落ち**。6 帯域ゲインがそのままローパスになる |
| 5 | **境界の一致** — 直接見通せる状態へ連続に繋がる（gain → 1.0） | ドアが開き切る瞬間に段差を作らない |

性質 1 は前川の式を使うことで**構造的に**保証される。δ は全候補の min を取っても連続で
（min は連続性を保つ。argmin が入れ替わっても値は飛ばない）、gain は δ のみの関数だから。
平滑化も重み付けも不要。

---

## 4. 非目標（明示的に捨てる）

- **回折レベルの物理的精度** — 数 dB のずれは問わない
- **3 次以上の回折**
- **別の部屋の音源を回折経路で追うこと** — 透過 ＋ 残響結合が担当する

3 つ目は、屋内マルチルームを回折で解こうとすると大域構造（プローブ網・ポータルグラフ）が
必要になり、**「ベイクなし・完全動的」という作品の主張と衝突する**ため。
知覚的にも、3 部屋先の音が「どの角から回り込んでいるか」を人は聞き分けない。
「壁越しにこもって聞こえる」で足りる。

## 5. 決定事項

### 5-1. モデルは前川の式（`Core/maekawa.h`）

符号付き δ のみの関数。影で正・境界で 0・照射側で負。境界では両側 5dB に収束して連続。
N = 2δ/λ が波長で割るので高域ほど減衰が強く、性質 4 が自動的に満たされる。

UTD を採らない理由と実測値は `DEV_LOG.md` G-3〜G-5。要点だけ：
UTD は回折点の 3D 幾何に依存するので稜線が入れ替わると飛ぶ。重み付き平均・複素和・
エネルギー加算をすべて試して、最良 3.8dB / 最悪 17.6dB の段差が残った。前川は 0.35dB。

### 5-2. 次数は 1 次のみ

当初 2 次まで扱う予定だった（再帰的な開口探索）。しかし §4 で「別の部屋は透過＋残響」と
決めた時点で、2 次の担当範囲がほとんど残らない（L 字廊下の角程度）。
必要になったら再帰で足せる設計にはしておくが、初版は 1 次。

### 5-3. 開口の探索は稜線ベース。プローブは使わない

検討して却下した案：

| 案 | 却下理由 |
|---|---|
| **サンプリング**（扇状にレイを飛ばし、通った方向を開口とする） | **問題設定がずれている**。サンプリングは「直線が通る場所」を見つける手法だが、回折は「直線が通らないとき」の現象。屋内では 1 本も通らず、例外処理が本体になる。音源ごとに扇が要るのでスケールもしない |
| **ポータル**（空間に開口部を定義） | 事前オーサリングは動く形状と両立しない。実行時の自動抽出は重い前処理を要する難問 |
| **プローブ可視グラフ**（Steam Audio の pathing 相当） | 1 次回折には方向解像度が足りず（格子間隔で量子化される）、2 次以上は §4 で担当外にした。**担当範囲が残らない** |

SH プローブ場は**後期残響専用**として別途導入する。SH は方向分布を表せるが時間構造を
表せないので、正確な遅延が要る直接音・早期反射・回折には使えない。

### 5-4. 到達可能性は「貫通長」で判定する

回折点の可視判定で、その稜線を持つ箱を**丸ごと除外してはいけない**。
大きな壁で「壁を何メートルも突き抜けて遠い稜線に達する経路」が開口と誤認される。

一方、単純に「交差＝無効」にもできない。**厚みのある壁の稜線を回る経路は、幾何的に必ず
その厚みぶんを貫く**ため、正しい経路まで消える。

→ 分けるのは「通るか否か」ではなく **「どれだけ通るか」**。
箱のいちばん薄い方向を抜けるぶんまでは回り込みとして許し、それを超える貫通は棄却する。
`aabb.h` の `segmentObbPenetration()`。

### 5-5. メッシュ対応時も回折は簡略プロキシ（箱）で扱う

- **レイトレース（遮蔽・反射）** → メッシュ + BVH
- **回折** → 簡略プロキシ（箱）

メッシュにそのまま稜線回折を持ち込むとシルエット稜線の動的抽出が要り重い。
Wwise が「音響用に簡略化したジオメトリを与えてください」と要求しているのと同じ割り切り。
副次的な利点として、**回折の実装がメッシュ対応で壊れない**。

### 5-6. 遮蔽感は透過と回折を一本化する（要レビュー）

```
遮蔽感 = 透過 + Σ path.gain
```

現状は「透過 ⊕ 回折」を別々に出し、見通し状態を判定して max か diff かを切り替える分岐が
入っている（`AcousticFlowSceneDemo.cs` の `_directBands` 周辺）。
`findDiffractionPaths` の合計ゲインが「回り込んで届く総量」そのものなので、その分岐は消える。

### 5-7. 開口 0 本のときは透過のみ（要レビュー）

完全に囲まれていて回り込みも無い場合、透過だけが届く。
④キーで封鎖した部屋の外の音がこれにあたる。**透過だけで正しい。**

## 6. 未決事項

### 6-1. 開口を「同じもの」と見なす基準

現状はリスナーから見た方向 25° 以内で融合している。
ドアと窓が近いと 1 つに融合してしまう。複数開口を出したい（要件）ので、この基準は効く。
**実験しながら調整する**方針（数値を先に決めない）。

### 6-2. 前川の式は「衝立」のモデルであって「開口」のモデルではない

見通せているのに低域に挿入損失が乗る（§7-1 の「開き切り 0.611」）。

前川の式は半無限スクリーンの挿入損失の実験式で、受音点が照射側にあるとき
（N が負、−0.2 < N < 0）も 0〜5dB の減衰を与える。単独の衝立ならこれは妥当だが、
**戸口のように両側に縁がある「開口」では成り立たない**（Babinet の相補性で挙動が反転する）。
現状は最小 δ の縁 1 本を衝立とみなすので、開口の中心に立っていても減衰が残る。

知覚上は「**見通せているのにこもって聞こえる**」ことになり、要件（遮蔽感を伝える）に反する。
遮蔽していないのに遮蔽感が出るのは、目的から見て最も避けたい誤りである。

対処の候補（実装時に決める）：

- **照射側では減衰を掛けない**（δ<0 なら gain = 1.0）。単純だが境界で 0.56 → 1.0 の段差が出る
- **開口の両縁を見て、両方から「照らされて」いれば減衰を打ち消す**。物理的には正しい向きだが、
  「開口である」ことを検出する必要がある
- **照射側の減衰を δ でフェードアウトさせる**（境界で 0.5、少し離れたら 1.0）。
  性質 1 と 5 の両方を満たす最小限の手当て。まずこれを試す

**これは §3 性質 5 の合格基準（開き切りで 125Hz > 0.9）に直結する。**

## 7. 検証：スイングドア

要件の 5 性質を**一度に**検証できる唯一のシーン。回帰テストとデモ動画を兼ねる。

押して開くドア。蝶番で回転し、開くにつれて直接聞こえる角度範囲が広がる。

- 隙間が開き始めた方向の音源 → 早い段階からダイレクト
- 振れた扉の板が覆う側の音源 → 扉が振り切るまで透過のまま

扉の角度を 0°→90° に連続に振り、各角度で測る。

| 測るもの | 対応する性質 |
|---|---|
| aperture が隣接角度で飛ばないか | 1 連続性 |
| aperture が扉の板の裏を指さないか | 2 到達可能性 |
| 支配クラスタの重み | 3 集中 |
| 低域 > 高域 | 4 周波数 |
| 直接見通せる角度で gain → 1.0 に繋がるか | 5 境界の一致 |

**このシーンは作品の主張そのものでもある。**
扉の角度ごとに音場が変わるのは、Project Acoustics が原理的にできず（角度ごとに焼き直せない）、
Wwise なら手動オーサリングを要求する領域。ベイクなしの価値を 1 シーンで示せる。

### 7-1. 現行実装のベースライン（2026-08-03 実測）

| 5 定位の維持 | **75° 以降 開口 0 本** | 消えない | 未達 |

読み取れること：

- **開口位置が 7.5° 刻みで階段状**（同じ値が2回続いて跳ぶ）。扉に追従していない。
  0°→15° では y が 4.53 → 1.60 と **3m 飛ぶ**。扉の上を越える経路から横を回る経路への乗り換え。
- **75° 以降、減衰が残っているのに開口が 0 本**になる。
  **見通しが開通した瞬間に定位が消える** ── 最も定位が効いてほしい場面で情報が無くなる。
  原因は §2 の重複：ゲイン側は `blockerMargin` を広げて候補を探すが、方向側は既定の 0 のまま。
- **開き切っても 125Hz が 0.611**。原因は §6 の未決事項に記載（衝立モデルを開口に適用している）。

**未達は `check()` にしていない。** 「壊れた」ではなく「まだ作っていない」なので、
赤いままのスイートは信用されなくなるため。作り直しのときに目標値をそのまま `check()` へ格上げする。
