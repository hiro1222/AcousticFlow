# 紹介資料に入れる画像 ── 撮影リスト

参考にした型は「敵の知覚 AI をデバッグ描画で見せる」やり方（AT13C629 の p04）。
**音は目に見えないので、経路と計器を描いたものを撮る。** 描画はすべて実装済みで、撮っていないだけ。

---

## 共通の設定

| | |
|---|---|
| 解像度 | **横 1600px 以上**（資料は 16:9・幅 338mm なので、粗いと目立つ） |
| 形 | 16:9 に近い長方形で切る（縦長は資料の枠に入らない） |
| 保存先 | `portfolio/img/`（png） |
| 命名 | 下の **S1〜S6** をそのままファイル名に（例 `S1_rooms.png`） |
| 余白 | UI の端で切らない。**枠に少し余白を残す** |

★ Unity のエディタテーマを **Light** にすると資料（白地）になじみます。Scene ビューの中身は
そのままでよいので、無理なら暗いままで構いません。

---

## S1 ── 部屋の抽出（p7 コンセプト②）

**いちばん効きます。**「部屋を勝手に見つけている」が一目で分かる絵。

| | |
|---|---|
| どこで | 2 部屋＋戸口のラボ（`Lab_Door` など） |
| 何を映す | Scene ビュー。**抽出された部屋が色分けされている**状態 |
| 条件 | 扉を **半開き**にして、開口が立っているところ |
| 添えたい | リスナーの占有割合（部屋 A 70% / 部屋 B 30% のような数字）が画面に出ていると最高 |

⚠ 部屋の色分け表示が無ければ、**代わりに Status Monitor の部屋の数値（体積・RT60・占有割合）**を
Scene ビューと並べて撮る。それでも成立します。

---

## S2 ── 経路の描画（p5 または p6）

`OnDrawGizmos` が既に描いているもの。**これが「音の見える化」の本命**です。

| | |
|---|---|
| どこで | 同じラボ。音源 2〜3 本 |
| 何を映す | Scene ビュー。次が同時に見えている状態 |
| | ・**反射経路**（バウンスが進むほど薄くなる黄色の線） |
| | ・**回折の候補**（最短＝水色／他＝薄い橙、到来点に球） |
| | ・**音源への線が遮蔽量で緑→赤**に変わっているところ |
| 条件 | **1 本は見通せて緑、1 本は柱や扉の陰で赤**、という対比が入るように置く |

★ ツール②の「Scene に経路」を ON にすると、直接＝緑／反射＝黄／回折＝水色で描かれます。

## S6 ── 扉スイープの音（p14 検証）

| | |
|---|---|
| 作り方 | `AfRenderWav door_sweep.wav` → 波形／スペクトログラムを画像化 |
| 何を映す | 扉が 0°→90°→0° と動くあいだの**帯域の変化**が見える図 |

## 撮ったあと

`portfolio/img/` に置いて連絡をもらえれば、こちらで資料に流し込みます。
差し替えは各ページの `★図：これから撮る` の枠を置き換えるだけです。

**S1〜S5 の 5 枚が入ると、17 枚中 10 枚が「絵が主役」になります。**
